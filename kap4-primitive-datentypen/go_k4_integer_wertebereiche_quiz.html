Richtig oder falsch?

Stimmt erst gemeinsam ab und lasst euch dann die Auflösung zeigen.

AussageDeine WahlAuflösung
Die Deklaration var x int8 = 200 ist erlaubt.
Falsch. Der größte Wert von int8 ist 127. Der Compiler weist die Konstante 200 deshalb zurück.
Ein int32 kann den Wert 2.000.000.000 speichern.
Richtig. Der größte Wert von int32 ist 2.147.483.647.
Der Typ int hat immer 64 Bit.
Falsch. Je nach Compiler und Hardware hat int 32 oder 64 Bit.
byte ist ein anderer Name für uint8 und speichert Werte von 0 bis 255.
Richtig. byte ist ein Alias für uint8, also vorzeichenlos mit 8 Bit.
Eine Variable vom Typ byte lässt sich ohne Typkonvertierung einer Variablen vom Typ uint8 zuweisen.
Richtig. Ein Alias ist nur ein anderer Name. byte und uint8 sind derselbe Typ.
Hat int auf deinem Rechner 64 Bit, sind int und int64 derselbe Typ.
Falsch. Es sind zwei verschiedene Typen mit der gleichen Größe. Eine Zuweisung zwischen ihnen erfordert eine Typkonvertierung.
Nach var a int8 = 127 und a = a + 1 gibt fmt.Println(a) den Wert 128 aus.
Falsch. Der Zeiger läuft über die Nahtstelle, und die Ausgabe ist −128. Go meldet diesen arithmetischen Überlauf nicht.
Nach var anzahl uint8 = 10 und anzahl = anzahl - 15 gibt fmt.Println(anzahl) den Wert 251 aus.
Richtig. uint8 kann −5 nicht darstellen. Gespeichert wird −5 + 256 = 251.
Im Kurstext heißt das Ergebnis 251 aus der vorigen Aussage arithmetischer Überlauf.
Falsch. Die Fußnote zu Hinweis 4.7 nennt es ein Repräsentationsproblem: Ein vorzeichenloser Typ kann negative Werte gar nicht darstellen.
Für Anzahlen und Rechnungen mit ganzen Zahlen nimmt man in Go im Normalfall int.
Richtig, sofern sein Wertebereich ausreicht. Eine feste Bitzahl braucht einen Grund.
Eine Anzahl ist nie negativ. Deshalb gehört sie in einen vorzeichenlosen Typ wie uint.
Falsch. Eine fehlerhafte Subtraktion kann ein negatives Ergebnis liefern. Mit int bleibt es sichtbar, mit uint entsteht ein großer positiver Wert.
fmt.Println('A') gibt die Zahl 65 aus.
Richtig. 'A' ist eine rune, also eine ganze Zahl: der Unicode-Codepunkt 65.
Noch nicht ausgewertet.
