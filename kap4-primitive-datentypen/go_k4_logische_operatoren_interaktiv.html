⚡ Kurzschluss-Auswertung (Short-Circuit Evaluation)

💡 Prinzip: Der rechte Operand wird nur ausgewertet, wenn der Wert des Ausdrucks nach dem linken Operanden noch nicht feststeht.

Konjunktion (&&): Auswertung von a && b

Fall 1: a = false

Schritt 1: a auswerten → false
Schritt 2: b auswerten → übersprungen!
Ergebnis: false
(da false && X immer false ist)

Fall 2: a = true

Schritt 1: a auswerten → true
Schritt 2: b auswerten → muss ausgewertet werden!
Ergebnis: Hängt von b ab
(true && b = b)
🔑 Regel: Bei a && b wird b nur ausgewertet, wenn a true ist.

Disjunktion (||): Auswertung von a || b

Fall 1: a = true

Schritt 1: a auswerten → true
Schritt 2: b auswerten → übersprungen!
Ergebnis: true
(da true || X immer true ist)

Fall 2: a = false

Schritt 1: a auswerten → false
Schritt 2: b auswerten → muss ausgewertet werden!
Ergebnis: Hängt von b ab
(false || b = b)
🔑 Regel: Bei a || b wird b nur ausgewertet, wenn a false ist.

Vorteile der Kurzschluss-Auswertung

✅ Drei wichtige Gründe:
  1. Einsparung von Rechenzeit – Besonders in Schleifen mit Millionen Durchläufen
  2. Vermeidung von Fehlern – Sichere Prüfungen vor kritischen Operationen
  3. Kontrolle von Seiteneffekten – Funktionsaufrufe nur wenn nötig

Praktisches Beispiel: Division durch Null vermeiden

// Sicher: Prüfung VOR der Division
x != 0 && (100 / x) > 10

// Erklärung:
// - Wenn x == 0: Linker Teil ist false
//   → Rechter Teil wird NICHT ausgewertet
//   → Keine Division durch 0!
// - Wenn x != 0: Linker Teil ist true
//   → Rechter Teil wird ausgewertet
//   → Division ist sicher!
⚠️ Reihenfolge wichtig: (100 / x) > 10 && x != 0 würde einen Fehler verursachen, weil die Division zuerst ausgewertet wird!

Weitere typische Anwendungen:

Null-Pointer Check
ptr != nil && ptr.value > 0
Greift nur auf ptr.value zu, wenn ptr nicht nil ist
Array Bounds Check
i < len(arr) && arr[i] == target
Verhindert Index-out-of-bounds Fehler
String Length Check
len(s) > 0 && s[0] == 'A'
Prüft erst Länge, dann erstes Zeichen

Seiteneffekte bei Funktionsaufrufen

💡 Seiteneffekt: Eine Funktion hat einen Seiteneffekt, wenn sie nicht nur einen Rückgabewert berechnet, sondern auch den Programmzustand oder -ablauf beeinflusst (z.B. Ausgaben, Dateioperationen, Variablenänderungen).

Beispiel aus dem Skript:

func f() bool {
    fmt.Println("<>")
    return false
}

func main() {
    fmt.Println("AND Auswertung")
    fmt.Println("ergibt", true && f())  // f() WIRD ausgewertet
    fmt.Println()
    
    fmt.Println("OR Auswertung")
    fmt.Println("ergibt", true || f())  // f() wird NICHT ausgewertet
}
Ausgabe:

AND Auswertung
<<Funktion f wird aufgerufen>>
ergibt false

OR Auswertung
ergibt true

true && f()

Da der linke Operand true ist, muss der rechte ausgewertet werden.

→ f() wird aufgerufen

→ Seiteneffekt tritt auf (Ausgabe erscheint)

true || f()

Da der linke Operand true ist, steht das Ergebnis fest.

→ f() wird NICHT aufgerufen

→ Seiteneffekt bleibt aus (keine Ausgabe)

⚠️ Wichtig: Wenn boolesche Ausdrücke Funktionen mit Seiteneffekten enthalten, ist das Auftreten der Seiteneffekte nicht garantiert und hängt von anderen Teilausdrücken ab!

⚖️ Vergleichsoperatoren

Alle Vergleichsoperatoren liefern einen Wert vom Typ bool:

Operator Bedeutung Verfügbar für Beispiel
== Gleich Alle primitiven Typen 5 == 5 → true
!= Ungleich Alle primitiven Typen 5 != 7 → true
< Kleiner Geordnete Typen (int, float, string) 3 < 5 → true
<= Kleiner oder gleich Geordnete Typen 5 <= 5 → true
> Größer Geordnete Typen 7 > 3 → true
>= Größer oder gleich Geordnete Typen 8 >= 8 → true

Beispiele mit verschiedenen Typen:

Integer-Vergleiche
a := 2 + 3
b := 5
a == b // true
Verschiedene Zahlensysteme
0xaf == 175 // true
33 == 33.0 // true
String-Vergleiche
s := "Hallo Welt"
t := "Hallo " + "Welt"
s == t // true
Verkettete Vergleiche
4 > 2 == (5 < 9)
// true (beide Seiten true)

🔤 Lexikographischer String-Vergleich

💡 Lexikographisch: Strings werden zeichenweise von links nach rechts verglichen, ähnlich wie Wörter in einem Wörterbuch sortiert werden.

Vergleichsregeln:

  1. Zeichenweise Vergleich: Vergleiche nacheinander jedes Zeichen
  2. Erstes unterschiedliches Zeichen entscheidet: Das Zeichen mit höherem Code-Wert gewinnt
  3. Verlängerung: Wenn ein String ein Präfix des anderen ist, ist der längere größer
🔑 Wertigkeit (Code-Reihenfolge):
Ziffern (0-9) < Großbuchstaben (A-Z) < Kleinbuchstaben (a-z)

Beispiele aus dem Skript:

AusdruckErgebnisErklärung
"Maus" > "Katze" true 'M' > 'K'
"Katzen" > "Katze" true "Katzen" ist länger (Verlängerung)
"affe" > "Ziege" true 'a' (Kleinbuchstabe) > 'Z' (Großbuchstabe)
"sieben" > "8" true 's' (Buchstabe) > '8' (Ziffer)
"56" > "199" true '5' > '1' (zeichenweise, nicht numerisch!)
⚠️ Achtung: String-Vergleiche sind nicht numerisch! "56" > "199" ist true, weil '5' > '1' (zeichenweise Vergleich).

Teil 1: Wahrheitstabellen und logische Operatoren

AussageDeine WahlAuflösung
Der Operator ! ist ein unärer Operator (hat nur einen Operanden).
Richtig: ! ist der einzige unäre logische Operator (Negation).
Der Ausdruck true && false ergibt true.
Falsch: Bei && müssen beide Operanden true sein. Ergebnis ist false.
Der Ausdruck false || true ergibt true.
Richtig: Bei || reicht es, wenn mindestens ein Operand true ist.
Der Ausdruck !false ergibt true.
falsch
 Richtig: Die Negation kehrt den Wahrheitswert um.
Der Ausdruck true && true && false ergibt true.
Falsch: Alle Operanden müssen true sein. Ein false reicht für Gesamtergebnis false.

Teil 2: Kurzschluss-Auswertung (Short-Circuit Evaluation)

AussageDeine WahlAuflösung
Bei false && b wird der Operand b nicht ausgewertet.
Richtig: Da linker Operand false ist, steht das Ergebnis fest (false).
Bei true && b wird der Operand b nicht ausgewertet.
Falsch: Da linker Operand true ist, muss b ausgewertet werden, um das Ergebnis zu bestimmen.
Bei true || b wird der Operand b nicht ausgewertet.
Richtig: Da linker Operand true ist, steht das Ergebnis fest (true).
Bei false || b wird der Operand b nicht ausgewertet.
Falsch: Da linker Operand false ist, muss b ausgewertet werden, um das Ergebnis zu bestimmen.
Die Kurzschluss-Auswertung dient u.a. der Einsparung von Rechenzeit.
Richtig: Besonders in Schleifen mit Millionen Durchläufen spart dies Zeit.

Teil 3: Praktische Anwendung der Kurzschluss-Auswertung

AussageDeine WahlAuflösung
Der Ausdruck x != 0 && (100 / x) > 10 ist sicher vor Division durch Null.
Richtig: Wenn x == 0, ist linker Teil false und Division wird nicht ausgeführt.
Der Ausdruck (100 / x) > 10 && x != 0 ist sicher vor Division durch Null.
Falsch: Die Division wird zuerst ausgewertet! Bei x == 0 gibt es einen Fehler.
Bei i < len(arr) && arr[i] == target wird ein Index-out-of-bounds Fehler vermieden.
Richtig: Die Längenprüfung erfolgt vor dem Array-Zugriff.
Die Reihenfolge der Operanden ist wichtig für die Sicherheit von Ausdrücken.
Richtig: Prüfungen müssen vor kritischen Operationen stehen.

Teil 4: Seiteneffekte

AussageDeine WahlAuflösung
Bei true || f() wird die Funktion f() nicht aufgerufen, wenn sie auf der rechten Seite steht.
Richtig: Wegen Kurzschluss-Auswertung wird f() übersprungen.
Bei true && f() wird die Funktion f() nicht aufgerufen.
Falsch: Da linker Operand true ist, muss f() ausgewertet werden.
Ein Seiteneffekt ist z.B. eine Ausgabe, Dateiope ration oder Variablenänderung.
Richtig: Seiteneffekte verändern den Programmzustand oder -ablauf.
Wenn boolesche Ausdrücke Funktionen mit Seiteneffekten enthalten, ist das Auftreten der Seiteneffekte nicht garantiert.
Richtig: Durch Kurzschluss-Auswertung können Funktionen übersprungen werden.

Teil 5: Vergleichsoperatoren

AussageDeine WahlAuflösung
Alle Vergleichsoperatoren liefern einen Wert vom Typ bool.
Richtig: Vergleichsoperatoren geben immer true oder false zurück.
Die Operatoren == und != sind für alle primitiven Typen verfügbar.
Richtig: Gleichheit und Ungleichheit können für alle primitiven Typen geprüft werden.
Die Vergleichsoperatoren <, >, <=, >= sind für bool verfügbar.
Falsch: Diese Operatoren sind nur für geordnete Typen (int, float, string) verfügbar.
Der Ausdruck 0xaf == 175 ergibt true.
Richtig: 0xaf (hexadezimal) ist gleich 175 (dezimal).

Teil 6: Lexikographische String-Vergleiche

AussageDeine WahlAuflösung
Bei lexikographischen String-Vergleichen werden Strings zeichenweise von links nach rechts verglichen.
Richtig: Ähnlich wie Wörter in einem Wörterbuch.
Der Ausdruck "Maus" > "Katze" ergibt true.
Richtig: 'M' hat einen höheren Code-Wert als 'K'.
Der Ausdruck "Katzen" > "Katze" ergibt true.
Richtig: "Katzen" ist länger (Verlängerung von "Katze").
Der Ausdruck "affe" > "Ziege" ergibt true.
Richtig: Kleinbuchstaben ('a') haben höhere Code-Werte als Großbuchstaben ('Z').
Der Ausdruck "56" > "199" ergibt true.
Richtig: '5' > '1' (zeichenweise, nicht numerisch!).
String-Vergleiche in Go erfolgen numerisch, wenn die Strings Ziffern enthalten.
Falsch: String-Vergleiche sind IMMER zeichenweise, niemals numerisch!
Die Wertigkeit der Zeichen ist: Ziffern (0-9) < Großbuchstaben (A-Z) < Kleinbuchstaben (a-z).
Richtig: Dies entspricht der ASCII/Unicode Code-Reihenfolge.
Der Ausdruck "sieben" > "8" ergibt true.
Richtig: Buchstaben haben höhere Code-Werte als Ziffern.
Noch nicht ausgewertet.

📝 Zusammenfassung

Logische Operatoren

  • ! – Negation (unär)
  • && – AND (beide wahr)
  • || – OR (mind. einer wahr)
  • Kurzschluss-Auswertung spart Rechenzeit
  • Ermöglicht sichere Prüfungen

Vergleichsoperatoren

  • ==, != für alle Typen
  • <, >, <=, >= für geordnete Typen
  • Strings: lexikographisch
  • Rückgabetyp immer bool
✅ Wichtigste Erkenntnisse:
  • Kurzschluss-Auswertung ist ein Feature, kein Fehler
  • Reihenfolge der Operanden ist wichtig für Sicherheit und Performance
  • Seiteneffekte in Ausdrücken können übersprungen werden
  • String-Vergleiche sind zeichenweise, nicht numerisch
