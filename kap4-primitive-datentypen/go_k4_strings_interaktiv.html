Strings in Go: Literale, Verkettung und Unveränderbarkeit

Ein String ist eine Zeichenkette. Die Seite zeigt, wie man einen String im Quelltext schreibt, was der Backslash darin bewirkt, wie man zwei Strings verkettet und warum sich ein String nicht ändern lässt.

Kurstext v3.0.6, Abschnitt 4.6.1, Seiten 99–102, und Abschnitt 4.6.2.2, Seiten 107–108.

Worum es geht

Ein Wert vom Typ string ist eine Zeichenkette, zum Beispiel grüne Wiese. Im Quelltext steht dafür ein String-Literal. Die doppelten Anführungszeichen grenzen die Zeichenkette vom übrigen Quelltext ab:

var text string = "grüne Wiese"
fmt.Println(text)    // grüne Wiese

Literal und Wert sind zweierlei. Das Literal ist die Schreibweise im Quelltext, mit den Anführungszeichen. Der Wert ist die Zeichenkette im Speicher, ohne sie. Mehrere Literale können für den gleichen Wert stehen. Dem Wert sieht man nicht mehr an, aus welchem Literal er stammt.

Zwei Formen des String-Literals

  • Das interpretierte String-Literal, "…": Go deutet darin den Backslash \. Das ist Schritt 1.
  • Das rohe String-Literal, `…`: Go übernimmt darin jedes Zeichen so, wie es dasteht. Das ist Schritt 2.

Schritt 1: Der Backslash

Erst vorhersagen, dann ausprobieren
  1. Was gibt fmt.Println("Zeile 1\nZeile 2") aus?
    AuflösungZwei Zeilen: erst „Zeile 1“, darunter „Zeile 2“. Die zwei Zeichen \n stehen zusammen für einen Zeilenumbruch.
  2. Wie viele Zeichen hat der String "a\\b"?
    AuflösungDrei: a, ein Backslash und b. Die zwei Backslashes im Literal stehen für einen Backslash im Wert.

In einem interpretierten String-Literal ist der Backslash \ das Escape-Zeichen. Er steht nicht für sich selbst. Er sagt: Das Zeichen danach hat eine besondere Bedeutung. Backslash und Folgezeichen zusammen heißen Escape-Sequenz. Im Wert steht dafür ein einziges Zeichen.

Escape-SequenzWelches Zeichen im Wert stehtWie oft man sie braucht
\nIm Wert steht ein Zeilenumbruch.Man braucht sie sehr oft.
\tIm Wert steht ein Tabulator.Man braucht sie gelegentlich.
\\Im Wert steht ein Backslash.Man braucht sie für jeden Backslash, der im Wert stehen soll.
\"Im Wert steht ein doppeltes Anführungszeichen.Man braucht sie für jedes Anführungszeichen, das im Wert stehen soll.
\a, \b, \f, \r, \vIm Wert steht ein Steuerzeichen: Klingel, Rückschritt, Seitenvorschub, Wagenrücklauf, vertikaler Tabulator.Man braucht sie fast nie.
\u und \U mit einer NummerIm Wert steht das Unicode-Zeichen mit dieser Nummer.Das ist Schritt 3.

Warum es \\ und \" braucht

  • Das Anführungszeichen: Ein " beendet das Literal. Soll ein Anführungszeichen im Wert stehen, muss Go es vom Ende unterscheiden können. Dafür steht \".
  • Der Backslash: Ein \ leitet eine Escape-Sequenz ein. Soll ein Backslash im Wert stehen, schreibt man ihn doppelt.

Das Beispiel des Kurstexts:

fmt.Println("Der Backslash \\ ist ein \"besonderes\" Zeichen.")
// Ausgabe: Der Backslash \ ist ein "besonderes" Zeichen.

Schritt 2: Rohe Literale

Ein rohes String-Literal steht zwischen zwei Backquotes: `blauer Himmel`. Darin gibt es keine Escape-Sequenzen. Jedes Zeichen kommt so in den Wert, wie es im Quelltext steht, auch \ und ".

fmt.Println(`Der Backslash \ ist ein "besonderes" Zeichen.`)
// Ausgabe: Der Backslash \ ist ein "besonderes" Zeichen.

Das einzige Zeichen, das in einem rohen String-Literal nicht vorkommen kann, ist der Backquote selbst, denn er beendet das Literal.

Der Backquote ` ist das Akzentzeichen von è und nicht der Apostroph. Auf einer deutschen Tastatur: Umschalttaste und Akzenttaste zusammen drücken, danach die Leertaste.

Wann sich das rohe Literal lohnt

  • Viele Backslashes und Anführungszeichen: Ein Pfad unter Windows enthält Backslashes und steht oft selbst in Anführungszeichen. Im rohen Literal bleibt er lesbar.
  • Mehrere Zeilen: Ein interpretiertes Literal muss in einer Zeile stehen, ein Zeilenumbruch darin heißt \n. Ein rohes Literal darf über mehrere Zeilen gehen. Jeder Zeilenumbruch im Quelltext gehört dann zum Wert.
var htmlCode string = `<html>
    <body>
        <p>This is a simple HTML page.</p>
    </body>
</html>`
fmt.Println(htmlCode)    // gibt die fünf Zeilen mit allen Einrückungen aus

Schritt 3: Unicode-Nummern

Go arbeitet mit dem Zeichensatz Unicode. Er enthält über 120.000 Zeichen: die Buchstaben vieler Sprachen, mathematische Zeichen, Symbole und Emojis. Der alte Zeichensatz ASCII hatte 128 Zeichen. Jedes Unicode-Zeichen darf in einem String-Literal stehen.

Viele Zeichen gibt es auf keiner Tastatur. Deshalb hat jedes Unicode-Zeichen eine Nummer, den Unicode code point. In Go heißt diese Nummer auch rune. Man schreibt sie hexadezimal.

  • \u mit vier Hexadezimalziffern: "∞" ist das Zeichen ∞ mit der Nummer 221E.
  • \U mit acht Hexadezimalziffern: "\U0001f600" ist der Smiley 😀 mit der Nummer 1F600. Das große U braucht man für Nummern mit mehr als vier Ziffern.

Eine kürzere Nummer wird vorn mit Nullen aufgefüllt: Das ü hat die Nummer FC und heißt ü.

fmt.Println("Unendlich ist ∞ und Smiley ist \U0001f600")
// Ausgabe: Unendlich ist ∞ und Smiley ist 😀

Schritt 4: Verketten

Für Strings gibt es den Operator +. Er heißt hier Verkettungsoperator oder Konkatenationsoperator. Er hängt den rechten String an den linken und liefert einen neuen String:

fmt.Println("hoch" + "springen")    // hochspringen

Die zwei Operanden bleiben, wie sie sind. Zwischen ihnen fügt Go nichts ein, auch kein Leerzeichen.

Beide Operanden müssen Strings sein

Go wandelt eine Zahl nicht von selbst in einen String um. Ein String und eine Zahl lassen sich deshalb nicht mit + verbinden. Go übersetzt den Ausdruck nicht.

Schritt 5: Unveränderbar

    
Erst vorhersagen, dann ausprobieren
      
    
        
  1. Das Programm unten weist b den Wert von a zu und hängt danach an a etwas an. Was gibt fmt.Println(b) aus?
          
    AuflösungSommer. Die Zuweisung b = a hat den Wert kopiert. Was danach mit a geschieht, betrifft b nicht.
    2. 
      

    

    
Strings sind in Go unveränderbar, auf Englisch immutable. Ein einzelnes Zeichen eines Strings lässt sich nicht austauschen. Der Ausdruck s[0] liefert das erste Byte, aber er kann nie auf der linken Seite einer Zuweisung stehen:


var s string = "Ohr"
s[0] = 85    // Go übersetzt die Zeile nicht

    
Die 85 ist die Nummer des Buchstabens U. Aus „Ohr“ sollte „Uhr“ werden. Der Compiler meldet: cannot assign to s[0] (neither addressable nor a map index expression)


    
Was stattdessen geht

    
Die Variable s ist veränderbar, der String nicht. Man weist s einen neuen String zu:


s = "Uhr"           // ein anderer String
s = "U" + s[1:]     // ein neuer String aus "U" und dem Rest des alten

    Was die Regel bringt
    
    
    Weil kein String sich ändern kann, dürfen sich Kopien eines Strings den gleichen Platz im Arbeitsspeicher teilen. Bei b = a muss Go die Zeichen nicht noch einmal ablegen.
