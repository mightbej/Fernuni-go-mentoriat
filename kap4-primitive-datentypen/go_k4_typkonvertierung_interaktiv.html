Typkonvertierung

In Go müssen beide Operanden eines Operators denselben Typ haben. Die Seite zeigt, wann Go den Typ selbst anpasst und wann das Programm ihn mit float64(a) oder int(f) umwandeln muss.

Kurstext v3.0.6, Abschnitt 4.7, Seiten 109–111.

Was die Seite zeigt

Ein binärer Operator wie +, * oder / verbindet zwei Operanden. In Go müssen beide Operanden denselben Typ haben. Das folgende Programm übersetzt Go deshalb nicht:

var a int = 25
var f float64 = 1.7
fmt.Println(f * a)

Der Compiler meldet: invalid operation: f * a (mismatched types float64 and int). Auf Deutsch: Die Typen float64 und int passen nicht zusammen.

Warum Go so streng ist

Ältere Programmiersprachen wandeln Werte stillschweigend um. Das ergibt kurze Programme und versteckte Fehler. Go ist eine streng typisierte Programmiersprache: Wer einen Wert in einen anderen Typ umwandeln will, schreibt das ins Programm. Besprochen wurde das in Abschnitt 2.4 des Kurstexts, Seiten 11–12. Dazu gibt es Schritt 2 der Seite Variablen, Typen und Speicher.

Ein konstanter Ausdruck besteht nur aus Literalen und Konstanten. Sein Wert steht beim Übersetzen fest. Beispiele sind 9, 2.5 und 3 * 10. Der Ausdruck 3 * a mit einer Variablen a ist kein konstanter Ausdruck.

Schritt 1: Implizite Typanpassung

Go passt den Typ eines Ausdrucks nur in zwei Fällen selbst an:

  • Konstanter Integer-Ausdruck neben einem Floating-Point-Typ: In g / 2 hat g den Typ float64. Go macht aus dem Integer-Literal 2 den Wert 2.0.
  • Ganzzahliger, konstanter Floating-Point-Ausdruck für eine Integer-Variable: var i int = 5.0 ist zulässig, weil 5.0 keine Nachkommastellen hat. Go speichert 5.

Der Typ einer Variablen wird nie angepasst. Das erste Beispiel dafür kam schon in Listing 3.2 vor: Im Ausdruck 32 + tempC*1.8 hat der rechte Operand den Typ float64, und Go macht aus 32 den Wert 32.0.

Die Beispiele des Kurstexts

var g float64 = 9
g = g / 2
fmt.Println(g)          // 4.5
fmt.Println(3 * 10 / g) // 6.666666666666667
fmt.Println(6 * 0.25)   // 1.5
fmt.Println(15.0 / 2.0) // 7.5
fmt.Println(15.0 / 2)   // 7.5
fmt.Println(15 / 2.0)   // 7.5
fmt.Println(15 / 2)     // 7

var i int = 5.0
i = 2.5 * 2.4
fmt.Println(i)          // 6

Eine Zeile zerlegen

Wähle eine Zeile. Die Darstellung zeigt ihre zwei Seiten mit Typ und markiert die Seite, die Go anpasst.

Blau steht ein Ausdruck mit ganzzahligem Typ, grün ein Ausdruck mit Floating-Point-Typ. Gestrichelt umrandet ist der Ausdruck, dessen Typ Go anpasst. Unter ihm steht, womit Go rechnet.
Warum ein Literal wie 9 sich anpassen lässt, wird in Abschnitt 5.2 des Kurstexts behandelt: Ein Literal hat zunächst keinen festen Typ. Dazu gibt es Schritt 4 der Seite Konstanten.

Schritt 2: Explizite Typkonvertierung

Für eine Variable gibt es keine implizite Typanpassung. Das Programm muss den Wert selbst umwandeln. Die Schreibweise heißt Typkonvertierung, englisch type conversion:

T(a)
  • T: der Name des Typs, den der Wert bekommen soll, zum Beispiel float64 oder int.
  • a: der Ausdruck, dessen Wert umgewandelt wird. Er steht in runden Klammern.
  • Beispiel: float64(a) liefert den Wert von a als float64. Hat a den Wert 25, dann hat float64(a) den Wert 25.0.

Eine Typkonvertierung sieht aus wie ein Funktionsaufruf. Sie ist ein Ausdruck und keine Anweisung: Sie liefert einen Wert, mit dem das Programm weiterrechnet.

Die Variable behält ihren Wert

Die Typkonvertierung int(f) wandelt nur den Wert um, den der Ausdruck liefert. Die Variable f bleibt, wie sie ist. Das zeigt die vorletzte Ausgabe im Programm. Erst die Zuweisung f = float64(a) gibt f einen neuen Wert.

Schritt 3: Abschneiden

Ein Wert vom Typ int hat keine Nachkommastellen. Bei der Konvertierung von float64 nach int schneidet Go die Nachkommastellen ab. Go rundet dabei nicht.

Beispiele
Der grüne Punkt ist f, der blaue Ring ist int(f). Der Pfeil zeigt vom grünen Punkt zum blauen Ring. Er zeigt immer in Richtung 0.
VerfahrenWas das Verfahren tutErgebnis für den eingestellten Wert von f
Die Seite konvertiert hier eine Variable. Den Ausdruck int(3.7) mit einem Literal übersetzt Go nicht. Der Compiler meldet: cannot convert 3.7 (untyped float constant) to type int. Zulässig ist int(5.0), weil 5.0 keine Nachkommastellen hat. Das ist die Regel aus Schritt 1.

Schritt 4: Division

Der Operator / rechnet je nach Typ seiner Operanden verschieden:

  • Zwei Operanden vom Typ int: Go teilt ganzzahlig. Das Ergebnis ist der Ganzzahlquotient, die Nachkommastellen fallen weg. 25 / 10 liefert 2.
  • Zwei Operanden vom Typ float64: Go liefert den rationalen Quotienten. 25.0 / 10.0 liefert 2.5.

Wer den rationalen Quotienten zweier Integer-Variablen braucht, konvertiert beide Variablen, bevor er teilt.

Beispiele
Jede der drei Rechnungen setzt zuerst die Werte von a und b ein und rechnet dann von innen nach außen. Blau umrandet ist die ganzzahlige Division, grün der rationale Quotient, rot der Denkfehler.
Eine einzelne Konvertierung genügt nicht: float64(a) / b übersetzt Go nicht, weil der linke Operand den Typ float64 hat und der rechte den Typ int.

Wie Go eine Gleitkommazahl speichert und warum dabei Rundungsfehler entstehen, zeigt die Seite Gleitkommazahlen.
