⚠️ Überlauf (Overflow) bei Ganzzahlen in Go

Wenn Berechnungsergebnisse den Wertebereich überschreiten – ohne Fehlermeldung!
Verstehe die Gefahr und lerne, Überläufe zu erkennen und zu vermeiden.

🚨 Das Problem: Stille Überläufe

⚠️ Kritisch: In Go führen Überläufe zur Laufzeit zu keiner Fehlermeldung!
  • Das Programm läuft weiter mit einem falschen Ergebnis
  • Überläufe können unbemerkt zu schwerwiegenden Bugs führen
  • Nur konstante Ausdrücke werden zur Compile-Zeit geprüft

Unterschied: Compile-Zeit vs. Laufzeit

❌ Compile-Zeit Fehler

var f uint8
f = 200 + 80  // Fehler!
Fehlermeldung:
overflows uint8

Da 200 + 80 = 280 konstant ist, wird es zur Compile-Zeit ausgewertet.

⚠️ Laufzeit Überlauf (KEIN Fehler)

var f uint8 = 200
var result = f + 80
Keine Fehlermeldung!
Ergebnis: 24 (statt 280)

Variable → erst zur Laufzeit bekannt → kein Fehler, nur falsches Ergebnis!

➕ Überlauf bei vorzeichenlosen Typen (uint8)

Bei vorzeichenlosen Typen werden arithmetische Operationen modulo 2n durchgeführt (wobei n die Bit-Länge ist). Man spricht von einem "wrap around".

💡 Prinzip: Alle Bits, die über die verfügbaren n Bits hinausgehen, werden verworfen.
Nur die n niederwertigsten Bits bilden das Ergebnis.

Beispiele aus dem Skript (uint8):

255 + 1
var uA uint8 = 255
fmt.Println(uA + 1)
Erwartet: 256
Ergebnis: 0
130 + 140
var uB uint8 = 130
fmt.Println(uB + 140)
Erwartet: 270
Ergebnis: 14
255 + 255
var uC uint8 = 255
fmt.Println(uC + 255)
Erwartet: 510
Ergebnis: 254

➖ Überlauf bei vorzeichenbehafteten Typen (int8)

Bei vorzeichenbehafteten Typen kann es durch den Überlauf auch zu einem Vorzeichenwechsel kommen!

⚠️ Gefahr: Ein Überlauf kann das Vorzeichen ändern (+ → − oder − → +), aber nicht jeder Überlauf führt zu einem Vorzeichenwechsel!

Beispiele mit Vorzeichenwechsel:

127 + 1 (Plus → Minus)
var iA int8 = 127
fmt.Println(iA + 1)
Erwartet: 128
Ergebnis: -128
+127 → -128
127 + 127 (Plus → Minus)
var iB int8 = 127
fmt.Println(iB + 127)
Erwartet: 254
Ergebnis: -2
+127 → -2
-128 - 1 (Minus → Plus)
var iC int8 = -128
fmt.Println(iC - 1)
Erwartet: -129
Ergebnis: 127
-128 → +127
-128 + (-128)
var iD int8 = -128
fmt.Println(iD + -128)
Erwartet: -256
Ergebnis: 0
-128 → 0
Bit-Darstellung: 127 + 1 = -128 01111111 (+127) + 00000001 (+1) ---------- 100000000 ^^^^^^^^ 10000000 = -128 (Vorzeichenbit wechselt von 0 auf 1!)

Beispiele OHNE Vorzeichenwechsel:

⚠️ Wichtig: Nicht jeder Überlauf führt zu einem Vorzeichenwechsel! Man kann sich nicht darauf verlassen, Überläufe am Vorzeichenwechsel zu erkennen.
12 × 121
var iE int8 = 12
fmt.Println(iE * 121)
Erwartet: 1452
Ergebnis: -84
Beide Faktoren positiv, aber Ergebnis negativ!
3 × 121
var iF int8 = 3
fmt.Println(iF * 121)
Erwartet: 363
Ergebnis: 107
Überlauf, aber kein Vorzeichenwechsel!
Bit-Darstellung: 3 × 121 = 107 00000011 (3) × 01111001 (121) ---------- 101101011 (363 benötigt 9 Bits) ^^^^^^^^ (nur 8 Bits verfügbar) 01101011 = 107 (Vorzeichen bleibt positiv!)

Gefährliche Situationen – Leicht zu übersehen!

In diesen Beispielen liegt das mathematische Endergebnis innerhalb des Wertebereichs, aber ein Zwischenergebnis verursacht einen Überlauf:

var x int8 = 120

// Reihenfolge der Auswertung ist entscheidend!
fmt.Println(x*3/3, "vs.", x*(3/3))
// Ausgabe: 34 vs. 120

fmt.Println(x*8/12, "vs.", x/12*8)
// Ausgabe: -5 vs. 80

fmt.Println((x+20)/2, "vs.", x/2+20/2)
// Ausgabe: -58 vs. 70
💡 Erkenntnis: Mathematisch äquivalente Ausdrücke können aufgrund von Überläufen zu unterschiedlichen Ergebnissen führen!
Das Distributivgesetz gilt nicht bei Überläufen: (x+20)/2 ≠ x/2+20/2

Detaillierte Erklärung: x*3/3 vs. x*(3/3)

x*3/3
1. x*3 = 120*3 = 360
→ Überlauf! 360 mod 256 = 104
→ Als int8: 104
2. 104/3 = 34
≠
x*(3/3)
1. 3/3 = 1
2. x*1 = 120*1 = 120
→ Kein Überlauf!

🔄 Überläufe können sich ausgleichen

💡 Überraschung: Manchmal können sich mehrere Überläufe gegenseitig ausgleichen, sodass das Endergebnis trotzdem korrekt ist!

Beispiel aus dem Skript:

var x int8 = 120

fmt.Println(x+20-40, "vs.", x-40+20)
// Ausgabe: 100 vs. 100  (beide korrekt!)
Detaillierte Analyse von x+20-40:
Schritt 1: x + 20 01111000 (120) + 00010100 (+20) ---------- 10001100 = -116 (Überlauf nach oben! Erwartet: 140) Schritt 2: -116 - 40 10001100 (-116) + 11011000 (-40 im Zweierkomplement) ---------- 1 01100100 = 100 (Überlauf nach unten! Erwartet: -156) ^^^^^^^^ 01100100 = 100 ✓ (Beide Überläufe gleichen sich aus!)
⚠️ Gefahr: Von einem korrekten Endergebnis darf man nicht darauf schließen, dass keine Überläufe aufgetreten sind! Der Ausdruck x+20 allein würde an anderer Stelle im Code zu einem falschen Ergebnis führen.

🛡️ Überläufe vermeiden – Best Practices

✅ Empfehlungen:
  1. Verwende int (mind. ±2 Milliarden) oder int64 (±9 Trillionen) wenn ausreichend
  2. Identifiziere potentiell gefährliche Berechnungen (große Werte, Multiplikationen, Zwischenergebnisse)
  3. Prüfe vor kritischen Operationen, ob das Ergebnis im Wertebereich liegt
  4. Bei Durchschnittsberechnungen: Vorsicht bei der Summenbildung großer Werte
  5. Nutze das Paket math/big für beliebig genaue Berechnungen

Praktische Wertebereiche:

Beispiel: Überlauf-Prüfung vor Addition

// Sicherstellen, dass a + b nicht überläuft (int32)
func safeAdd(a, b int32) (int32, error) {
    if b > 0 && a > math.MaxInt32 - b {
        return 0, errors.New("Überlauf würde auftreten")
    }
    if b < 0 && a < math.MinInt32 - b {
        return 0, errors.New("Unterlauf würde auftreten")
    }
    return a + b, nil
}
📦 math/big Package: Für Berechnungen mit beliebiger Genauigkeit (arbitrary-precision arithmetic) stellt Go das Paket math/big zur Verfügung, das Ganzzahlen und Gleitkommazahlen ohne Größenbeschränkung unterstützt.

📝 Zusammenfassung

Vorzeichenlos (unsigned)

  • Wrap around modulo 2n
  • Bits werden verworfen
  • Kein Vorzeichenwechsel möglich
  • Manchmal absichtlich genutzt

Vorzeichenbehaftet (signed)

  • Kann Vorzeichenwechsel verursachen
  • Aber: Nicht immer Vorzeichenwechsel!
  • Zweierkomplement-Verhalten
  • Besonders gefährlich bei Multiplikation
🚨 Kritische Punkte:
  • Keine Fehlermeldung zur Laufzeit – Programm läuft mit falschen Werten weiter
  • Mathematisch äquivalente Ausdrücke können unterschiedliche Ergebnisse liefern
  • Überläufe können sich ausgleichen → korrektes Endergebnis trotz Fehler in Zwischenschritten
  • Korrekte Endergebnisse garantieren nicht die Abwesenheit von Überläufen!
