Überlauf bei Ganzzahlen in Go

Passt das Ergebnis einer Rechnung nicht in seinen Typ, rechnet Go mit einem falschen Wert weiter und meldet nichts. Die Seite zeigt, wann ein Überlauf entsteht, welcher Wert dabei herauskommt und warum man ihn leicht übersieht.

Kurstext v3.0.6, Abschnitt 4.3.8, Seiten 78–84.

Worum es geht

Jeder Ganzzahl-Typ hat eine feste Zahl von Bits und damit einen festen Wertebereich. Ein uint8 reicht von 0 bis 255, ein int8 von −128 bis 127.

Ein arithmetischer Überlauf entsteht, wenn das Ergebnis einer Rechnung außerhalb dieses Wertebereichs liegt. Das richtige Ergebnis bräuchte dann mehr Bits, als der Typ hat. Go behält nur die Bits, die in den Typ passen:

var f uint8 = 200
fmt.Println(f + 80)    // 24

200 + 80 ist 280. Ausgegeben wird 24. Das Programm läuft weiter, als sei nichts geschehen.

Go meldet einen Überlauf nicht. Es gibt keinen Abbruch und keine Warnung. Das macht den Überlauf zu einem Fehler, der schwer zu finden ist.

Was aus früheren Abschnitten dazugehört

  • Abschnitt 4.3.4, Seite 63, die Typen: Welcher Typ welchen Wertebereich hat, zeigt die Seite Zahlenkreis, Schritt 4.
  • Abschnitt 4.3.5, Seiten 64–66, das Zweierkomplement: Wie ein Bitmuster als Zahl mit Vorzeichen gelesen wird, zeigt die Seite Zweierkomplement.
  • Abschnitt 4.3.7.1, Seiten 69–71, der Typ eines Ergebnisses: Das Ergebnis von f + 80 hat den Typ von f, hier also uint8.

Den Überlauf als Sprung auf einem Kreis von 127 nach −128 zeigt die Seite Zahlenkreis, Schritt 3. Diese Seite rechnet die Beispiele des Kurstexts nach.

Die fünf Schritte

  • Schritt 1, keine Meldung: Mit einer Variable entsteht der Überlauf, während das Programm läuft. Mit zwei Literalen meldet schon der Compiler einen Fehler.
  • Schritt 2, ohne Vorzeichen: Bei uint8 fallen die überzähligen Bits weg.
  • Schritt 3, mit Vorzeichen: Bei int8 kann dabei das Vorzeichen wechseln.
  • Schritt 4, Teilausdrücke: Ein Überlauf mitten in einem Ausdruck, obwohl das Endergebnis in den Typ passen würde.
  • Schritt 5, was man dagegen tut: Der passende Typ und eine Prüfung vor der Rechnung.
Die Seite rechnet wie der Kurstext mit den Typen uint8 und int8. Sie sind so klein, dass man jeden Überlauf nachrechnen kann. In einem echten Programm steht meist int. Alle Programmzeilen der Seite sind mit Go 1.26 ausgeführt.

Schritt 1: Keine Meldung

Ob Go einen zu großen Wert bemerkt, hängt davon ab, wann der Wert feststeht.

var f uint8 = 200      // Wertebereich 0 bis 255
fmt.Println(f + 80)    // Überlauf, keine Meldung: 24
f = f + 80             // Überlauf, keine Meldung
f = 200 + 80           // Go übersetzt die Zeile nicht
  • Mit einer Variable, zur Laufzeit: Den Wert von f kennt Go erst, wenn das Programm läuft. Das Ergebnis von f + 80 hat den Typ uint8. Es wird ausgerechnet, passt nicht und läuft über. Go meldet nichts.
  • Mit zwei Literalen, beim Übersetzen: 200 + 80 enthält nur Konstanten. Der Compiler rechnet die Summe 280 selbst aus und sieht, dass sie nicht in f passt. Er meldet:
    cannot use 200 + 80 (untyped int constant 280) as uint8 value in assignment (overflows)

In der Meldung steht das Wort „overflows“. Gemeint ist dort aber nur: Die Konstante passt nicht in den Typ. Der Überlauf, um den es auf dieser Seite geht, ist der erste Fall. Er entsteht zur Laufzeit und bleibt ohne Meldung.

Der Typ des Ergebnisses

Der Typ von f + 80 steht fest, sobald der Ausdruck dasteht: Er ist uint8, weil f diesen Typ hat. Es spielt keine Rolle, wohin das Ergebnis danach geht. Auch fmt.Println(f + 80) gibt deshalb 24 aus und nicht 280.

Schritt 2: Ohne Vorzeichen

    
Erst vorhersagen, dann ausprobieren
      
    
        
  1. Was gibt fmt.Println(a + b) aus, wenn a und b vom Typ uint8 sind und beide den Wert 255 haben?
          
    Auflösung254. Die Summe 510 braucht 9 Bits: 1 1111 1110. Das linke Bit fällt weg, es bleibt 1111 1110, und das ist 254. Als Rechnung: 510 − 256 = 254.
    2. 
        
  2. Und was ergibt 3 − 5 mit zwei Variablen vom Typ uint8?
          
    Auflösung254. Einen negativen Wert kann der Typ nicht darstellen. Go rechnet auch hier modulo 256: −2 + 256 = 254.
    3. 
      

    

    
Das richtige Ergebnis von 255 + 1 ist 256. Dafür braucht man 9 Bits, der Typ uint8 hat 8. Go wirft alle Bits weg, die links über die 8 Bits hinausgehen. Das Ergebnis besteht aus den 8 rechten Bits.


    1111 1111    255
+   0000 0001      1
-------------------
  1 0000 0000    256    richtig, braucht 9 Bits
    0000 0000      0    was in uint8 übrig bleibt


    
Das Gleiche als Rechnung

    
Die Bits links wegzuwerfen heißt bei einem Typ ohne Vorzeichen: Go rechnet modulo 2n. Dabei ist n die Zahl der Bits des Typs. Bei uint8 ist n gleich 8, und 28 ist 256.

    
Modulo 256 heißt: Vom richtigen Ergebnis wird 256 so oft abgezogen oder dazugezählt, bis ein Wert von 0 bis 255 übrig ist. Die drei Beispiele des Kurstexts:

    
    
      
  • 255 + 1: 256 mod 256 = 0
    • 
      
  • 130 + 140: 270 mod 256 = 14
    • 
      
  • 255 + 255: 510 mod 256 = 254
    • 
    

    
Im Englischen heißt das „wrap around“: Nach 255 geht es bei 0 weiter.

Ein Überlauf mit Absicht

    
Bei den Typen ohne Vorzeichen legt Go dieses Verhalten fest, und man darf sich darauf verlassen. Manche Programme nutzen es: Eine Hash-Funktion zum Beispiel soll immer einen Wert von 0 bis 2n − 1 liefern und rechnet deshalb absichtlich modulo 2n.

  

  

    
    
  

  


  

  

    
Schritt 3: Mit Vorzeichen

    
Erst vorhersagen, dann ausprobieren
      
    
        
  1. Was gibt fmt.Println(a + b) aus, wenn a und b vom Typ int8 sind und die Werte 127 und 1 haben?
          
    Auflösung−128. Die Summe hat das Bitmuster 1000 0000. Bei int8 zählt das linke Bit −128.
    2. 
        
  2. 12 · 121 und 3 · 121 laufen in int8 beide über. Bei welcher Rechnung ist das Ergebnis negativ?
          
    AuflösungBei 12 · 121: Es kommt −84 heraus. 3 · 121 ergibt 107. Ein Überlauf ist also nicht immer am Vorzeichen zu erkennen.
    3. 
      

    

    
Auch bei int8 behält Go die 8 rechten Bits. Der Typ liest sie aber im Zweierkomplement: Das linke Bit zählt −128. Landet beim Überlauf eine 1 im linken Bit, wird aus einer Summe zweier positiver Zahlen eine negative Zahl.


    0111 1111    127
+   0000 0001      1
-------------------
    1000 0000    128    richtig wäre 128
    1000 0000   -128    als int8 gelesen

Schritt 4: Teilausdrücke

    
Erst vorhersagen, dann ausprobieren
      
    
        
  1. x hat den Typ int8 und den Wert 120. Was ergibt x*3/3?
          
    Auflösung34 und nicht 120. Go rechnet erst x*3. Das wäre 360 und läuft über zu 104. Danach kommt 104 / 3 = 34.
    2. 
      

    

    
Go wertet einen Ausdruck Schritt für Schritt aus. Jedes Zwischenergebnis hat den Typ der Operanden und muss in diesen Typ passen. Läuft ein Zwischenergebnis über, ist das Endergebnis falsch, auch wenn es selbst bequem in den Typ gepasst hätte.


var x int8 = 120
fmt.Println(x*3/3, "vs.", x*(3/3))        // 34 vs. 120
fmt.Println(x*8/12, "vs.", x/12*8)        // -5 vs. 80
fmt.Println((x+20)/2, "vs.", x/2+20/2)    // -58 vs. 70

    
Links und rechts von "vs." steht jedes Mal ein Ausdruck, der mathematisch das Gleiche bedeutet. Links läuft ein Teilausdruck über, rechts nicht.

Zwei Überläufe, die sich aufheben

    
Das vierte Paar der Demo zeigt einen besonders tückischen Fall. x+20-40 liefert 100, und das ist richtig. Trotzdem ist unterwegs zweimal etwas übergelaufen: x+20 ergibt −116 statt 140, und -116 - 40 ergibt 100 statt −156. Der erste Überlauf geht nach oben, der zweite nach unten.

    
Ein richtiges Endergebnis beweist nicht, dass kein Teilausdruck übergelaufen ist. Wer sich nach einem Test mit x+20-40 auf x+20 verlässt, erlebt an anderer Stelle eine Überraschung.

    
Mit int16 statt int8 läuft in keinem der vier Paare etwas über. Dann liefern linker und rechter Ausdruck den gleichen Wert.

  

  

    
    
  

  


  

  

    
Schritt 5: Was man dagegen tut

    
Die Beispiele dieser Seite sind mit Absicht klein. In der Praxis rechnet kaum jemand mit int8. Die meisten Ausdrücke eines Programms können gar nicht überlaufen, weil ihre Werte weit innerhalb des Wertebereichs bleiben. Auf wenige Stellen muss man achten.


    
Den passenden Typ wählen

    
    
      
  • int: Der Typ hat mindestens 32 Bit und reicht damit mindestens bis etwa ±2 Milliarden. Für die meisten Aufgaben genügt das.
    • 
      
  • int64: Der Typ reicht bis etwa ±9 · 1018, das sind 9 Trillionen.
    • 
    


    
Gefährdete Stellen erkennen

    
    
      
  • Große Zahlen multiplizieren: Bei einem Produkt sieht man schlecht, ob es noch in den Typ passt. Schon 100.000 · 100.000 ist größer als 2 Milliarden.
    • 
      
  • Große Zwischenergebnisse: Für einen Durchschnitt werden viele Werte addiert. Die Summe kann überlaufen, obwohl der Durchschnitt selbst klein ist.
    • 
      
  • Mehrere Variablen: Hängt ein Ausdruck von mehreren Variablen oder Funktionswerten ab, lässt sich sein Wert schwer vorhersagen.
    • 
    


    
Vor der Rechnung prüfen

    
Nach einer Addition lässt sich ein Überlauf nicht mehr sicher erkennen. Man prüft deshalb vorher, ob das Ergebnis in den Typ passen wird. Für zwei positive Zahlen a und b vom Typ int8 sieht das so aus:


var a, b int8 = 120, 20
if a > math.MaxInt8-b {      // 120 > 127 - 20
    fmt.Println("Die Summe passt nicht in int8.")
} else {
    fmt.Println(a + b)
}
// Ausgabe: Die Summe passt nicht in int8.

    
Die Bedingung stellt a + b > 127 so um, dass auf keiner Seite etwas überlaufen kann. math.MaxInt8 ist die Konstante für den größten Wert des Typs, also 127. Mit a gleich 100 gibt das Programm 120 aus.

    
Im Kurstext steht nur, dass man vor einer solchen Addition prüfen kann. Das Programm dazu ist eine Ergänzung des Mentors. Die if-Anweisung wird in Abschnitt 5.5.1 behandelt, dazu gibt es die Seite if-Anweisung in Go.


    
Wenn kein Typ reicht

    
Für ganze Zahlen beliebiger Größe gibt es in der Standardbibliothek das Paket math/big. Im Kurstext wird es im Expertenwissen 4.15 genannt und nicht weiter verwendet.

Wo das Thema im Kurstext noch vorkommt

    
    
      
  • Abschnitt 2.3, Seiten 10–11, Teilausdrücke: Bei großen Zahlen kann a · c zu groß für den Wertebereich sein. Dann liefern (a − b) · c und a · c − b · c verschiedene Ergebnisse. Das ist der Gedanke von Schritt 4, dort in Go. Eine Lektion zu diesem Teil von Abschnitt 2.3 gibt es nicht.
    • 
      
  • Abschnitt 4.3.4 und 4.3.5, Seiten 63–66, Wertebereiche: Lektion: Zahlenkreis.
    • 
      
  • Abschnitt 7.1, Seiten 163–165, mehrere Rückgaben: Eine Funktion kann einen Fehler als zweite Rückgabe melden. Die Lektion Funktionen in Go zeigt in Schritt 4 die Funktion safeAdd, die so einen Überlauf meldet.
    • 
    


    
Wie es weitergeht

    
    
      
  • Quiz: Das Quiz zu den Wertebereichen fragt nach den Grenzen der Ganzzahl-Typen.
    • 
      
  • Der Überlauf am Kreis: Die Seite Zahlenkreis, Schritt 3, zeigt den Sprung von 127 nach −128.
    • 
      
  • Der Übertrag im Addierer: Wohin das neunte Bit im Rechenwerk fällt, zeigt die Seite Rechenwerk, Schritt 4.
    • 
      
  • Die Prüfung als Funktion: In Kapitel 7 wird aus der Prüfung die Funktion safeAdd. Sie gibt die Summe und einen Fehler zurück. Das zeigt die Seite Funktionen in Go, Schritt 4.
    • 
      
  • Ein gewollter Überlauf: Eine Hashfunktion setzt den Überlauf bewusst ein, so steht es in Abschnitt 4.3.8. Das rechnet der Exkurs Vertiefung: Blockchain in Go in Schritt 2 Byte für Byte vor. Dort steht in Schritt 4 auch, was bei uint64 aus 75 − 76 wird.
    • 
      
  • Ein Überlauf in einer Schleife: Die Seite break-Anweisung in Go rechnet Fakultäten und prüft vor jeder Multiplikation, ob das Produkt noch passt.
