Das erste Go-Programm: Hello, World!

Ein Programm aus sieben Zeilen, das „Hello, World!“ ausgibt. An ihnen siehst du, woraus jedes Go-Programm besteht: Paketklausel, Import, die Funktion main und ein Aufruf.

Kurstext v3.0.6, Abschnitt 3.1 und 3.2, Seiten 21–24.

Worum es geht

In fast jeder Programmiersprache ist das erste Programm eines, das nur den Text „Hello, World!“ ausgibt. Die Tradition stammt aus dem Buch „The C Programming Language“ von Brian W. Kernighan und Dennis M. Ritchie aus dem Jahr 1978. In Go sieht das Programm so aus:

    Listing 3.1, hello_world.go, Kurstext v3.0.6, Abschnitt 3.2, Seite 22

    So startest du es

    Im Terminal gibst du im Ordner der Datei diesen Befehl ein:

    go run hello_world.go

    Go übersetzt das Programm zuerst in Maschinensprache und führt es danach aus. Das Programm gibt eine Zeile aus und ist dann beendet:

    Hello, World!

    Was beim Übersetzen geschieht, erklärt die Lektion Höhere und niedrigere Programmiersprachen in Schritt 2.

    So arbeitest du mit der Lektion

    • Schritt 1, Zeile für Zeile: Du klickst eine Zeile an und liest, was sie bewirkt.
    • Schritt 2 bis 4: Je ein Teil des Programms genauer: Pakete und Import, Leerraum, die Funktion main. Jeder Schritt zeigt eine geänderte Fassung des Programms. Du sagst erst vorher, was Go damit macht, und siehst dann, was Go meldet oder ausgibt.
    • Schritt 5, selbst ausprobieren: Im Editorlotsen auf deinem Rechner änderst du das Programm und führst es aus. Sonst siehst du, was Go zu jeder Fassung meldet.

    Klick eine Zeile des Programms an. Darunter steht, was sie bewirkt.

      Schritt 2: Pakete und Import

      Was ein Paket ist

      Ein Paket fasst Programmteile zusammen, die einem gemeinsamen Zweck dienen, zum Beispiel der Ausgabe von Text. Ein anderes Programm importiert das Paket und verwendet seine Funktionen wieder. In anderen Programmiersprachen heißt ein Paket Bibliothek oder Modul.

      Die Standardbibliothek

      Zu Go gehört die Standardbibliothek mit über 150 Paketen. Sie liefern, was viele Programme brauchen:

      • Text: einlesen, ausgeben, formatieren und bearbeiten, zum Beispiel mit dem Paket fmt
      • Dateien und Netzwerk: auf das Dateisystem und das Netz zugreifen
      • Rechnen und Ordnen: mathematische Funktionen, Sortieren, Zeit und Datum
      • Dateiformate: zum Beispiel HTML, CSV, JSON, PNG und ZIP
      • Kryptographie: Verschlüsseln und Prüfsummen

      Alle Pakete stehen mit ihrer Beschreibung unter pkg.go.dev/std. Die Seite ist englisch.

      Die Regeln für import

      • Ort: Alle Importdeklarationen stehen direkt nach der Paketklausel.
      • Anzahl: Ein Programm darf mehrere Pakete importieren oder keines.
      • Nutzung: Jedes importierte Paket muss das Programm auch verwenden, mindestens eine Funktion daraus. Sonst übersetzt Go das Programm nicht. So sammeln sich keine unnötigen Pakete an.

        Schritt 3: Leerraum

        Leerzeichen, Tabulatoren und Zeilenumbrüche heißen zusammen Leerraum. Der Leerraum trennt die Teile des Programms voneinander, zum Beispiel package von main. Darüber hinaus beachtet Go ihn nicht. Ob an einer Stelle ein Leerzeichen steht oder mehrere, ist für Go gleich.

        Zwei Ausnahmen

        • Im String-Literal: Zwischen den Anführungszeichen gehört jedes Leerzeichen zur Zeichenkette. Dort ist es kein Leerraum.
        • Zeilenumbrüche: An manchen Stellen hat ein Zeilenumbruch in Go eine Bedeutung. Das erklärt Abschnitt 3.3.2. Die Lektion Fehlersuche: drei kurze Go-Programme zeigt in Schritt 3 ein Beispiel.
        Erst vorhersagen: In dieser Fassung stehen package und main in zwei Zeilen, und an vielen Stellen stehen zusätzliche Leerzeichen, auch im String-Literal. Übersetzt Go das Programm? Wenn ja, was gibt es aus?

          Go übersetzt das Programm. Der zusätzliche Leerraum zwischen den Teilen ändert nichts.

          In der Ausgabe stehen nach dem Komma drei Leerzeichen. Sie stehen im String-Literal und gehören deshalb zur Zeichenkette.

          Leerraum für den Leser

          Für Go ist die Fassung oben so gut wie Listing 3.1. Ein Mensch liest Listing 3.1 leichter. Leerraum setzt du deshalb so, dass das Programm übersichtlich wird: eine Leerzeile zwischen den Teilen, eingerückt ist, was in geschweiften Klammern steht. Go rückt nach seiner Standardformatierung mit einem Tabulator ein. Ein Editor zeigt ihn meist so breit wie vier Leerzeichen.

          Schritt 4: main als Einstiegspunkt

          Die letzten drei Zeilen von Listing 3.1 deklarieren eine Funktion mit dem Namen main. Diese Funktion hat eine besondere Aufgabe:

          • Start: Startet das Programm, ruft Go die Funktion main von selbst auf.
          • Ende: Ist die letzte Anweisung in main ausgeführt, endet main und mit ihr das Programm.
          • Pflicht: Jedes Go-Programm muss deshalb eine Funktion main deklarieren.

          Der Lauf des Programms

          Mit „weiter“ gehst du den Lauf von Listing 3.1 durch. Gelb ist die Zeile, die gerade an der Reihe ist.

            Ausgabe

            Wie ein Aufruf zur Funktion springt und wieder zurückkehrt, zeigt die Lektion Unterprogramme und Funktionen in Schritt 1. Eigene Funktionen in Go stehen in Abschnitt 3.4.

            Erst vorhersagen: In dieser Fassung heißt die Funktion start statt main. Sonst ist alles wie in Listing 3.1. Was geschieht?

              Go übersetzt das Programm nicht. Die Meldung heißt auf Deutsch: Die Funktion main ist im Paket main nicht deklariert.

              Anders als sonst nennt die Meldung keine Zeile. Jede Zeile für sich ist richtig. Go bemerkt den Fehler erst am Schluss, wenn es das Programm zusammensetzt und den Einstiegspunkt sucht. Der Teil runtime.main_main·f vorn ist der Name der Stelle in Go, die main aufrufen soll.

              Schritt 5: Selbst ausprobieren

              Hier stehen Listing 3.1 und die vier Fassungen aus Schritt 2 bis 4. Öffnest du die Lektion im Editorlotsen auf deinem Rechner, änderst du ein Programm hier im Editor und führst es aus. Der Editorlotse übersetzt es mit Go und zeigt die Ausgabe oder die Meldung an. Sonst siehst du, was Go zu jeder Fassung meldet oder ausgibt.

              Vorschläge zum Ausprobieren:

              • Eigener Text: Lass das Programm deinen Namen ausgeben.
              • Zweite Zeile: Schreib unter den Aufruf einen zweiten Aufruf von fmt.Println mit einem anderen Text.
              • Fehler einbauen: Lösch ein Anführungszeichen oder die letzte Klammer } und lies, was Go meldet.

              Die Seite speichert nicht, was du im Editor schreibst. Lädst du die Seite neu, steht dort wieder die Fassung der Lektion.
