Vergleich von Verbünden in Go

Zwei Verbünde sind gleich, wenn alle ihre Felder gleich sind. Zwei Verbund-Variablen mit dem gleichen Wert bleiben trotzdem zwei Variablen an zwei Adressen.

Kurstext v3.0.6, Abschnitt 8.2.5, Seite 208.

Worum es geht

Ein Datentyp heißt in Go vergleichbar, englisch comparable, wenn die Operatoren == und != für ihn definiert sind. Alle primitiven Datentypen sind vergleichbar.

Für Verbünde gelten zwei Regeln:

  • Wann ein Verbund-Typ vergleichbar ist: wenn alle seine Feld-Typen vergleichbar sind.
  • Wann zwei Verbund-Werte gleich sind: wenn alle ihre Feld-Werte gleich sind.

Die Beispiele verwenden den Typ koordinate aus dem Kurstext:

type koordinate struct {
    x, y, z int
}

Was dazugehört

  • Abschnitt 4.5.2, Vergleichsoperatoren: Die Lektion Logische Operatoren und Vergleiche zeigt == und != für die primitiven Datentypen.
  • Abschnitt 7.4, Vergleich von Zeigern: Zwei Zeiger sind gleich, wenn sie auf dieselbe Variable zeigen. Das steht in der Lektion Zeiger in Go, Schritt 2.
  • Abschnitt 8.2.1, Verbund-Literal: Die Lektion Verbund in Go, Schritt 3.

Schritt 1: Feld für Feld

Erst vorhersagen, dann ausprobieren
  1. a ist koordinate{5, -7, 8}, b ist koordinate{0, -7, 8}. Zwei von drei Feldern stimmen überein. Was liefert a == b?
    Auflösungfalse. Schon ein Feld mit verschiedenen Werten genügt.

Beim Vergleich zweier Verbund-Werte vergleicht Go die Felder, die einander entsprechen. Für den Typ koordinate bedeutet a == b das Gleiche wie:

a.x == b.x && a.y == b.y && a.z == b.z

    Schritt 2: Gleicher Wert oder dieselbe Variable

    Erst vorhersagen, dann ausprobieren
    1. a und b haben beide den Wert {5 -7 8}. Was liefert &a == &b?
      Auflösungfalse. &a und &b sind die Adressen von zwei verschiedenen Variablen.

    Zwei Fragen sehen ähnlich aus und sind verschieden:

    • Haben zwei Variablen den gleichen Wert? Das fragt a == b. Verglichen werden die Felder.
    • Ist es dieselbe Variable? Das fragt &a == &b. Verglichen werden die Adressen.

    Auch wenn a == b gilt, sind a und b zwei Variablen. Es gilt dann weiter &a != &b.

    Für die Auswahl gilt der Stand am Ende von Schritt 1, dazu eine Farbe:

    a := koordinate{5, -7, 8}
b := koordinate{5, -7, 8}
f := rgb{5, -7, 8}

    Schritt 3: Der Vergleich im Speicher

    Erst vorhersagen, dann ausprobieren
    1. In den drei Zellen von a und in den drei Zellen von b stehen die gleichen Bitmuster. Du schaltest in einer Zelle von b ein einziges Bit um. Was liefert a == b danach?
      Auflösungfalse. Ein anderes Bitmuster ist bei einer Ganzzahl ein anderer Wert, und ein Feld mit einem anderen Wert genügt.

    Im Hauptspeicher ist ein Verbund eine Reihe von Zellen, in denen die Felder hintereinander liegen. Jede Zelle fasst 8 Bit. Der Vergleich a == b sieht dort so aus: Der Rechner liest die Zellen jedes Felds von a und die Zellen des gleichen Felds von b und vergleicht die Bitmuster.

    • Gleiche Bitmuster in allen Feldern: Die zwei Verbünde sind gleich.
    • Ein Bit ist verschieden: Das Feld hat einen anderen Wert, die zwei Verbünde sind verschieden.

    Damit ein Feld in eine Zelle passt, haben die Felder in diesem Modell den Typ int8:

    type koordinate struct {
    x, y, z int8
}

a := koordinate{5, -7, 8}  // liegt in den Zellen 100 bis 102
b := koordinate{0, -7, 8}  // liegt in den Zellen 103 bis 105

    Ein Klick auf ein Bit schaltet es um. Die Seite vergleicht nach jedem Klick neu.

    Zwei Adressen

    &a ist in diesem Modell die Adresse 100, &b ist die Adresse 103. Der Vergleich &a == &b vergleicht diese zwei Zahlen und sieht die Zellen gar nicht an. Er liefert deshalb false, gleich was in den Zellen steht.

    Das Modell vereinfacht. Für Ganzzahlen stimmt es genau: gleicher Wert, gleiches Bitmuster. Go vergleicht aber Feld für Feld nach den Regeln des Feld-Typs. Bei einem Feld vom Typ string vergleicht Go die Zeichen der zwei Strings. Die Zellen, die Adressen 100 bis 105 und der Typ int8 für die Felder gehören zum Modell dieser Seite, im Kurstext hat koordinate Felder vom Typ int.
