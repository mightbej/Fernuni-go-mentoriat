1. Was ist ein hierarchischer Verbund?

Ein hierarchischer Verbund enthält selbst wieder einen Verbund als Feld. So lassen sich Daten in sinnvollen Ebenen strukturieren, etwa Person und Fahrzeug oder Adresse und Firma.

Kernidee: Statt alles flach nebeneinander zu speichern, werden zusammengehörige Informationen gruppiert.

2. Feld als Verbund-Wert

Im Typ besitzerW speichert das Feld fahrzeug den kompletten auto-Wert. Das bedeutet: Jeder Besitzer besitzt seine eigene Kopie.

type besitzerW struct { name string ort string fahrzeug auto }
Folge: Wird das Fahrzeug später geändert, dann bleibt eine frühere Kopie unverändert.

3. Feld als Zeiger

Im Typ besitzerZ speichert das Feld fahrzeug nur einen Zeiger auf ein auto. Dadurch können mehrere Besitzer auf dasselbe Fahrzeug zeigen.

type besitzerZ struct { name string ort string fahrzeug *auto }
Folge: Änderungen am gemeinsamen Fahrzeug sind für alle Referenzen sichtbar.

4. Kopie versus Referenz

Die Demo zeigt, dass ein Wertfeld ein eigenständiges Objekt erzeugt, während ein Zeigerfeld nur auf die vorhandene Struktur verweist.

altesAuto := mike.fahrzeug var pMikesAuto *auto = &(mike.fahrzeug)
VarianteEigenschaft
altesAutoKopie des Feldwerts, unabhängig vom Original
pMikesAutoZeiger auf das Feld, sichtbar bei jeder Änderung

5. Warum Zeiger-Felder oft praktischer sind

Wenn mehrere Strukturen dieselben Daten teilen sollen, ist ein Zeiger-Feld flexibler. Das spart Kopien und erlaubt gemeinsames Arbeiten am gleichen Objekt.

Praxis: Die Go-Demo zeigt ein gemeinsames Auto für mehrere Besitzer-Zeiger.

6. Zusammenfassung

KonzeptMerksatz
Hierarchischer VerbundVerbund enthält wieder einen Verbund
Wert-Feldeigene Kopie, keine gemeinsame Änderung
Zeiger-Feldgemeinsame Referenz, Änderungen sichtbar
Fazit: Wert für Unabhängigkeit, Zeiger für gemeinsames Objekt und effizienten Zugriff.
