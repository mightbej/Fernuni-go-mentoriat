Verbund in Go: der Datentyp struct

Ein Verbund fasst Werte verschiedener Typen unter einem Namen zusammen, zum Beispiel Vorname, Geburtsjahr und Wohnort einer Person. In Go heißt der Verbund struct.

Kurstext v3.0.6, Abschnitt 8.1 bis 8.2.2, Seiten 195–203.

Worum es geht

Ein Array fasst viele Werte des gleichen Typs zusammen. Ein Verbund fasst Werte zusammen, die zusammengehören und verschiedene Typen haben dürfen. Andere Namen für den Verbund sind Datensatz, englisch Record, und in Go Struct.

Die Teile eines Verbunds heißen Felder. Jedes Feld hat einen Namen und einen Typ.

Schritt 1: Wozu ein Verbund

Erst vorhersagen, dann ausprobieren
  1. Die Daten von zwei Personen stehen in sechs Variablen: nummerA, vornameA, nachnameA und das Gleiche mit B. Wie viele Paare von Variablen muss ein Programm tauschen, damit A und B die Plätze wechseln?
    AuflösungDrei, eines für jede Angabe. Mit einem Verbund ist es ein einziger Tausch.

Im Kurstext steht als Beispiel die Lochkarte: 80 Spalten, aufgeteilt in feste Bereiche für Personalnummer, Nachname, Vorname, Geburtsdatum und Gehalt. Eine Karte trägt die Daten einer Person.

Ein Programm soll viele solche Karten speichern. Ohne Verbund gibt es zwei Wege, und beide haben den gleichen Mangel:

  • Einzelne Variablen: nachnameA, nachnameB, vornameA, vornameB. Dass nachnameA und vornameA zu einer Person gehören, steht nur im letzten Buchstaben des Namens.
  • Ein Array je Angabe: ein Array für die Nachnamen, eines für die Vornamen, eines für die Personalnummern. Was zusammengehört, steht nur am gleichen Index.

Mit einem Verbund gehören die Daten einer Person zu einer Variable. Auf ein Feld greift das Programm mit einem Punkt zu, zum Beispiel personA.nachname.

    Ausgabe

    Viele Verbünde: ein Array von Verbünden

    Für das Personal eines ganzen Unternehmens nimmt man ein Array, dessen Elemente Verbünde sind. Die Suche nach einer Person läuft dann über ein einziges Array:

    for i, _ := range personArr {
    if personArr[i].Vorname == "Gundel" && personArr[i].Nachname == "Gaukeley" {
        return personArr[i].Personalnummer
    }
}

    Ohne Verbund müsste die Schleife in drei Arrays zugleich nachsehen.

    Schritt 2: Der Verbund-Typ

    Erst vorhersagen, dann ausprobieren
    1. Zwei Verbund-Definitionen haben die gleichen fünf Felder mit den gleichen Typen. In der zweiten steht nachname vor vorname. Ist das der gleiche Datentyp?
      AuflösungNein. Zum Typ gehören die Namen der Felder, ihre Typen und ihre Reihenfolge.

    Ein Verbund wird mit dem Schlüsselwort struct definiert. Jedes Feld steht in einer eigenen Zeile: erst der Name, dann der Typ. Hinter dem Typ steht kein Komma.

    struct {
    vorname     string
    nachname    string
    gebJahr     int
    ort         string
    verheiratet bool
}

    Ein Name für den Typ

    Vor die Definition setzt man das Schlüsselwort type und einen Bezeichner. Das deklariert einen benannten Datentyp:

    type person struct {
    vorname     string
    nachname    string
    gebJahr     int
    ort         string
    verheiratet bool
}

    Der Typname person steht danach überall, wo auch int oder string stehen kann:

    var ich person
var großeltern [4]person

func jünger(p1, p2 person) person {
    // ...
}

    Vier Schreibweisen im Vergleich

    Wähle eine Definition. Die Seite sagt, ob sie den gleichen Datentyp beschreibt wie die Definition oben.

    Groß oder klein geschrieben

    Auch für Typnamen und Feldnamen gilt die Regel aus Abschnitt 3.3.4: Nur ein Bezeichner, der mit einem Großbuchstaben beginnt, wird exportiert und ist außerhalb seines Pakets sichtbar. In der Standardbibliothek sind Typnamen und Feldnamen von Verbünden deshalb meist groß geschrieben. Die Beispiele des Kurstexts schreiben sie klein, weil sie nichts exportieren.

    Schritt 3: Null-Wert und Literale

    Erst vorhersagen, dann ausprobieren
    1. Was gibt fmt.Println(anna) nach var anna person aus?
      Auflösung{ 0 false}. Jedes Feld hat den Null-Wert seines Typs. Die drei leeren Strings sieht man nur an den Leerzeichen dazwischen.
    2. Ein Array-Literal darf weniger Werte nennen, als das Array Elemente hat. Gilt das auch für person{"Anna", "Schmidt", 1966, "Hamburg"}?
      AuflösungNein. In der Schreibweise ohne Feldnamen müssen alle fünf Werte dastehen.

    Der Null-Wert

    Eine Verbund-Variable ohne Anfangswert bekommt den Null-Wert ihres Typs. Er besteht aus den Null-Werten der Felder, bei person also aus "", "", 0, "" und false.

    Das Verbund-Literal

    Ein Verbund-Literal schreibt einen Wert des Typs hin: erst der Typname, dann die Werte der Felder in geschweiften Klammern. Dafür gibt es zwei Schreibweisen:

    • Ohne Feldnamen: Die Werte aller Felder stehen in der Reihenfolge der Definition, getrennt durch Kommas. Es darf keiner fehlen.
    • Mit Feldnamen: Vor jedem Wert stehen der Feldname und ein Doppelpunkt. Die Reihenfolge ist frei. Ein Feld, das fehlt, bekommt seinen Null-Wert.
    karl = person{
    nachname: "Müller",
    vorname:  "Karl",
    ort:      "Köln",
    gebJahr:  1955, // Komma ist Pflicht
}

    Steht das Literal über mehrere Zeilen, braucht auch die letzte Angabe ein Komma. Das ist die gleiche Regel wie beim Array-Literal.

    Wähle eine Zeile. Die Seite zeigt, was fmt.Println für die Variable ausgibt, oder die Meldung des Compilers.

    Ausgabe

    Hinweis 8.1 des Kurstexts: Die Schreibweise ohne Feldnamen ist kurz. Ändert jemand später die Reihenfolge der Felder, muss er jedes Literal anpassen. Tauscht er zwei Felder des gleichen Typs, etwa nachname und vorname, meldet der Compiler nichts. In der Praxis nimmt man deshalb meist die Schreibweise mit Feldnamen. Die kurze passt zu kleinen Typen mit einer festen Reihenfolge, zum Beispiel koordinate{10, -7, 22} für x, y und z oder rgb{255, 255, 0} für Rot, Grün und Blau.

    Schritt 4: Ausgabe

    Erst vorhersagen, dann ausprobieren
    1. fmt.Println(anna) gibt {Anna Schmidt 1966 Hamburg false} aus. Woran erkennt ein Leser, welcher Wert der Wohnort ist?
      AuflösungAn der Ausgabe erkennt er es nicht, er muss die Definition des Typs kennen. Mit %+v stehen die Feldnamen dabei.

    fmt.Println gibt von einem Verbund die Werte der Felder in geschweiften Klammern aus. fmt.Printf mit dem Verb %v tut das Gleiche. Zwei Flags vor dem v ändern die Ausgabe:

    • %+v: Die Feldnamen stehen dabei.
    • %#v: Die Ausgabe hat die Form eines Verbund-Literals mit Feldnamen.
