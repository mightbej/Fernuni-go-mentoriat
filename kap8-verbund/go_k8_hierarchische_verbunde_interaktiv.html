Hierarchische Verbünde: ein Verbund als Feld

Ein Feld eines Verbunds darf selbst ein Verbund sein. Die Seite zeigt, was ein solches Feld speichert und was sich ändert, wenn das Feld stattdessen einen Zeiger auf einen Verbund enthält.

Kurstext v3.0.6, Abschnitt 8.3, Seiten 212–214.

Was die Seite zeigt

Bei der Deklaration eines Felds kann fast jeder Datentyp stehen, auch ein Verbund-Typ. Ein Verbund, der einen anderen Verbund als Feld enthält, heißt hierarchischer Verbund.

Das Beispiel der Seite stammt aus dem Kurstext: Ein Besitzer hat einen Namen, einen Ort und ein Fahrzeug. Das Fahrzeug ist selbst ein Verbund vom Typ auto mit Marke, Kennzeichen, Tachostand und TÜV-Jahr.

Für das Feld fahrzeug gibt es zwei Bauweisen:

  • Verbund als Feld: Das Feld hat den Typ auto. Es enthält die vier Werte des Autos selbst. So ist der Typ besitzerW gebaut.
  • Zeiger als Feld: Das Feld hat den Typ *auto. Es enthält die Adresse eines Autos, das in einer anderen Variable gespeichert ist. So ist der Typ besitzerZ gebaut.
type auto struct {
    marke       string
    kennzeichen string
    tachostand  int
    tüvJahr     int
}

type besitzerW struct {
    name     string
    ort      string
    fahrzeug auto  // Feld mit Verbund-Typ
}

type besitzerZ struct {
    name     string
    ort      string
    fahrzeug *auto // Feld mit Zeiger auf Verbund-Typ
}

Die Seite geht in vier Schritten vor. Jeder Schritt hat oben einen Reiter.

  • Schritt 1, Verbund als Feld: Die Variable mike enthält ein ganzes Auto. Ein Klick auf ein Feld zeigt den Ausdruck, der zu ihm führt.
  • Schritt 2, Kopie und Zeiger: Ein Programm kopiert das Auto von mike in eine Variable und merkt sich in einer zweiten Variable die Adresse des Felds. Danach bekommt mike ein neues Auto.
  • Schritt 3, Zeiger als Feld: Zwei Besitzer teilen sich ein Auto. Drei Anweisungen ändern es auf drei Wegen.
  • Schritt 4, Wert oder Zeiger: Eine Tabelle stellt beide Bauweisen nebeneinander.

Worauf die Seite aufbaut

  • Datenverbund in Kapitel 2: In Abschnitt 2.2, Seite 9, wird eine Person mit Vorname, Nachname, Adresse und Telefonnummer beschrieben. Die Adresse ist dort selbst aus Straße, Hausnummer, Postleitzahl und Ort zusammengesetzt. Das ist ein hierarchischer Verbund ohne Go. Dazu gibt es die Seite Variablen, Typen und Speicher, Schritt 3.
  • Zuweisung eines Verbunds: Eine Zuweisung kopiert alle Felder eines Verbunds. Das steht in Abschnitt 8.2.3, Seiten 204–205. Dazu gibt es die Seite Speichermodell: Verbund.
  • Zeiger: Ein Zeiger ist eine Variable, deren Wert eine Adresse ist. Das steht in Abschnitt 7.4, Seiten 173–178. Dazu gibt es die Seite Speichermodell: Zeiger.
  • Zeiger auf einen Verbund: Über einen Zeiger erreicht man ein Feld mit p.feld. Go folgt dem Zeiger dabei von selbst. Das steht in Abschnitt 8.2.4, Seiten 205–207, Hinweis 8.2. Dazu gibt es die Seite Zeiger auf Verbünde.

Schritt 1: Ein Verbund als Feld

Das Feld fahrzeug im Typ besitzerW hat den Typ auto. Sein Wert ist ein ganzer Verbund mit vier Feldern. Im Literal steht deshalb an der Stelle des Felds ein zweites Literal: auto{…}.

mike := besitzerW{
    name: "Mike",
    ort:  "München",
    fahrzeug: auto{
        marke:       "Mercedes",
        kennzeichen: "M-RT357",
        tachostand:  133000,
        tüvJahr:     2024,
    },
}
fmt.Println("Mike mit altem Auto:", mike)
// Mike mit altem Auto: {Mike München {Mercedes M-RT357 133000 2024}}

Die Ausgabe zeigt die Hierarchie mit geschweiften Klammern: Die inneren Klammern umschließen die vier Werte des Autos.

Der äußere Kasten ist die Variable mike. Der grüne Kasten darin ist das Feld fahrzeug. Es liegt in mike selbst. Ein Klick auf ein Feld oder auf den Kopf eines Kastens zeigt den Ausdruck dazu.

Der Punkt hängt die Namen aneinander, von außen nach innen. mike.fahrzeug ist das ganze Auto, mike.fahrzeug.tachostand ist ein Feld dieses Autos.

    Schritt 3: Ein Zeiger als Feld

    Zwei Personen sollen sich ein Auto teilen. Mit besitzerW geht das nicht, denn jedes Feld fahrzeug enthält ein eigenes Auto. Im Typ besitzerZ hat das Feld den Typ *auto. Es enthält die Adresse eines Autos, und zwei Felder können dieselbe Adresse enthalten.

      Schritt 4: Wert oder Zeiger

      Die Tabelle stellt die zwei Bauweisen des Felds fahrzeug nebeneinander. Die Beispiele stammen aus Schritt 2 und Schritt 3.

      FrageFeld fahrzeug auto im Typ besitzerWFeld fahrzeug *auto im Typ besitzerZ
      Was speichert das Feld?Das Feld speichert die vier Werte des Autos.Das Feld speichert die Adresse eines Autos. Die vier Werte stehen in einer anderen Variable.
      Was geschieht bei einer Zuweisung an das Feld?mike.fahrzeug = bmw kopiert die vier Werte von bmw in das Feld.fahrzeug: &audi speichert die Adresse von audi im Feld. Die Werte bleiben, wo sie sind.
      Können zwei Besitzer dasselbe Auto haben?Nein. Jeder Besitzer hat in seinem Feld eine eigene Kopie.Ja. Die Felder von olaf und olga enthalten dieselbe Adresse.
      Wer bemerkt eine Änderung am Auto?Nur der Besitzer, in dessen Feld geändert wurde. bmw.tachostand = 8000 ändert mike.fahrzeug nicht.Alle, die auf das Auto zeigen. olaf.fahrzeug.tachostand += 1000 ändert auch den Wert, den olga und audi liefern.
      Wie lautet der Zugriff auf den Tachostand?mike.fahrzeug.tachostandolaf.fahrzeug.tachostand. Die Schreibweise ist dieselbe, Go folgt dem Zeiger von selbst.

      Im Kurstext steht dazu: Hierarchische Verbünde mit Zeigern als Feldern sind flexibler einsetzbar als solche mit ganzen Verbund-Werten als Feldern. In der Praxis werden deshalb meist Zeiger auf Verbünde als Feld-Typ verwendet.

      Wo das Thema im Kurstext noch vorkommt

      • Abschnitt 2.2, Seiten 8–10, Datenverbund: Ohne Go steht dort das Beispiel einer Person mit Vorname, Nachname, Adresse und Telefonnummer. Die Adresse ist selbst wieder zusammengesetzt. Lektion: Variablen, Typen und Speicher, Schritt 3.
      • Abschnitt 7.3 und 7.4, Seiten 171–184, Zeiger: Lektion: Zeiger in Go.

      Wie es im Kurstext weitergeht

      • Abschnitt 8.3.1, Seiten 215–216: Ein Verbund-Typ darf ein Feld mit einem Zeiger auf den eigenen Typ haben. So entsteht ein rekursiver Verbund-Typ, zum Beispiel ein Stammbaum. Dazu gibt es die Seite Rekursive Verbund-Typen.
      • Abschnitt 8.3.2, Seiten 216–220: Ein Feld ohne Namen heißt anonymes Feld. Es verkürzt den Zugriff auf die Felder des eingebetteten Verbunds. Dazu gibt es die Seite Anonyme Felder und eingebettete Verbünde.
