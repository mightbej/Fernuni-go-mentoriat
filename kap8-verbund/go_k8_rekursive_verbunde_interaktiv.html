Rekursive Verbund-Typen in Go

Ein Verbund darf ein Feld haben, das auf einen Verbund des gleichen Typs zeigt. So hängen Verbünde aneinander: zu einem Stammbaum, und in Kapitel 9 zu einer verketteten Liste.

Kurstext v3.0.6, Abschnitt 8.3.1, Seiten 215–216.

Worum es geht

Der Typ eines Felds darf fast jeder Datentyp sein, auch ein anderer Verbund-Typ. Eine Ausnahme gibt es: Ein Verbund-Typ darf sich nicht selbst als Feld enthalten. Erlaubt ist ein Feld mit einem Zeiger auf den eigenen Typ.

Ein Verbund-Typ, dessen Felder Zeiger auf Verbünde des gleichen Typs enthalten, heißt rekursive Datenstruktur. Auf dieser Bauweise beruhen die verkettete Liste und der Baum in Kapitel 9.

Was dazugehört

  • Abschnitt 8.3, Verbund als Feld und Zeiger als Feld: Die Lektion Hierarchische Verbünde.
  • Abschnitt 8.2.4, Zeiger auf Verbünde: Die Lektion Zeiger auf Verbünde zeigt die Kurzschreibweise p.feld und einen Zeiger im Speicher.
  • Abschnitt 7.4, nil: Der Null-Wert eines Zeigers. Er steht in der Lektion Zeiger in Go, Schritt 2.
  • Abschnitt 7.5, Rekursion: Die Lektion Rekursion in Go zeigt Funktionen, die sich selbst aufrufen. Hier ist es ein Typ, der sich selbst nennt.

Schritt 1: Der Typ selbst als Feld

Erst vorhersagen, dann ausprobieren
  1. Ein Verbund mensch soll zwei Felder vater und mutter vom Typ mensch haben. Wie viele Zellen müsste der Rechner für eine Variable dieses Typs reservieren?
    AuflösungUnendlich viele. In jedem mensch lägen zwei weitere, in jedem von ihnen wieder zwei, ohne Ende.

Diese Deklaration übersetzt Go nicht:

// NICHT ZULÄSSIG
type mensch struct {
    name          string
    vater, mutter mensch // der Typ selbst als Feld-Typ
}
invalid recursive type: mensch refers to itself

Der Grund zeigt sich im Hauptspeicher. Die Felder eines Verbunds liegen in seinen Zellen. Ein Feld vom Typ mensch wäre ein ganzer Verbund im Verbund, mit eigenem Vater und eigener Mutter, und die Definition käme nie an ein Ende.

Mit einem Zeiger geht es

// rekursiver Verbund-Typ
type mensch struct {
    name          string
    vater, mutter *mensch // Zeiger-Typ des Verbund-Typs
}

Auch diese Definition nennt den eigenen Typ. Zwei Gründe machen sie zulässig:

  • Feste Größe: Ein Zeiger belegt immer 8 Zellen, gleich worauf er zeigt. Die Felder vater und mutter brauchen zusammen 16 Zellen. In ihnen steht je eine Adresse, der andere Verbund liegt an einer anderen Stelle im Speicher.
  • Ein Ende: Ein Zeiger darf nil sein. Wer keinen Vater eingetragen hat, bekommt im Feld vater den Wert nil, und dort hört die Kette auf.
Feld-TypWas in den Zellen des Felds liegtÜbersetzt Go die Deklaration?
vater menschDort läge ein ganzer Verbund vom Typ mensch.Nein, der Typ hätte keine endliche Größe.
vater *menschDort liegt eine Adresse in 8 Zellen oder nil.Ja.

Schritt 2: Ein Stammbaum

Erst vorhersagen, dann ausprobieren
  1. Nach chris := mensch{"Chris", &achim, &anita}: Liegt in der Variable chris eine Kopie von achim?
    AuflösungNein. Im Feld vater liegt die Adresse von achim. Den Verbund achim gibt es nur einmal.

Mit dem Typ mensch entsteht ein kleiner Stammbaum. Jeder Mensch ist eine Verbund-Variable. Wer Eltern hat, bekommt ihre Adressen in die Felder vater und mutter.

Unter dem Rahmen steht der Hauptspeicher des Modells: je Variable ein Block mit ihrer Anfangsadresse und ihrem Inhalt. In einem Zeiger-Feld steht eine Zahl, die Adresse eines anderen Verbunds, oder nil. Die Adressen sind erfunden.

    Ausgabe

    Im Kurstext gibt das Programm die ganze Verwandtschaft aus:

    fmt.Println(erik.name, "hat Vater", erik.vater.name,
    "und Mutter", erik.mutter.name,
    "sowie die Opas", erik.vater.vater.name,
    "und", erik.mutter.vater.name,
    "und die Omas", erik.vater.mutter.name,
    "und", erik.mutter.mutter.name)
    Erik hat Vater Chris und Mutter Dagmar sowie die Opas Achim und Bert und die Omas Anita und Bärbel

    Schritt 3: Dem Zeiger folgen

    Erst vorhersagen, dann ausprobieren
    1. Achim hat keinen Vater eingetragen. Was liefert erik.vater.vater.vater?
      Auflösungnil. erik.vater.vater ist Achim, und in seinem Feld vater steht nil.

    Der Ausdruck erik.vater.vater.name ist eine Kette von Feld-Zugriffen. Bei jedem Punkt hinter einem Zeiger folgt Go dem Zeiger von selbst, das ist die Kurzschreibweise aus Abschnitt 8.2.4. Im Hauptspeicher ist jeder dieser Punkte ein Sprung: Der Rechner liest eine Adresse aus einem Feld und geht zu dem Verbund an dieser Adresse.

    Wähle einen Ausdruck. Die Verbünde, die der Rechner dabei besucht, sind gelb markiert.

    Wert oder Meldung

    Vor jedem Sprung muss feststehen, dass der Zeiger auf einen Verbund zeigt. Ein Programm prüft dafür mit != nil, zum Beispiel if erik.vater != nil.

    Schritt 4: Eine Kette

    Erst vorhersagen, dann ausprobieren
    1. Eine Schleife beginnt bei Erik und geht in jedem Durchlauf zum Vater weiter, bis kein Vater mehr eingetragen ist. Welche Namen gibt sie aus?
      AuflösungErik, Chris, Achim. Bei Achim steht im Feld vater der Wert nil, dort endet die Schleife.

    Wer immer nur dem Feld vater folgt, läuft eine Kette entlang: von Erik zu Chris, von Chris zu Achim. Wie lang die Kette ist, steht nirgends. Eine Schleife läuft deshalb, bis der Zeiger nil ist:

      Ausgabe

      Der Zeiger p wandert. In jedem Durchlauf liest die Schleife aus dem Verbund, auf den p zeigt, die Adresse des nächsten und legt sie in p ab.

      Von hier zur verketteten Liste

      In Abschnitt 9.2 des Kurstexts wird aus dieser Bauweise die verkettete Liste. Ihr Element ist ein rekursiver Verbund-Typ mit einem Wert und einem Zeiger auf das nächste Element:

      type listenElement struct {
    wert     int
    nächstes *listenElement
}
      FrageStammbaum in diesem SchrittVerkettete Liste in Abschnitt 9.2
      Welches Feld führt weiter?Das Feld vater vom Typ *mensch führt weiter.Das Feld nächstes vom Typ *listenElement führt weiter.
      Woran erkennt man das Ende?Im Feld vater steht nil.Im Feld nächstes steht nil.
      Wie läuft ein Programm hindurch?Eine Schleife läuft mit p = p.vater, bis p gleich nil ist.Eine Schleife läuft mit dem Zeiger auf das nächste Element, bis er nil ist.

      Ein Array hat eine feste Länge. Eine Kette aus Verbünden wächst mit jedem Verbund, der angehängt wird. Das ist der Grund für die dynamischen Datenstrukturen in Kapitel 9.
