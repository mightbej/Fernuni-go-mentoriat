Bubblesort auf einem Verbund-Array

Ein Telefonbuch ist ein Array von Verbünden. Bubblesort sortiert es nach dem Namen: Er vergleicht Nachbarn und vertauscht zwei ganze Verbünde mit einer Zuweisung.

Kurstext v3.0.6, Abschnitt 8.4.2, Seiten 225–226.

Worum es geht

Die binäre Suche aus Abschnitt 8.4.1 findet einen Namen im Telefonbuch schnell. Sie setzt voraus, dass das Array nach dem Feld name sortiert ist. Ist es das nicht, muss das Programm erst sortieren.

Das Sortierverfahren des Kurstexts ist Bubblesort: Er vergleicht benachbarte Elemente und vertauscht sie, wenn sie in der falschen Reihenfolge stehen. Neu gegenüber den Programmierübungen zu Kapitel 6 und 7 ist, was sortiert wird. Ein Element ist hier ein Verbund mit Name und Telefonnummer, und verglichen wird nur ein Feld.

Schritt 1: Namen vergleichen

Erst vorhersagen, dann ausprobieren
  1. Was liefert "meier" > "Zimmer"?
    Auflösungtrue. Go vergleicht Byte für Byte. Das kleine m hat den Wert 109, das große Z den Wert 90.

Das Telefonbuch besteht aus Verbünden des Typs person:

type person struct {
    name          string
    telefonnummer int
}

telbuch := [10]person{{"Meier", 4711}, {"Schulz", 1234}, {"Becker", 5522}, {"Wagner", 9081}, {"Arnold", 3310},
    {"Koch", 7745}, {"Zimmer", 2063}, {"Fischer", 6398}, {"Lange", 8127}, {"Huber", 4456}}

Sortiert wird nach dem Feld name. Dafür vergleicht das Programm zwei Strings mit >. Wähle einen Vergleich.

Ausgabe oder Meldung

Im Kurstext heißt die Reihenfolge „alphabetisch“. Das stimmt, solange alle Namen gleich geschrieben sind: großer Anfangsbuchstabe, keine Umlaute. Die zehn Namen dieser Lektion sind so gewählt.

Schritt 2: Die Funktion

Erst vorhersagen, dann ausprobieren
  1. Die Funktion bekommt einen Zeiger auf das Array und hat keine Rückgabe. Woher weiß main nach dem Aufruf, wie das sortierte Array aussieht?
    AuflösungDie Funktion sortiert das Array von main selbst. Der Zeiger enthält dessen Adresse, eine Kopie des Arrays gibt es nicht.
// sortiert das Verbund-Array aufsteigend nach dem Feld name
func bubblesort(a *[10]person) {
    // äußere Schleife: noch zu sortierende Elemente
    for n := len(a); n > 1; n-- {
        // innere Schleife: Sortieren durch Vertauschen
        for i := 0; i < n-1; i++ {
            if a[i].name > a[i+1].name {
                // vertausche benachbarte Elemente
                a[i], a[i+1] = a[i+1], a[i]
            }
        }
    }
}
  • a *[10]person: Der Parameter ist ein Zeiger auf ein Array von zehn Verbünden. Der Aufruf lautet bubblesort(&telbuch). Kopiert wird eine Adresse und kein Verbund.
  • len(a): len liefert auch für einen Zeiger auf ein Array dessen Länge, hier 10.
  • a[i].name: Das ist die Kurzschreibweise für (*a)[i].name: dem Zeiger folgen, das Element mit dem Index i nehmen, davon das Feld name.
  • Innere Schleife: Sie vergleicht die Nachbarn mit den Indizes i und i+1, von links nach rechts. Der Verbund mit dem größten Namen wandert dabei bis ans Ende des betrachteten Teils.
  • Äußere Schleife: n ist die Zahl der Elemente, die noch zu sortieren sind. Nach jedem Durchgang steht ein weiteres Element an seinem Platz, n wird um eins kleiner.
  • a[i], a[i+1] = a[i+1], a[i]: Die Tupel-Zuweisung vertauscht zwei ganze Verbünde. Name und Telefonnummer bleiben zusammen.
Ohne Verbünde bräuchte das Telefonbuch zwei Arrays, eines für die Namen und eines für die Nummern. Bei jedem Tausch müsste das Programm in beiden Arrays vertauschen, und ein vergessener Tausch brächte Namen und Nummern durcheinander.

Schritt 3: Durchgang für Durchgang

Erst vorhersagen, dann ausprobieren
  1. Das Telefonbuch beginnt mit Meier, Schulz, Becker. Wo steht der Eintrag „Zimmer“ nach dem ersten Durchgang?
    AuflösungAm Ende, am Index 9. Zimmer ist der größte Name. Er gewinnt jeden Vergleich mit seinem rechten Nachbarn und wandert bis ans Ende.

Die Demo zeigt den ersten Durchgang Vergleich für Vergleich. Jeder weitere Durchgang ist eine Anweisung der Demo. Grün sind die zwei Elemente des letzten Vergleichs oder, nach einem ganzen Durchgang, die Elemente an ihrem endgültigen Platz.

Im Rahmen von bubblesort steht kein Array. Dort steht der Zeiger a. Das Array gibt es nur einmal, im Rahmen von main.

    Schritt 4: Aufwand

    Erst vorhersagen, dann ausprobieren
    1. Zehn Einträge brauchen 45 Vergleiche. Wie viele brauchen hundert Einträge?
      Auflösung4950. Zehnmal so viele Einträge brauchen rund hundertmal so viele Vergleiche.

    Der erste Durchgang vergleicht n − 1 Paare, der zweite n − 2, der letzte eines. Bei einem Array mit n Elementen sind das zusammen:

    (n − 1) + (n − 2) + … + 1 = n · (n − 1) / 2

    Zahl der Elemente nZahl der Vergleiche n · (n − 1) / 2
    1045
    1004950
    1000499500

    Die Zahl der Vergleiche liegt in der Größenordnung von n². Bubblesort hat quadratische Laufzeit. Die Zahl der Vertauschungen kann im ungünstigsten Fall genauso groß werden. Das Telefonbuch aus Schritt 3 braucht 24 Vertauschungen.

    Die binäre Suche aus Abschnitt 8.4.1 braucht für tausend sortierte Einträge etwa zehn Vergleiche. Das Sortieren davor kostet mit Bubblesort fast eine halbe Million. Der Exkurs Wie die Laufzeit mit der Datenmenge wächst stellt beide Wachstumsarten nebeneinander.
