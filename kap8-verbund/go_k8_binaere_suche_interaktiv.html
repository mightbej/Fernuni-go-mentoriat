Binäre Suche in einem Verbund-Array

Ein Telefonbuch ist nach Namen sortiert. Die binäre Suche sieht in der Mitte nach und verwirft bei jedem Blick die Hälfte, in der der Name nicht stehen kann.

Kurstext v3.0.6, Abschnitt 8.4.1, Seiten 221–225.

Worum es geht

Am Ende von Abschnitt 8.1 wird eine Personalnummer in einem Array von Verbünden gesucht. Eine for-Schleife sieht dort jeden Eintrag von vorn an, bis sie den Namen findet. Bei tausend Einträgen sind das bis zu tausend Vergleiche.

Ein Telefonbuch ist nach Namen sortiert. In Abschnitt 8.4.1 wird gezeigt, wie ein Programm das ausnutzt. Die binäre Suche vergleicht den gesuchten Namen mit dem Namen in der Mitte. Danach steht fest, in welcher Hälfte der Name stehen muss, und die Suche geht nur dort weiter. Die Funktion dazu ruft sich selbst auf, sie ist rekursiv.

Schritt 1: Die Idee

Erst vorhersagen, dann ausprobieren
  1. Die Suche sieht zuerst am Index 4 nach, dort steht Koch. Gesucht ist Becker. Welche Einträge kommen danach noch in Frage?
    AuflösungNur die vier Einträge links von Koch, Arnold bis Huber. Becker kommt im Alphabet vor Koch. Koch selbst und alles rechts davon fallen weg.

Das Telefonbuch dieser Lektion hat zehn Einträge vom Typ person, sortiert nach dem Feld name. Es ist das Telefonbuch aus der Lektion zu Bubblesort, nachdem es sortiert ist.

type person struct {
    name          string
    telefonnummer int
}

telbuch := [10]person{{"Arnold", 3310}, {"Becker", 5522}, {"Fischer", 6398}, {"Huber", 4456}, {"Koch", 7745},
    {"Lange", 8127}, {"Meier", 4711}, {"Schulz", 1234}, {"Wagner", 9081}, {"Zimmer", 2063}}

Klicke einen Namen an, den die Suche finden soll. Drei Namen stehen nicht im Telefonbuch, sie haben eigene Knöpfe. Danach zeigt „nächster Blick“, wie die Suche den Bereich verkleinert.

Namen, die fehlen:

Grau und gestrichelt: Der Name kann dort nicht mehr stehen. Gelb: der Name in der Mitte, mit dem die Suche gerade vergleicht. Grün: gefunden. Ein blauer Rand markiert den gesuchten Namen.

So steht die Idee in Abschnitt 8.4.1: Die Suche vergleicht mit dem Namen in der Mitte. Ist der gesuchte Name alphabetisch kleiner, sucht sie in der ersten Hälfte weiter, sonst in der zweiten. Bei jedem Blick halbiert sich der Bereich, bis er einen Eintrag enthält. Stimmt dessen Name nicht, steht der Name nicht im Telefonbuch.

Die gleiche Strategie steht im Exkurs Von der Problemstellung zum Go-Programm zu Kapitel 3, Stufe 3, beim Zahlenraten. Wer dort immer die Mitte des Bereichs tippt, der noch möglich ist, verkleinert den Bereich bei jedem Tipp auf die Hälfte. Beim Zahlenraten sagt das Programm „zu klein“ oder „zu groß“. Hier sagt es der Vergleich mit dem Namen in der Mitte.

Schritt 2: Die Funktion

Erst vorhersagen, dann ausprobieren
  1. links ist 5, rechts ist 9. Welchen Wert bekommt mitte?
    Auflösung7. Die Rechnung lautet 5 + (9 − 5) / 2 = 5 + 2 = 7.

Die Idee aus Schritt 1 übergibt bei jedem Schritt die halbe Liste. Eine Kopie des halben Arrays wäre aufwendig. Die Funktion bekommt deshalb nur einen Zeiger auf das ganze Array und zwei Indizes, links und rechts. Sie grenzen den Bereich ein, der noch zu durchsuchen ist.

package main

const arrlen = 10 // Länge des Arrays

type person struct {
    name          string
    telefonnummer int
}

// Die rekursive Funktion sucht im Verbund-Array nach einem Element,
// dessen Feld name den Wert suchwert hat und gibt bei Erfolg
// den Wert des Felds telefonnummer dieses Elements zurück;
// ansonsten den Wert -1, wenn suchwert nicht gefunden wurde.
//
// Das Array muss aufsteigend sortiert sein und
// suchwert darf im Array höchstens einmal vorkommen.
//
// links und rechts sind die Grenzen des Suchbereichs,
// der beide Grenzen mit umfasst.
//
// Der initiale Aufruf erfolgt mit dem kompletten Array,
// also links=0 und rechts=arrlen-1.
func binSuche(personArr *[arrlen]person, links, rechts int,
    suchwert string) int {
    var ergebnis int
    // prüfen, ob Suchbereich zulässig ist
    if rechts >= links {
        // Mitte des Suchbereichs berechnen
        // (Index-Position im gesamten Array)
        mitte := links + (rechts-links)/2
        if personArr[mitte].name == suchwert {
            // suchwert gefunden
            ergebnis = personArr[mitte].telefonnummer
        } else {
            if personArr[mitte].name > suchwert {
                // Suche im linken Teilbereich fortsetzen
                ergebnis = binSuche(personArr, links, mitte-1,
                    suchwert)
            } else {
                // Suche im rechten Teilbereich fortsetzen
                ergebnis = binSuche(personArr, mitte+1, rechts,
                    suchwert)
            }
        }
    } else {

        ergebnis = -1 // suchwert nicht gefunden
    }
    return ergebnis
}

Listing 8.1, binSuche.go, aus dem Kurstext „Imperative Programmierung“ (Kurs 01613) der FernUniversität in Hagen, Abschnitt 8.4.1, Seite 224, unverändert übernommen.

  • Die Parameter: personArr ist ein Zeiger auf das Array. links und rechts sind der erste und der letzte Index des Suchbereichs, beide gehören dazu. suchwert ist der gesuchte Name.
  • Der erste Aufruf: Im Kurstext lautet er binSuche(&telbuch, 0, arrlen-1, "Müller"). Der Bereich umfasst das ganze Array, vom Index 0 bis zum Index 9.
  • rechts >= links: Diese Bedingung entscheidet, ob noch etwas zu durchsuchen ist. Ist rechts kleiner als links, ist der Bereich leer. Die Funktion ruft sich dann nicht mehr auf, die Rekursion bricht ab. Die Bedingung verhindert auch einen Zugriff auf einen Index außerhalb des Arrays.
  • mitte := links + (rechts-links)/2: Der Operator / teilt zwei ganze Zahlen ganzzahlig. Ist rechts - links ungerade, liegt kein Element genau in der Mitte. Die Division wählt dann das linke der zwei mittleren. Beispiel: Mit links 0 und rechts 9 ist mitte gleich 0 + 9 / 2 = 4.
  • Gefunden: Stimmt der Name am Index mitte, bekommt ergebnis dessen Telefonnummer.
  • Links weitersuchen: Ist der Name in der Mitte größer als suchwert, ruft sich die Funktion mit links und mitte-1 auf. Der Name in der Mitte ist schon verglichen und gehört nicht mehr zum Bereich.
  • Rechts weitersuchen: Sonst ruft sie sich mit mitte+1 und rechts auf.
  • return ergebnis: Jeder Aufruf gibt zurück, was sein eigener rekursiver Aufruf geliefert hat. So kommt die Telefonnummer oder −1 bis zum ersten Aufruf zurück. Der Wert −1 bedeutet „nicht gefunden“, denn eine Telefonnummer ist nie negativ.
Warum links + (rechts-links)/2 und nicht (links+rechts)/2? Beide Ausdrücke liefern hier den gleichen Wert. Im Kurstext steht keine Begründung für die erste Form. Sie hat einen Vorteil: Bei sehr großen Indizes kann die Summe links + rechts den Wertebereich des Typs überschreiten, die Differenz nicht. Wie ein solcher Überlauf aussieht, steht in Abschnitt 4.3.8.

Schritt 3: Aufruf für Aufruf

Erst vorhersagen, dann ausprobieren
  1. Gesucht ist Zuse. Der Name steht nicht im Telefonbuch und ist größer als alle Namen darin. Mit welchen Werten für links und rechts läuft der letzte Aufruf?
    Auflösunglinks ist 10 und rechts ist 9. Der Aufruf davor hat bei Zimmer am Index 9 verglichen und mit mitte+1 weitergesucht. Der Bereich ist leer, der Aufruf liefert −1.

In Abschnitt 8.4.1 werden sechs Fälle durchgespielt: Der Name steht vorn, hinten oder dazwischen, oder er fehlt und ist kleiner als alle, größer als alle oder liegt zwischen zwei Namen. Wähle einen Fall.

Jeder Aufruf von binSuche hat einen eigenen Rahmen mit seinen Variablen. In jedem Rahmen steht ein eigener Zeiger personArr mit der Adresse des Telefonbuchs. Das Telefonbuch selbst gibt es nur einmal, im Rahmen von main.

    Der Suchbereich des jüngsten Aufrufs

    Ausgabe

    Im Hauptspeicher stehen das Telefonbuch und von jedem Aufruf die drei Werte, die er übergeben bekommt: der Zeiger und die zwei Indizes. Kopiert wird nie ein Verbund.

    Schritt 4: Aufwand

    Erst vorhersagen, dann ausprobieren
    1. Ein Telefonbuch hat tausend Einträge. Mit wie vielen Namen vergleicht die binäre Suche höchstens?
      AuflösungMit zehn. 210 ist 1024. Tausend Einträge lassen sich also höchstens zehnmal halbieren.

    Jeder Vergleich mit der Mitte halbiert den Suchbereich mindestens. In Abschnitt 8.4.1 heißt es dazu: Ein Array mit 2n Elementen lässt sich nur n-mal halbieren. Die Suche von vorn aus Abschnitt 8.1 sieht dagegen im ungünstigsten Fall jeden Eintrag an.

    Deshalb reichen beim Zahlenraten im Exkurs Von der Problemstellung zum Go-Programm sieben Versuche für die Zahlen von 1 bis 100: 27 ist 128. Wer immer die Mitte tippt, gewinnt jede Runde.

    Zahl der EinträgeVergleiche mit der Mitte bei der binären Suche, höchstensVergleiche bei der Suche von vorn, höchstens
    10410
    1000101000
    1000000201000000

    Die Laufzeit der binären Suche ist logarithmisch. Die Suche muss das Array dafür nicht einmal ganz lesen. Der Exkurs Wie die Laufzeit mit der Datenmenge wächst stellt die Suche von vorn und die binäre Suche nebeneinander.

    Was die Suche voraussetzt

    • Sortiert: Das Array muss nach dem Feld sortiert sein, nach dem gesucht wird. Ist es das nicht, muss das Programm erst sortieren. Das zeigt die Lektion Bubblesort auf einem Verbund-Array zu Abschnitt 8.4.2. Sortieren kostet viel mehr als Suchen. Es lohnt sich, wenn ein Programm einmal sortiert und danach oft sucht.
    • Jeder Name einmal: Laut dem Kommentar über Listing 8.1 darf suchwert höchstens einmal im Array stehen.
    • Direkter Zugriff: Die Suche springt mit personArr[mitte] sofort an jeden Index. In einem Array geht das.

    Zum Weiterdenken

    Zu den Aufgaben gibt es hier keine Lösung.

    • Ohne Rekursion: Schreibe binSuche mit einer for-Schleife statt mit einem rekursiven Aufruf. Welche Variablen ändert die Schleife bei jedem Durchlauf?
    • Nach der Nummer suchen: Warum findet binSuche nicht den Namen zu einer bekannten Telefonnummer, auch wenn man den Vergleich auf das Feld telefonnummer umstellt?
    • Ein Name zweimal: Zwei Einträge heißen Meier. Was liefert binSuche dann, und ist es immer der erste der beiden?
