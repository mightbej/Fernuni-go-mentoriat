Vertiefung: Blockchain in Go

Eine Blockchain ist eine verkettete Liste mit zwei Änderungen: Ein neuer Block kommt immer vorn an und zeigt auf den älteren. Und jeder Block trägt den Fingerabdruck seines Vorgängers. Diese Lektion baut eine kleine Blockchain mit dem Stoff des Kurses in Go nach.

Vertiefung zur Lektion Blockchain: eine verkettete Liste mit Fingerabdruck. Exkurs zu Kapitel 9. Kurstext v3.0.6, Abschnitt 9.2, Seiten 229–236. Dazu Abschnitt 4.3.6, Seiten 66–68, und Abschnitt 4.3.8, Seiten 78–84.

Worum es geht

Diese Lektion ist die Vertiefung. Die leichte Fassung ist die Lektion Blockchain: eine verkettete Liste mit Fingerabdruck. Wer sie kennt, findet hier jede Funktion ausgeschrieben und Schritt für Schritt nachgerechnet.

Eine Blockchain ist ein Kassenbuch, das als Kopie auf vielen Rechnern zugleich liegt. Jeder Eintrag steht in einem Block, und die Blöcke sind miteinander verkettet. Bekannt wurde die Blockchain 2009 mit Bitcoin. Wie die echten Blockchains arbeiten und was mit ihnen heute geschieht, zeigt die Lektion Vom Eisenbahnzug in den Maschinenraum von Tether.

Diese Lektion zeigt, dass du den Kern einer Blockchain schon programmieren kannst. Sie ist eine verkettete Liste wie in Abschnitt 9.2 des Kurstexts, mit zwei Änderungen:

  • Die Richtung: Ein neuer Block kommt immer vorn an, und jeder Block zeigt auf den älteren Block. Im Bild des Güterzugs: Jeder neue Wagon kommt direkt hinter die Lokomotive, und jede Kupplung zeigt zum älteren Wagon.
  • Der Fingerabdruck: Jeder Block trägt einen Hashwert, der aus seinem Inhalt berechnet ist, und den Hashwert seines Vorgängers. Wer einen alten Block ändert, fällt auf.
Blockchain und Hashfunktion kommen im Kurstext nicht vor. In Abschnitt 4.3.8 wird die Hashfunktion nur in einem Satz als Beispiel genannt. Diese Lektion ist ein Exkurs des Mentors. Das Programm ist ein Modell: kein echtes Geld und keine echte Blockchain.

Die Schritte

  • Schritt 1: Du hängst vier Blöcke an eine leere Kette. Jeder neue Block kommt vorn an.
  • Schritt 2: Eine Hashfunktion mit 32 Bit, XOR und gewolltem Überlauf. Du gibst einen Text ein und siehst die Rechnung.
  • Schritt 3: Jeder Block trägt den Hashwert seines Vorgängers. Du fälschst einen alten Block und siehst, wo die Prüfung anschlägt.
  • Schritt 4: Guthaben im Typ uint64 und was bei 75 − 76 geschieht.
  • Schritt 5: Du überweist zwischen drei Konten. Jede Buchung wird ein Block.
  • Schritt 6: Der Herausgeber sperrt Konten, vernichtet Guthaben und hält die Kette an.

Das ganze Programm liegt als blockchain.go bereit. Es läuft mit go run blockchain.go.

Schritt 1: Der umgedrehte Güterzug

Erst vorhersagen, dann ausprobieren
  1. Im Güterzug des Kurstexts kommt ein neuer Wagon an die Stelle, die zu seiner Containernummer passt. In eine Blockchain wird nie etwas in der Mitte eingefügt, ein neuer Block kommt immer ganz vorn an. Welcher Fall der Funktion elementEinfügen aus Listing 9.1 ist das?
    AuflösungDer erste Fall: Das neue Element wird der Kopf der Liste. Er braucht zwei Zuweisungen. Erst bekommt das neue Element den alten Kopf als Nachfolger, dann zeigt der Kopf auf das neue Element.

Im Güterzug des Kurstexts zeigt die Lokomotive auf den ersten Wagon und jeder Wagon auf den nächsten. Die Reihenfolge ergibt sich aus den Containernummern.

In einer Blockchain ergibt sich die Reihenfolge aus der Zeit. Jeder neue Block kommt direkt hinter die Lokomotive, und seine Kupplung zeigt auf den Block, der vorher dort stand. So zeigt jeder Block auf einen älteren Block. Wer vom Kopf aus durch die Kette läuft, geht in der Zeit zurück bis zum ersten Block. Dessen Zeiger ist nil. Den ersten Block nennt man in echten Blockchains den Genesis-Block.

Die zwei Verbund-Typen sehen aus wie die der Liste. Nur heißt der Zeiger vorgänger statt nächstes:

// Ein Block der Kette
type block struct {
    nummer    int
    vorgänger *block
}

// Die Kette. kopf zeigt auf den neuesten Block.
type blockkette struct {
    kopf *block
}

Blockchain: ein Block kommt vorn an

func blockAnhängen(k *blockkette) {

    Schritt 2: Der Fingerabdruck

    Erst vorhersagen, dann ausprobieren
    1. Die Texte „Alice an Bob: 25“ und „Alice an Bob: 5“ unterscheiden sich in einem Zeichen. Wie ähnlich sind ihre Hashwerte?
      AuflösungSie haben nichts gemeinsam: 4e3c6e66 und cd11eb3e. Schon ein geändertes Byte mischt sich über die Multiplikation in alle Bits.

    Eine Hashfunktion berechnet aus einem beliebig langen Text eine Zahl mit fester Zahl von Bits, den Hashwert. Man nennt ihn auch Fingerabdruck. Zwei Eigenschaften braucht die Blockchain:

    • Gleicher Text, gleicher Wert: Jeder Rechner berechnet aus demselben Text denselben Hashwert.
    • Anderer Text, anderer Wert: Ändert sich ein einziges Zeichen, ändert sich der ganze Hashwert.

    Die Hashfunktion dieser Lektion heißt FNV-1a. Sie braucht nur Stoff aus Kapitel 4:

    // fingerabdruckText berechnet aus einem Text einen Hashwert mit 32 Bit.
// Das Verfahren heißt FNV-1a. Der Überlauf bei der Multiplikation ist gewollt.
func fingerabdruckText(text string) uint32 {
    var h uint32 = 2166136261
    for i := 0; i < len(text); i++ {
        h = h ^ uint32(text[i]) // das Byte mit XOR einmischen
        h = h * 16777619        // Überlauf: Go rechnet modulo 2^32
    }
    return h
}
    • uint32: Ein Hashwert ist ein Bitmuster und keine Menge. Für Bitmuster sind die vorzeichenlosen Typen da, so steht es in Abschnitt 4.3.6.
    • text[i]: Der Index-Ausdruck liefert ein Byte, Abschnitt 4.6. Ein Umlaut wie „ü“ besteht aus zwei Bytes.
    • ^: XOR aus Abschnitt 4.3.7.2. Jedes Bit von h, an dessen Stelle das Byte eine 1 hat, kippt.
    • * 16777619: Das Produkt braucht bis zu 57 Bit. Go behält die unteren 32 und verwirft den Rest. In Abschnitt 4.3.8 steht, dass man diesen Überlauf bei einer Hashfunktion bewusst einsetzt: Das Ergebnis landet immer im Wertebereich.

    Die Rechnung Byte für Byte

    Die Texte, die später in die Blöcke kommen, sind Einträge eines Kassenbuchs. In dieser Lektion haben drei Personen ein Konto: Alice, Bob und Charlie. Bezahlt wird in Coins, der Geldeinheit des Modells. Der Eintrag „Alice an Bob: 25“ heißt also: Alice überweist Bob 25 Coins. Die Hashfunktion kennt diese Bedeutung nicht. Für sie ist jeder Eintrag nur eine Folge von Bytes.

    Wähle einen Text oder schreibe einen eigenen, höchstens 40 Bytes lang. So liest du die Tabelle:

    • Eine Zeile ist ein Durchlauf der Schleife, also ein Byte des Textes.
    • Byte: der Wert von text[i] als Zahl, in Klammern das Zeichen.
    • h nach XOR: der Wert von h nach der ersten Anweisung im Rumpf.
    • Produkt ohne Grenze: was die Multiplikation in der Mathematik ergäbe. Die Zahl hat bis zu 17 Stellen und passt nicht in 32 Bit.
    • h neu: was Go davon behält, die unteren 32 Bit. Mit diesem Wert beginnt die nächste Zeile.

    Der Wert von h in der letzten Zeile ist der Hashwert. Alle Werte von h stehen hexadezimal, wie fmt.Printf sie mit %08x ausgibt.

    32 Bit sind zu wenig. Es gibt nur rund 4,3 Milliarden verschiedene Werte vom Typ uint32. Ein Programm, das der Reihe nach „Alice an Bob: 26“, „Alice an Bob: 27“ und so weiter durchrechnet, findet einen zweiten Text mit dem Hashwert von „Alice an Bob: 25“. Auf einem gewöhnlichen Rechner hat ein Go-Programm dafür knapp zehn Minuten gebraucht. Es fand „Alice an Bob: 9403879403“, die letzte Vorlage oben. Beide Texte haben den Hashwert 4e3c6e66. Echte Blockchains verwenden deshalb Hashfunktionen mit 256 Bit, Bitcoin zum Beispiel SHA-256. In Go gibt es dafür das Paket crypto/sha256. Es verlangt den Text als Slice, und Slices verwendet der Kurs nicht.

    Schritt 3: Hash statt Zeiger

    Erst vorhersagen, dann ausprobieren
    1. Die Kette liegt als Kopie auf tausend Rechnern. Auf einem Rechner liegt Block 1 ab Zelle 248, auf einem anderen ab einer ganz anderen Adresse. Wie kann Block 2 seinen Vorgänger so benennen, dass es auf jedem Rechner gilt?
      AuflösungMit dem Hashwert des Vorgängers. Den berechnet jeder Rechner aus demselben Inhalt gleich. Eine Adresse gilt nur in einem laufenden Programm auf einem Rechner.

    Der Zeiger vorgänger genügt dem Programm auf einem Rechner. Für die anderen Rechner trägt jeder Block zusätzlich zwei Hashwerte:

    // Ein Block der Kette. Er kennt seinen Vorgänger auf zwei Arten:
// über den Zeiger vorgänger und über dessen Hashwert vorgängerHash.
type block struct {
    nummer        int
    eintrag       string
    vorgängerHash uint32
    hash          uint32
    vorgänger     *block
}
    • eintrag: Was im Kassenbuch steht, zum Beispiel „Alice an Bob: 25“.
    • vorgängerHash: Der Hashwert des Vorgängers. Beim ersten Block ist er 0.
    • hash: Der eigene Hashwert. Er wird aus Nummer, Eintrag und vorgängerHash berechnet. So hängt er auch vom Vorgänger ab, und über den Vorgänger von allen älteren Blöcken.
    // fingerabdruck berechnet den Hashwert eines Blocks aus seiner Nummer,
// seinem Eintrag und dem Hashwert seines Vorgängers.
func fingerabdruck(b *block) uint32 {
    text := fmt.Sprintf("%d|%s|%08x", b.nummer, b.eintrag, b.vorgängerHash)
    return fingerabdruckText(text)
}

// blockAnhängen hängt einen neuen Block vorn an die Kette.
func blockAnhängen(k *blockkette, eintrag string) {
    neuer := &block{eintrag: eintrag}
    if k.kopf != nil {
        neuer.nummer = k.kopf.nummer + 1
        neuer.vorgängerHash = k.kopf.hash
    }
    neuer.hash = fingerabdruck(neuer)
    neuer.vorgänger = k.kopf
    k.kopf = neuer
}

// ketteGültig prüft jeden Block, vom neuesten bis zum ersten.
func ketteGültig(k *blockkette) bool {
    for b := k.kopf; b != nil; b = b.vorgänger {
        if b.hash != fingerabdruck(b) {
            return false
        }
        if b.vorgänger != nil && b.vorgängerHash != b.vorgänger.hash {
            return false
        }
    }
    return true
}

    fmt.Sprintf arbeitet wie fmt.Printf aus Abschnitt 4.2, gibt den Text aber zurück, statt ihn auszugeben. Für Block 2 entsteht der Text 2|Alice an Bob: 25|2b2ae705.

    Einen alten Block fälschen

    Die Kette hat vier Blöcke. Das Bild zeichnet sie wie die Liste in Listing 9.1: vorn kopf, dahinter der neueste Block 3, ganz hinten Block 0 mit nil. Jeder Pfeil ist ein Zeiger vorgänger. Im Feld vorgängerHash steht deshalb der Hashwert des Blocks rechts daneben. Unter dem Feld steht auf jeder Karte, von welchem Block der Wert stammt.

    Alice hat Bob in Block 2 25 Coins überwiesen. Nun will sie nachträglich nur 5 Coins überwiesen haben. Wähle, wie weit sie mit dem Fälschen geht. Gelb ist ein geändertes Feld, rot ein Feld, an dem die Prüfung anschlägt.

    Bei Bitcoin kommt eine Hürde hinzu: Für jeden Block muss ein Rechner eine teure Rechenaufgabe lösen. Wer einen alten Block fälscht, müsste das für ihn und für jeden späteren Block wiederholen, schneller als alle anderen Rechner zusammen. Dieses Verfahren heißt Proof of Work. Die Lektion zeigt es nicht.

    Die Adressen sind erfunden.

    Schritt 4: Guthaben ohne Vorzeichen

    Erst vorhersagen, dann ausprobieren
    1. Alice hat 75 Coins, gespeichert als uint64. Ein Programm zieht 76 ab, ohne vorher zu prüfen. Was steht danach im Guthaben?
      Auflösung18446744073709551615, die größte Zahl des Typs uint64. Alice ist auf einen Schlag sehr reich, und Go meldet nichts.

    Ein Guthaben kann nicht negativ sein. Es liegt nahe, dafür einen vorzeichenlosen Typ zu nehmen. Davor wird im Kurstext in Hinweis 4.7 gewarnt: Ein Rechenfehler, der eine negative Zahl ergäbe, schwappt unbemerkt an das obere Ende des Wertebereichs. Das Beispiel dort ist 10 − 15 im Typ uint8, Ergebnis 251. Den Sprung über die Null siehst du am Zahlenkreis, Schritt 3.

    Blockchains tun es trotzdem. Verträge in der Sprache Solidity für Ethereum speichern Guthaben meist im Typ uint256. Deshalb muss jedes Programm prüfen, bevor es abzieht. Das Programm dieser Lektion verwendet uint64 und prüft so:

    if betrag > sender.guthaben {
    return false, "das Guthaben reicht nicht"
}
sender.guthaben = sender.guthaben - betrag

    Beim Ausgeben neuer Coins wächst ein Guthaben. Auch eine Summe kann überlaufen. Die Funktion ausgeben prüft deshalb vor der Addition:

    if empfänger.guthaben+betrag < empfänger.guthaben {
    return false, "Überlauf verhindert"
}

    Ist die Summe kleiner als der alte Wert, ist sie übergelaufen. Bei vorzeichenlosen Typen ist diese Prüfung sicher, weil Go modulo 2^64 rechnet. Am Ende von Abschnitt 4.3.8 steht, dass man vor einer gefährdeten Addition prüfen sollte, ob das Ergebnis im Wertebereich liegt.

    Schritt 5: Überweisen

    Erst vorhersagen, dann ausprobieren
    1. Bob hat 45 Coins und überweist 50 an Charlie. Was ändert sich an den Konten, und was an der Kette?
      AuflösungNichts. überweisen gibt false zurück, bevor es etwas bucht. Ein Block entsteht nur bei einer Buchung.

    Die Konten liegen in einem Array von Verbünden, wie das Telefonbuch in der Programmierübung zu Kapitel 8. Die Kette bekommt dafür drei neue Felder:

    // Ein Konto mit Namen, Guthaben und Sperrvermerk
type konto struct {
    name     string
    guthaben uint64
    gesperrt bool
}

// Die Blockkette mit den Konten. kopf zeigt auf den neuesten Block.
type blockkette struct {
    kopf        *block
    konten      [3]konto
    herausgeber string
    angehalten  bool
}

// kontoSuchen liefert einen Zeiger auf das Konto mit dem Namen oder nil.
func kontoSuchen(k *blockkette, name string) *konto {
    for i := 0; i < len(k.konten); i++ {
        if k.konten[i].name == name {
            return &k.konten[i]
        }
    }
    return nil
}

    &k.konten[i] ist die Adresse eines Array-Elements. In Abschnitt 7.4 steht, dass ein Element eines Arrays adressierbar ist. Über den Zeiger ändert überweisen das Konto im Array selbst und keine Kopie.

    Die Funktion überweisen prüft erst alle Regeln und bucht dann. Sie gibt zwei Werte zurück: ob gebucht wurde, und eine Meldung. Gelb ist die Zeile, mit der der letzte Aufruf geendet hat.

      Schritt 6: Wer darf sperren?

      Erst vorhersagen, dann ausprobieren
      1. Der Herausgeber sperrt Alice. Läuft die Kette weiter? Und kann Alice noch überweisen?
        AuflösungDie Kette läuft weiter, die Sperre steht sogar als eigener Block darin. Alice kann nichts mehr überweisen, weil überweisen vorher sender.gesperrt prüft.

      Die Kette hat einen Herausgeber. Nur er darf neue Coins ausgeben. Das Programm gibt ihm drei weitere Rechte:

      // sperren sperrt ein Konto. Das darf nur der Herausgeber.
func sperren(k *blockkette, aufrufer string, name string) (bool, string) {
    if aufrufer != k.herausgeber {
        return false, "das darf nur der Herausgeber"
    }
    betroffen := kontoSuchen(k, name)
    if betroffen == nil {
        return false, "unbekanntes Konto"
    }
    betroffen.gesperrt = true
    blockAnhängen(k, k.herausgeber+" sperrt "+name)
    return true, "gesperrt"
}

// vernichten setzt das Guthaben eines gesperrten Kontos auf 0.
// Das darf nur der Herausgeber.
func vernichten(k *blockkette, aufrufer string, name string) (bool, string) {
    if aufrufer != k.herausgeber {
        return false, "das darf nur der Herausgeber"
    }
    betroffen := kontoSuchen(k, name)
    if betroffen == nil {
        return false, "unbekanntes Konto"
    }
    if !betroffen.gesperrt {
        return false, name + " ist nicht gesperrt"
    }
    betrag := betroffen.guthaben
    betroffen.guthaben = 0
    blockAnhängen(k, fmt.Sprintf("%s vernichtet %d von %s", k.herausgeber, betrag, name))
    return true, "vernichtet"
}

      Die Funktion anhalten setzt k.angehalten auf true. Danach lehnt überweisen jede Überweisung ab. Auch sie prüft zuerst den Aufrufer.

      Im Modell kann jeder Aufruf „Herausgeber“ als Aufrufer angeben. In einer echten Blockchain belegt eine digitale Signatur, wer eine Funktion aufruft. Fälschen lässt sie sich ohne den geheimen Schlüssel nicht.
