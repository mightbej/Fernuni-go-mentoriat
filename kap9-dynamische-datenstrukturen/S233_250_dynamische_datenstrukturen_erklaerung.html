Kapitel 9 · Dynamische Datenstrukturen

Erklärseite zu S233-250

Diese Seite ordnet Kapitel 9 ein: Warum dynamische Datenstrukturen wichtig sind, wie Listen arbeiten und weshalb Suchbäume effizient sein können.

Worum geht es in diesem Kapitel?

Der Studienbrief zeigt zuerst die Grenze sortierter Arrays: Einfügen kostet oft viele Verschiebungen. Danach folgen verkettete Listen und binäre Bäume als flexiblere Alternativen. Kernidee: Strukturen sollen sich zur Laufzeit anpassen, ohne große Datenblöcke laufend umzuschreiben.

Motivation

Ein neuer Eintrag mitten in einem sortierten Array kann viele Verschiebungen auslösen.

Ziel

Mit Zeigern und Knotenstrukturen lassen sich Einfügen, Suchen und Löschen oft flexibler und verständlicher modellieren.

Wichtiges Prinzip

Nur die Verknüpfungen ändern sich, nicht unbedingt alle Daten selbst.

9.1 Motivation: Warum Arrays an Grenzen stoßen

Ein sortiertes Array muss beim Einfügen in der Mitte viele Elemente verschieben. Dynamische Strukturen sollen genau diesen Aufwand reduzieren.

Problem im Array
  • Einfügen an der richtigen Stelle verschiebt viele Elemente.
  • Das funktioniert nur, wenn im Array noch Platz vorhanden ist.
  • Im Mittel wandert etwa die Hälfte der Daten.
Idee der Alternativen
  • Weniger Daten verschieben, mehr Verknüpfungen ändern.
  • Die eigentlichen Inhalte bleiben an Ort und Stelle.
  • Nur Verweise auf die nächsten Elemente werden umgehängt.
Sortiertes Array: - beim Einfügen oft viele Verschiebungen - abhängig von freiem Platz Dynamische Struktur: - Knoten bleiben bestehen - Zeiger werden neu gesetzt - Einfügen wird lokalisiert statt global
Kernaussage: Zeiger und Knoten liefern eine deutlich flexiblere Datenorganisation als ein starr belegtes Array.

9.2 Verkettete Listen

Die Liste ist eine Kette von Elementen. Jedes Element enthält einen Wert und einen Zeiger auf den Nachfolger. Das letzte Element zeigt auf nil.

Was passiert hier?
  • Die Liste wird beim Einfügen an der passenden Stelle aufgeschnitten.
  • Ein neuer Knoten wird erzeugt.
  • Zeiger werden so umgebogen, dass die Reihenfolge erhalten bleibt.
  • Die Liste bleibt aufsteigend sortiert.
Welche Konzepte werden benutzt?
  • Verbund-Typ für einen Knoten.
  • Zeiger auf den Nachfolger.
  • Zeiger auf den Kopf der Liste.
  • Rekursive oder iterative Traversierung.
type listenElement struct { wert int nächstes *listenElement } type sortierteListe struct { kopf *listenElement } Einfügen bedeutet: - richtige Position suchen - neues Element erzeugen - Zeiger neu verbinden
Warum das gut ist: Werte bleiben stehen, nur Verknüpfungen werden geändert.

Was passiert hier?
  • Benachbarte Elemente werden verglichen.
  • Bei falscher Reihenfolge werden sie vertauscht.
  • Ein Durchlauf ordnet jeweils das größte Element nach hinten ein.
  • Eine optimierte Version bricht ab, wenn nichts mehr vertauscht wird.
Welche Konzepte werden benutzt?
  • Array von Verbünden.
  • Vergleich nach einem Feldwert wie dem Namen.
  • Zähler für Vergleiche und Vertauschungen.
  • Optimierung durch Early Exit.
Bubblesort auf Person-Verbünden: - Vergleich benachbarter Einträge - Vertauschung bei falscher Reihenfolge - Anzahl Vergleiche wächst quadratisch Optimierung: - Wenn kein Tausch stattfindet, ist das Array fertig sortiert.

9.3 Binäre Bäume und Suchbäume

Danach folgen Bäume. Ein Knoten hat bis zu zwei Nachfolger. Für Suchbäume gilt: links liegen kleinere, rechts größere Werte.

Was passiert hier?
  • Binäre Bäume haben höchstens zwei Kinder pro Knoten.
  • Binäre Suchbäume ordnen kleinere Werte links und größere rechts an.
  • Das Suchen folgt rekursiv dem passenden Teilbaum.
  • Einfügen und Suchen sind bei balancierten Bäumen effizient.
Welche Konzepte werden benutzt?
  • Rekursive Datenstruktur.
  • Knoten mit links/rechts-Zeigern.
  • In-Order-Ausgabe für sortierte Reihenfolge.
  • Suchzeit grob in O(log n) bei guter Balance.
Binärer Suchbaum: - Wurzel - linker Teilbaum: kleinere Werte - rechter Teilbaum: größere Werte Suchen: - Vergleich an der Wurzel - dann links oder rechts weiter - nil bedeutet: Wert nicht vorhanden
Wichtige Idee: Die Ordnung steckt nicht in einer Liste, sondern in der Baumstruktur selbst.

Warum diese Kapitelhälfte zusammengehört

Thema Grundgedanke
Sortierte Arrays Einfügen ist teuer, weil viele Elemente verschoben werden müssen.
Verkettete Listen Einfügen passiert lokal über Zeiger, nicht durch Massenverschiebung.
Binäre Bäume Ordnung wird durch Verzweigungen gespeichert, Suche und Einfügen werden rekursiv.
Bubblesort Zeigt einen klassischen Algorithmus auf einem Array von Verbünden.
