Blockchain: eine verkettete Liste mit Fingerabdruck

Hinter Bitcoin steckt eine Datenstruktur, die du aus Kapitel 9 kennst: eine verkettete Liste. Dazu kommen ein Fingerabdruck für jeden Block und Guthaben in einem vorzeichenlosen Typ aus Kapitel 4.

Exkurs zu Kapitel 9. Kurstext v3.0.6, Abschnitt 9.2, Seiten 229–236, und Abschnitt 4.3.6, Seiten 66–68.

Worum es geht

Eine Bank führt für jedes Konto ein Kassenbuch: Wer hat wem wie viel überwiesen? Bei Bitcoin gibt es keine Bank. Das Kassenbuch liegt als Kopie auf vielen tausend Rechnern zugleich. Dieses gemeinsame Kassenbuch heißt Blockchain, auf Deutsch Kette von Blöcken. Bitcoin gibt es seit 2009.

In dieser Lektion baust du ein kleines Modell davon. Drei Personen haben ein Konto: Alice, Bob und Charlie. Bezahlt wird in Coins, der Geldeinheit des Modells. Ein Eintrag im Kassenbuch lautet zum Beispiel „Alice an Bob: 25“: Alice überweist Bob 25 Coins.

Was du aus dem Kurs schon kennst

  • Die verkettete Liste, Abschnitt 9.2: Die Einträge stehen in Blöcken, und jeder Block zeigt mit einem Zeiger auf den Block davor. Die Lektion Verkettete Listen in Go.
  • Vorzeichenlose Typen, Abschnitt 4.3.6: Guthaben stehen in einem Typ wie uint64. Die Lektion Zahlenkreis.

Die Schritte

  • Schritt 1: Blöcke werden zu einer Kette verbunden, wie die Wagons des Güterzugs im Kurstext.
  • Schritt 2: Jeder Block bekommt einen Fingerabdruck. Damit fällt auf, wenn jemand einen alten Eintrag ändert.
  • Schritt 3: Guthaben als uint64, und was bei 75 − 76 geschieht.
  • Schritt 4: Überweisungen und Sperren als Funktionen mit if.
Blockchain und Fingerabdruck kommen im Kurstext nicht vor. Diese Lektion ist ein Exkurs des Mentors. Wer jede Funktion ausgeschrieben und nachgerechnet sehen will, findet sie in der Vertiefung. Wie echte Programme auf einer Blockchain aussehen, zeigt die Lektion Vom Eisenbahnzug in den Maschinenraum von Tether.

Schritt 1: Eine Kette von Blöcken

Erst vorhersagen, dann ausprobieren
  1. Die Kette hat einen Zeiger kopf auf den neuesten Block. Ein neuer Block soll dazukommen und auf den bisher neuesten zeigen. Welche zwei Zuweisungen braucht das? Tipp: der erste Fall von elementEinfügen in Listing 9.1.
    AuflösungErst neuer.vorgänger = k.kopf, dann k.kopf = neuer. In umgekehrter Reihenfolge ginge die Adresse des bisher neuesten Blocks verloren.

Im Güterzug des Kurstexts hängt jeder Wagon mit einer Kupplung am nächsten. Eine Blockchain ist genauso gebaut, mit einem Unterschied: Ein neuer Block kommt immer ans Ende der Zeit, eingefügt wird nie in der Mitte. Seine Kupplung zeigt auf den Block, der vor ihm kam, seinen Vorgänger. Der erste Block hat keinen Vorgänger, sein Zeiger ist nil.

type block struct {
    eintrag   string // zum Beispiel "Alice an Bob: 25"
    vorgänger *block
}

type blockkette struct {
    kopf *block // der neueste Block
}

Blöcke anhängen

Hänge nacheinander vier Einträge an. Das Bild zeichnet die Kette wie die Liste in der Lektion zu Kapitel 9: vorn kopf, direkt dahinter der neueste Block, ganz hinten der älteste mit nil. Jeder Pfeil ist ein Zeiger vorgänger. Ein neuer Block schiebt sich also immer zwischen kopf und den bisher neuesten Block.

Wie die Blöcke im Hauptspeicher liegen, zeigt die Vertiefung, Schritt 1.

Kurstext v3.0.6, Abschnitt 9.2, Seiten 229–236: Güterzug und Listing 9.1. Die Typen sind eigene Beispiele, geprüft mit Go 1.26.

Schritt 2: Der Fingerabdruck

Erst vorhersagen, dann ausprobieren
  1. Die Kette liegt auf vielen tausend Rechnern. Kann ein Block seinen Vorgänger dort mit einer Speicheradresse benennen?
    AuflösungNein. Eine Adresse gilt nur im laufenden Programm auf einem Rechner. Auf einem anderen Rechner liegt der Block an einer anderen Stelle.

Jeder Block bekommt deshalb einen Fingerabdruck: eine Zahl, die ein Programm aus dem Eintrag berechnet. Fachleute sagen Hashwert. Er hat zwei Eigenschaften:

  • Gleicher Eintrag, gleiche Zahl: Jeder Rechner berechnet aus dem gleichen Eintrag den gleichen Hashwert.
  • Ein Zeichen anders, ganz andere Zahl: Die zwei Hashwerte haben nichts mehr gemeinsam.

Die Hashfunktion des Modells rechnet mit dem Typ uint32 und lässt den Überlauf bewusst zu. Im Kurstext steht in Abschnitt 4.3.8, dass man das bei einer Hashfunktion so macht. Die Hashwerte stehen hexadezimal da, mit acht Ziffern.

Wähle einen Eintrag:

Ein Block merkt sich den Fingerabdruck seines Vorgängers

Jeder Block trägt zwei Hashwerte: seinen eigenen in hash und den seines Vorgängers in vorgängerHash. Der eigene Hashwert wird aus dem Eintrag und aus vorgängerHash berechnet.

Die Kette unten hat vier Blöcke, vorn kopf und der neueste Block 3, ganz hinten Block 0. Unter vorgängerHash steht auf jeder Karte, von welchem Block der Wert stammt. Alice hat Bob in Block 2 25 Coins überwiesen. Später ändert sie den Eintrag und behauptet, es seien nur 5 gewesen. Gelb ist ihre Änderung, rot die Stelle, an der die Fälschung auffällt.

Die Rechnung der Hashfunktion Byte für Byte und weitere Stufen der Fälschung zeigt die Vertiefung, Schritt 2 und 3.

Kurstext v3.0.6, Abschnitt 4.3.8, Seiten 78–84. Die Hashfunktion heißt FNV-1a, alle Hashwerte sind mit Go 1.26 berechnet.

Schritt 3: Guthaben als uint

Erst vorhersagen, dann ausprobieren
  1. Alice hat 75 Coins im Typ uint64. Ein Programm zieht 76 ab, ohne vorher zu prüfen. Was steht danach im Guthaben?
    Auflösung18446744073709551615, die größte Zahl des Typs uint64. Go meldet nichts.

Ein Guthaben kann nicht negativ sein. Deshalb liegt es nahe, einen vorzeichenlosen Typ zu nehmen:

type konto struct {
    name     string
    guthaben uint64
    gesperrt bool
}

Genau davor wird im Kurstext in Hinweis 4.7 gewarnt: Ergibt eine Rechnung eine negative Zahl, springt der Wert unbemerkt an das obere Ende des Wertebereichs. Diesen Sprung über die Null zeigt der Zahlenkreis, Schritt 3.

Echte Blockchains verwenden trotzdem vorzeichenlose Typen, oft sogar mit 256 Bit. Darum muss jedes Programm prüfen, bevor es abzieht.

Abziehen mit und ohne Prüfung

Alice hat 75 Coins. Wähle den Betrag.

Ohne Prüfung

guthaben = guthaben - betrag

Mit Prüfung

if betrag > guthaben {
    // ablehnen
} else {
    guthaben = guthaben - betrag
}

Kurstext v3.0.6, Abschnitt 4.3.6, Hinweis 4.7, Seiten 66–68, und Abschnitt 4.3.8, Seiten 78–84. Die Werte sind mit Go 1.26 geprüft.

Schritt 4: Regeln als Programm

Erst vorhersagen, dann ausprobieren
  1. Alice ist gesperrt und will Bob 10 Coins überweisen. Was muss die Funktion überweisen prüfen, bevor sie bucht?
    AuflösungOb der Absender gesperrt ist, und ob sein Guthaben reicht. Erst wenn beide Prüfungen bestanden sind, bucht sie und hängt einen Block an.

Die Regeln des Kassenbuchs sind Funktionen mit if. Eine Überweisung prüft erst und bucht dann:

func überweisen(k *blockkette, von *konto, an *konto, betrag uint64) bool {
    if von.gesperrt {
        return false
    }
    if betrag > von.guthaben {
        return false
    }
    von.guthaben = von.guthaben - betrag
    an.guthaben = an.guthaben + betrag
    blockAnhängen(k, fmt.Sprintf("%s an %s: %d", von.name, an.name, betrag))
    return true
}

Wer darf ein Konto sperren? In diesem Modell nur der Herausgeber, also die Stelle, die die Coins ausgegeben hat. Die Sperre landet als eigener Block in der Kette. Jeder kann sie also sehen, aufheben kann sie niemand außer dem Herausgeber.

Ausprobieren

Am Anfang hat Alice 75 Coins, Bob 45 und Charlie 10.

Was das Modell zeigt

Die Kette ist technisch in Ordnung, und trotzdem entscheidet eine einzige Stelle, wer zahlen darf. Genau solche Funktionen stehen im Programm des digitalen Dollars USDT. Du liest sie in der Lektion Vom Eisenbahnzug in den Maschinenraum von Tether.
