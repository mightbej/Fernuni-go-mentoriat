Rekursion in Go

Eine Funktion, die sich selbst aufruft, heißt rekursiv. Die Seite führt die rekursiven Funktionen des Kurstexts Aufruf für Aufruf aus: Fakultät, Fibonacci-Zahlen und die Türme von Hanoi.

Kurstext v3.0.6, Abschnitt 7.5, Seiten 185–193.

Worum es geht

Funktionen lagern eine Berechnung aus. Ein Programm verwendet sie aus zwei Gründen: Es braucht die gleiche Berechnung an mehreren Stellen, und es wird durch Funktionen übersichtlich.

Eine Funktion darf andere Funktionen aufrufen, und sie darf sich selbst aufrufen. Ruft eine Funktion in ihrem Rumpf sich selbst auf, heißt das direkte Rekursion. Rekursion gliedert das Problem und weniger das Programm: Die Funktion führt eine Aufgabe auf eine kleinere Aufgabe der gleichen Art zurück.

Schritt 1: Iterativ und rekursiv

Erst vorhersagen, dann ausprobieren
  1. Die Funktion fakultätRek ruft für n größer als 1 sich selbst mit n-1 auf. Wie oft läuft die Funktion beim Aufruf fakultätRek(4) insgesamt?
    AuflösungViermal: mit den Argumenten 4, 3, 2 und 1.

Die Fakultät n! einer natürlichen Zahl n ≥ 1 hat zwei Definitionen:

  • Als Produkt: n! = 1 · 2 · 3 · … · n
  • Rekursiv: 1! = 1 und (n + 1)! = (n + 1) · n!

Iterativ

Aus der ersten Definition wird eine Schleife. Die Variable fac beginnt mit 1 und wird nacheinander mit 2, 3, … n multipliziert. Eine Funktion ohne Selbstaufruf heißt iterativ.

func fakultätIte(n int) int {
    fac := 1
    for i := 2; i <= n; i++ {
        fac = fac * i
    }
    return fac
}

Rekursiv

Aus der zweiten Definition wird eine Funktion, die sich selbst aufruft. Sie hat zwei Zweige:

  • Der kleinste Wert: Für n gleich 1 liefert sie 1 und ruft sich nicht mehr auf.
  • Alle anderen Werte: Sie ruft sich mit dem Argument n-1 auf und multipliziert das Ergebnis mit n.

    Ausgabe

    Jeder Aufruf hat einen eigenen Rahmen mit einem eigenen n. Ein Aufruf, der auf das Ergebnis eines anderen wartet, bleibt stehen. Sein n muss so lange gespeichert bleiben.

    Was gegen dieses Beispiel spricht

    • Speicher: Die rekursive Funktion hat keine Variablen i und fac. Sie spart trotzdem keinen Speicher, denn für jeden wartenden Aufruf bleibt ein Wert von n gespeichert.
    • Tabelle: Eine Funktion für die Fakultät nimmt man in der Praxis aus einer Tabelle. Die Werte wachsen so schnell, dass nur wenige in einen Ganzzahltyp passen.

    Schritt 2: Endrekursion

    Erst vorhersagen, dann ausprobieren
    1. In fakultätRek steht return n * fakultätRek(n-1). Was muss der Aufruf noch tun, nachdem der rekursive Aufruf sein Ergebnis geliefert hat?
      AuflösungEr muss das Ergebnis mit n multiplizieren. Der rekursive Aufruf ist dort also nicht die letzte Operation.

    Eine Funktion ist endrekursiv, englisch tail recursion, wenn zwei Bedingungen erfüllt sind:

    • Ein Aufruf ruft die Funktion höchstens einmal rekursiv auf.
    • Dieser rekursive Aufruf ist die letzte Operation des Aufrufs.

    Nach dem rekursiven Aufruf ist dann nichts mehr zu tun. Der Aufrufer gibt das Ergebnis unverändert weiter und braucht dafür keinen seiner Werte mehr. Dafür muss der letzte Aufruf das fertige Ergebnis schon in der Hand haben.

    Die endrekursive Fakultät braucht eine Hilfsfunktion iter mit zwei Parametern: k zählt herunter, e trägt das Zwischenergebnis. Jeder Aufruf multipliziert erst k in das Zwischenergebnis und ruft dann iter mit k-1 auf.

      Ausgabe

      Der Unterschied zu Schritt 1

      • fakultätRek rechnet auf dem Rückweg: Erst steigt die Funktion bis n gleich 1 ab. Die Multiplikationen laufen danach, eine in jedem wartenden Aufruf.
      • iter rechnet auf dem Hinweg: Bei k gleich 1 steht das ganze Ergebnis in e. Auf dem Rückweg reicht jeder Aufruf den Wert 24 nur weiter.

      Das else nach dem return ist in iter überflüssig, weil die Funktion im if-Zweig schon endet. Im Kurstext steht es der Klarheit wegen.

      Schritt 3: Fibonacci-Zahlen

      Erst vorhersagen, dann ausprobieren
      1. fibonacciRek(5) ruft fibonacciRek(4) und fibonacciRek(3) auf. Wie oft läuft die Funktion insgesamt mit dem Argument 3?
        AuflösungZweimal: einmal direkt aus dem Aufruf mit 5 und einmal aus dem Aufruf mit 4. Wähle unten n = 5 und sieh dir den Baum an.

      Die Fibonacci-Zahlen sind rekursiv definiert: Fibo(1) = 1, Fibo(2) = 1 und Fibo(n + 2) = Fibo(n) + Fibo(n + 1). Die Folge beginnt mit 1, 1, 2, 3, 5, 8.

      Iterativ

      Die Schleife merkt sich die letzte und die vorletzte Zahl. Die Zuweisung an letzte überschreibt die bisherige letzte Zahl. Die zweite Zuweisung gewinnt sie als Differenz zurück.

      func fibonacciIter(n int) int {
    if n <= 2 {
        return 1
    }
    vorletzte := 1
    letzte := 1
    for i := 3; i <= n; i++ {
        letzte = vorletzte + letzte
        vorletzte = letzte - vorletzte
    }
    return letzte
}

      Rekursiv

      Die rekursive Funktion ist kürzer und folgt der Definition Wort für Wort:

      func fibonacciRek(n int) int {
    if n <= 2 {
        return 1
    } else {
        return fibonacciRek(n-1) + fibonacciRek(n-2)
    }
}

      Die Funktion enthält zwei rekursive Aufrufe. Danach unterscheidet man zwei Arten:

      • Lineare Rekursion: Ein Aufruf ruft die Funktion höchstens einmal auf, wie bei der Fakultät. Die Zahl der Aufrufe wächst linear mit der Rekursionstiefe.
      • Kaskadenartige Rekursion: Ein Aufruf ruft die Funktion mehrmals auf, wie hier. Die Zahl der Aufrufe wächst exponentiell mit der Rekursionstiefe.

      Wähle ein Argument. Die Seite zählt die Aufrufe von fibonacciRek.

      Die Funktion rechnet viel, und sie rechnet das Gleiche mehrmals: Für das gleiche Argument läuft sie immer wieder, obwohl der Wert schon einmal berechnet war. Die rekursive Funktion ist elegant geschrieben und nicht effizient.

      Schritt 4: Türme von Hanoi

      Erst vorhersagen, dann ausprobieren
      1. Zwei Scheiben liegen auf Stange 1 und sollen nach Stange 3. Welche drei Züge braucht es?
        AuflösungDie kleine Scheibe von 1 nach 2, die große von 1 nach 3, die kleine von 2 nach 3.

      Auf einer Stange liegen n Scheiben verschiedener Größe, die größte unten. Alle Scheiben sollen auf eine andere Stange. Eine dritte Stange hilft. Zwei Regeln gelten:

      • Ein Zug nimmt die oberste Scheibe einer Stange und legt sie oben auf eine andere Stange.
      • Nie liegt eine größere Scheibe auf einer kleineren.

      Die Zerlegung

      Irgendwann muss die größte Scheibe zur Zielstange. Dafür müssen alle anderen Scheiben auf der dritten Stange liegen. Daraus folgen drei Teile:

      • n − 1 Scheiben von der Startstange zur dritten Stange bewegen,
      • die größte Scheibe von der Startstange zur Zielstange bewegen,
      • n − 1 Scheiben von der dritten Stange zur Zielstange bewegen.

      Der erste und der dritte Teil sind die gleiche Aufgabe mit einer Scheibe weniger. Das ist der rekursive Aufruf.

      func move(start, ziel, n int) {
    if n == 1 {
        fmt.Println("Zug von", start, "nach", ziel)
    } else {
        move(start, 6-start-ziel, n-1)
        fmt.Println("Zug von", start, "nach", ziel)
        move(6-start-ziel, ziel, n-1)
    }
}

      Die Stangen heißen 1, 2 und 3. Ihre Summe ist 6. Die Differenz 6 - start - ziel ist deshalb immer die Nummer der dritten Stange.

      Wähle die Zahl der Scheiben. Die Demo führt move(1, 3, n) Zug für Zug aus.

      Stange 1Stange 2Stange 3

      Ausgabe

      Indirekte Rekursion

      Im Kurstext steht vor move ein Programm mit sechs Funktionen, eine für jedes Paar von Stangen: moveAB, moveAC, moveBA, moveBC, moveCA und moveCB.

      func moveAB(n int) {
    if n == 1 {
        fmt.Println("Zug von A nach B")
    } else {
        moveAC(n - 1)
        fmt.Println("Zug von A nach B")
        moveCB(n - 1)
    }
}

      Keine dieser Funktionen ruft sich selbst auf. moveAB ruft aber moveAC auf, und moveAC ruft wieder moveAB auf. Ein solcher Selbstaufruf über einen Umweg heißt indirekte Rekursion. Sie ist schwerer zu erkennen als die direkte, weil sich viele Funktionen im Kreis aufrufen können.

      Schritt 5: Terminierung

      Erst vorhersagen, dann ausprobieren
      1. Die Funktion zahlenfolge ruft sich für ein gerades n mit n / 2 auf und für ein ungerades n mit n + 1. Welche Argumente entstehen nach dem Aufruf mit 7?
        Auflösung7, 8, 4, 2, 1. Bei 1 endet die Funktion.

      Terminierung heißt: Die rekursiven Aufrufe kommen zu einem Ende. Dafür braucht es zweierlei:

      • Ein Ende: Für mindestens einen Wert ruft die Funktion sich nicht mehr auf. Bei indirekter Rekursion gilt das für mindestens eine der beteiligten Funktionen.
      • Ein Abstieg: Jeder rekursive Aufruf bekommt ein Argument, das kleiner ist als das eigene. So kommt die Funktion dem Ende mit jedem Aufruf näher.

      In den Schritten 1 bis 4 war das Argument eine natürliche Zahl, und der rekursive Aufruf bekam n-1 oder n-2. Bei 1 war Schluss.

      Wenn das Argument nicht immer kleiner wird

      „Kleiner“ muss nicht die Ordnung der Zahlen sein. Es genügt, dass irgendeine Größe mit jedem Aufruf kleiner wird und nicht endlos kleiner werden kann. Die Funktion zahlenfolge zeigt das:

      func zahlenfolge(n int) {
    fmt.Printf("%v, ", n)
    if n == 1 {
        fmt.Println("Ende")
    } else if n%2 == 0 { // n gerade
        zahlenfolge(n / 2)
    } else { // n ungerade und n >= 3
        zahlenfolge(n + 1)
    }
}

      Bei einem ungeraden n wird das Argument um 1 größer. Die Funktion endet trotzdem. Das zeigt eine Abstiegsfunktion fA. Sie ordnet jedem Argument eine natürliche Zahl zu:

      • fA(n) = n, falls n gerade ist,
      • fA(n) = n + 2, falls n ungerade und mindestens 3 ist,
      • fA(1) = 1.

      Zu zeigen ist: Ruft die Funktion mit dem Argument n sich selbst mit dem Argument m auf, dann ist fA(n) größer als fA(m). Die Werte von fA sind natürliche Zahlen, und eine Folge natürlicher Zahlen kann nicht endlos kleiner werden. Also endet die Funktion.

      Ausgabe

      Im Kurstext wird der Abstieg für vier Fälle nachgerechnet: n gerade und n/2 gerade, n gerade und n/2 ungerade mit n ≥ 6, n = 2, und n ungerade. Eine solche Abstiegsfunktion zu finden ist oft schwer.

      Was geschieht, wenn eine Rekursion nicht endet

      Fehlt der Zweig ohne rekursiven Aufruf, ruft die Funktion sich immer weiter auf. Jeder Aufruf belegt Speicher. Go bricht das Programm ab, sobald der Speicher für die Aufrufe verbraucht ist:

      func ohneEnde(n int) int {
    return n * ohneEnde(n-1)
}
      runtime: goroutine stack exceeds 1000000000-byte limit fatal error: stack overflow
