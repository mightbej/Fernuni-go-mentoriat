Zeiger in Go

Ein Zeiger ist die Adresse einer Variable. Mit einem Zeiger greift ein Programm auf eine Variable zu, ohne ihren Namen zu nennen. So kann eine Funktion eine Variable ihres Aufrufers ändern.

Kurstext v3.0.6, Abschnitt 7.3 und 7.4, Seiten 171–184.

Worum es geht

Eine Funktion bekommt von jedem Argument eine Kopie. Die Funktion negToZeroValue aus Listing 7.1 konnte deshalb das Array ihres Aufrufers nicht ändern. Sie hat eine geänderte Kopie zurückgegeben.

Mit einem Zeiger geht es ohne Kopie des Arrays: Der Aufrufer übergibt die Adresse des Arrays, und die Funktion ändert das Array an dieser Adresse.

Was aus früheren Kapiteln dazugehört

  • Abschnitt 2.2, Variable und Speicher: Eine Variable ist ein Speicherplatz mit einer Adresse. Die Lektion Variablen, Typen und Speicher zeigt das ohne Go.
  • Abschnitt 5.1, Variablendeklaration: Eine Variable ist ein Speicherort, der mit einem Wert belegt ist. Der Bezeichner ist der Name, unter dem das Programm sie anspricht. Die Lektion dazu heißt Variablendeklaration in Go.
  • Abschnitt 7.2, Wertübergabe: Die Lektion Funktionen in Go führt in Schritt 5 Listing 7.1 aus.

Die Schritte

  • Schritt 1: Listing 7.2 übergibt die Adresse eines Arrays. Die Funktion ändert das Array des Aufrufers.
  • Schritt 2: Der Zeiger-Typ *T, der Adressoperator & und der Dereferenzierungsoperator *, an drei Variablen.
  • Schritt 3: Die Funktion incr erhöht eine Variable ihres Aufrufers. Das ist ein Seiteneffekt.
  • Schritt 4: Die Funktion giveMeFive gibt einen Zeiger auf ihre lokale Variable zurück.
  • Schritt 5: Eine Variable lebt, solange ein Verweis auf sie besteht.
  • Schritt 6: new erzeugt eine Variable ohne Namen.
Diese Lektion zeigt Variablen als Kästen. Wie ein Zeiger im Hauptspeicher liegt, Zelle für Zelle, zeigt die Seite Speichermodell: Zeiger.

Schritt 1: Adresse übergeben

Erst vorhersagen, dann ausprobieren
  1. Die Funktion negToZeroPointer bekommt die Adresse des Arrays nums und hat keine Rückgabe. Was gibt fmt.Println(nums) nach dem Aufruf aus?
    Auflösung[8 0 6 0 0 1 0 3 0 2]. Die Funktion hat das Array nums selbst geändert.

Listing 7.2 löst die Aufgabe aus Listing 7.1 mit einem Zeiger. Drei Schreibweisen sind neu:

  • &nums im Aufruf: Der Adressoperator & liefert die Speicheradresse der Variable nums. Die Adresse einer Variable heißt Zeiger, englisch pointer. Die Funktion bekommt also einen Zeiger und keine Kopie des Arrays.
  • pa *[10]int in der Parameterliste: Der Stern vor dem Typ macht daraus einen Zeiger-Typ. Ein Wert vom Typ *[10]int ist ein Zeiger auf eine Variable vom Typ [10]int.
  • *pa im Rumpf: Der Dereferenzierungsoperator * vor einem Zeiger liefert die Variable, auf die der Zeiger zeigt. *pa ist hier das Array nums. Für den Zugriff auf ein Element braucht der Ausdruck Klammern: (*pa)[i].

    Ausgabe

    Kürzer geschrieben

    Der Zugriff auf ein Element über einen Zeiger auf ein Array kommt oft vor. Go erlaubt deshalb zwei Kurzschreibweisen und dereferenziert den Zeiger dabei von selbst:

    • Element: pa[i] an der Stelle von (*pa)[i].
    • Schleife: for i := range pa an der Stelle von for i := range *pa.
    func negToZeroPointer(pa *[10]int) {
    for i := range pa {
        if pa[i] < 0 {
            pa[i] = 0
        }
    }
}
    Hinweis 7.4 des Kurstexts: An pa[i] oder range pa allein sieht man nicht, ob pa ein Array ist oder ein Zeiger auf ein Array. Das steht in der Deklaration von pa.

    Kurstext v3.0.6, Abschnitt 7.3, Seiten 171–172, und Hinweis 7.4, Seite 177. Das Programm ist Listing 7.2, array_per_zeiger.go, ohne die Zeilen mit package und import und ohne Kommentare.

    Schritt 2: Die Operatoren & und *

    Erst vorhersagen, dann ausprobieren
    1. Nach var x int = 42 und p := &x läuft die Zuweisung *p = 33. Welchen Wert hat x danach?
      Auflösung33. *p ist die Variable, auf die p zeigt, und das ist x.

    Der Wert eines Zeigers ist die Adresse, unter der eine Variable im Speicher abgelegt ist. Mit einem Zeiger greift ein Programm indirekt auf eine Variable zu, also ohne ihren Bezeichner.

    • Zeiger-Typ *T: Zu jedem Typ T gibt es den Zeiger-Typ *T. *int spricht man „Zeiger auf int“. Der Null-Wert jedes Zeiger-Typs ist nil.
    • Adressoperator &: &x liefert die Adresse von x. Der Operand muss eine Variable sein, auch ein Element a[i] eines Arrays zählt dazu. Ein Literal wie 4.95 hat keine Adresse.
    • Dereferenzierungsoperator *: *p ist die Variable, auf die p zeigt. *p darf in einem Ausdruck stehen und auf der linken Seite einer Zuweisung.

    Nach p = &x sagt man: „p zeigt auf x“ oder „p enthält die Adresse von x“.

      Ausgabe

      Ausdrücke mit x, p und pp

      Am Ende des Programms hat x den Wert 33, p zeigt auf x, und pp zeigt auf p. Wähle einen Ausdruck oder eine Anweisung. Die Seite nennt Typ und Wert oder die Meldung von Go.

      Zeiger vergleichen

      Zwei Zeiger des gleichen Typs sind genau dann gleich, wenn sie auf dieselbe Variable zeigen oder beide nil sind. Zwei Variablen mit dem gleichen Wert haben zwei verschiedene Adressen:

      var y, z int = 5, 5
fmt.Println(y == z, &y == &z) // true false
      Hinweis 7.3 des Kurstexts, der Stern: In einer Typangabe wie *int bildet der Stern den Namen des Zeiger-Typs. In einem Ausdruck wie *p ist er der Dereferenzierungsoperator. Zwischen zwei Operanden wie in a * b multipliziert er.

      Mit einem Zeiger lässt sich in Go nicht rechnen. Ein Programm kann einen Zeiger zuweisen, vergleichen und ausgeben, mehr nicht. In der Sprache C ist das anders, dort gibt es Zeiger-Arithmetik.

      Kurstext v3.0.6, Abschnitt 7.4, Seiten 173–178. Das Programm fasst Zeilen des Kurstexts zusammen. Im Kurstext gibt das Programm auch Adressen aus, zum Beispiel 0xc00000a0a8. Sie sind bei jedem Start andere, die Seite schreibt dafür „Adresse von x“. Die Meldungen von Go sind eine Ergänzung, geprüft mit Go 1.26.

      Schritt 3: Zeiger als Parameter

      Erst vorhersagen, dann ausprobieren
      1. x hat den Wert 1. Das Programm ruft zweimal incr(&x) auf. Welchen Wert hat x danach?
        Auflösung3. Jeder Aufruf erhöht die Variable, auf die der Zeiger zeigt, um 1.

      Die Funktion incr bekommt einen Zeiger auf eine int-Variable. Sie erhöht diese Variable um 1 und gibt ihren neuen Wert zurück.

        Ausgabe

        Seiteneffekt

        Die Funktion incr liefert einen Wert und ändert dazu eine Variable, die außerhalb ihres Rumpfs deklariert ist. Eine solche Änderung heißt Seiteneffekt. Nach dem Aufruf ist der Zustand des Programms ein anderer als davor.

        Auch ein Zeiger wird kopiert

        Call-by-value gilt auch hier. Beim Aufruf incr(&x) bekommt der Parameter p eine Kopie des Arguments. Das Argument ist eine Adresse, also bekommt p eine Kopie dieser Adresse. Die Kopie zeigt auf dieselbe Variable x.

        x++ und incr(&x)

        • x++ ist eine Anweisung und kein Ausdruck. Die Zeile fmt.Println(x++) übersetzt Go nicht.
        • incr(&x) ist eine Anweisung und auch ein Ausdruck, weil der Aufruf einen Wert liefert. fmt.Println(incr(&x)) ist erlaubt.

        Einen Zeiger als Argument kennst du schon von fmt.Scan(&s): Die Funktion bekommt die Adresse von s und legt die Eingabe in dieser Variable ab.

        Kurstext v3.0.6, Abschnitt 7.4.1, Seiten 178–180. Das Programm stammt aus dem Kurstext.

        Schritt 4: Zeiger als Rückgabe

        Erst vorhersagen, dann ausprobieren
        1. q und r bekommen je einen Zeiger aus einem Aufruf von giveMeFive(). Was liefert *q == *r, und was liefert q == r?
          Auflösung*q == *r liefert true: Beide Variablen haben den Wert 5. q == r liefert false: Die zwei Zeiger zeigen auf zwei verschiedene Variablen.

        Der Bezeichner einer lokalen Variable gilt nur in dem Block, in dem sie deklariert ist. Das gilt für den Bezeichner. Die Variable selbst kann länger bestehen: Gibt die Funktion einen Zeiger auf sie zurück, erreicht der Aufrufer sie über diesen Zeiger.

        Jeder Aufruf von giveMeFive deklariert eine neue Variable v. Zwei Aufrufe liefern deshalb Zeiger auf zwei verschiedene Variablen.

          Ausgabe

          Der grüne Rahmen enthält die Variablen, deren Bezeichner nicht mehr gilt. Das Programm erreicht sie nur noch über einen Zeiger.

          Kurstext v3.0.6, Abschnitt 7.4.2, Seite 180. Das Programm stammt aus dem Kurstext. Die Namen „erste Variable v“ und „zweite Variable v“ gehören zur Darstellung dieser Seite.

          Schritt 5: Lebenszeit

          Erst vorhersagen, dann ausprobieren
          1. Eine Funktion gibt einen Zeiger auf ihre lokale Variable zurück, und der Aufrufer legt ihn in p ab. Später weist das Programm p eine andere Adresse zu. Was geschieht mit der lokalen Variable?
            AuflösungGibt es keinen anderen Zeiger auf sie, ist sie unerreichbar. Go gibt ihren Speicherplatz von selbst wieder frei.

          Die Lebenszeit einer Variable ist der Zeitraum, in dem es die Variable während des Programmlaufs gibt. Der Gültigkeitsbereich ist der Teil des Programmtexts, in dem ihr Bezeichner gilt.

          • Ohne Zeiger: Die Variable entsteht bei ihrer Deklaration. Verlässt das Programm den Gültigkeitsbereich ihres Bezeichners, endet ihre Lebenszeit.
          • Mit Zeigern: Jeder Zeiger, in dem die Adresse der Variable steht, ist ein weiterer Verweis auf sie. Die Variable lebt, solange mindestens ein Verweis besteht.
          • Unerreichbar: Gilt der Bezeichner nicht mehr und steht die Adresse in keinem Zeiger mehr, heißt die Variable unerreichbar. Erst dann endet ihre Lebenszeit. Der Garbage-Collector von Go gibt ihren Speicherplatz frei.

          Im Programm der Demo gibt neueIntVar einen Zeiger auf die lokale Variable v zurück. Man sagt: Die Variable v bricht aus der Funktion aus, englisch „v escapes from the function“.

            Eine Variable aus einem Block

            Auch die Variable eines Blocks kann länger leben, als ihr Bezeichner gilt:

            var p *int
for i := range 10 {
    i += i
    p = &i
}
fmt.Println(*p) // 18

            Der Bezeichner i gilt nur im Rumpf der Schleife. Im letzten Durchlauf hat i erst den Wert 9 und nach i += i den Wert 18. p enthält die Adresse dieser Variable, deshalb gibt es sie nach der Schleife noch.

            Sorgsam mit der Lebenszeit umgehen

            • Globale Variable: Ihre Lebenszeit ist die ganze Laufzeit des Programms. Sie belegt die ganze Zeit Speicher, auch wenn das Programm sie nicht mehr braucht.
            • Vergessener Zeiger: Solange ein Zeiger auf eine Variable zeigt, kann der Garbage-Collector ihren Speicher nicht freigeben. Zeigt ein Zeiger auf eine Variable, die das Programm längst nicht mehr braucht, bleibt der Speicher belegt. Das heißt Speicherleck, englisch memory leak.

            Kurstext v3.0.6, Abschnitt 7.4.3, Seiten 181–182, und Abschnitt 7.4.4, Seiten 182–183. Das Programm der Demo stammt aus dem Kurstext, ohne die vier Zeilen, die Adressen ausgeben. Die Zahl der Verweise zählt die Seite mit.

            Schritt 6: new

            Erst vorhersagen, dann ausprobieren
            1. Was gibt fmt.Println(*p) gleich nach var p *int = new(int) aus?
              Auflösung0. new(int) erzeugt eine int-Variable mit dem Null-Wert und liefert ihre Adresse.

            Eine Deklaration verlangt einen Bezeichner. Greift das Programm auf die Variable nur über einen Zeiger zu, ist der Bezeichner überflüssig. Dafür gibt es die eingebaute Funktion new.

            Der Aufruf new(T) tut drei Schritte:

            • Er erzeugt eine Variable vom Typ T.
            • Er gibt ihr den Null-Wert von T.
            • Er liefert ihre Adresse, einen Wert vom Typ *T.

            Eine Variable, die new erzeugt hat, heißt unbenannte oder anonyme Variable.

              Ausgabe

              Zwei Schreibweisen, die gleiche Variable

              Die zwei Funktionen tun das Gleiche. Die erste vergibt einen Bezeichner, den niemand braucht:

              func neueIntVar() *int {
    var v int
    return &v
}

func neueIntVarNew() *int {
    return new(int)
}

              Für die Variable macht es keinen Unterschied, ob eine Deklaration oder new sie erzeugt hat. Auch eine Variable aus new gibt der Garbage-Collector frei, sobald sie unerreichbar ist.
