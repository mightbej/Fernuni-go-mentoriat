Ausgangspunkt: Selection Sort mit Funktionen

Das ist der Stand aus dem vorigen Block. Beide Funktionen arbeiten mit call-by-value – das Array wird kopiert:

package main import "fmt" func findMin(a [10]int, pos int) int { min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } return min } func swap(a [10]int, i int, j int) [10]int { a[i], a[j] = a[j], a[i] return a } func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) for pos := 0; pos < len(a)-1; pos++ { min := findMin(a, pos) a = swap(a, pos, min) fmt.Printf("Nach Runde %d: %v\n", pos+1, a) } fmt.Println("Sortiert:", a) }
Das Problem: Die swap-Funktion muss das gesamte Array kopieren und zurückgeben, obwohl sie nur zwei Elemente tauscht.
Neue Lösung: Zeiger-Parameter ermöglichen es der Funktion, das Original-Array direkt zu verändern.

Zeiger-Grundlagen wiederholt

Ein Zeiger speichert die Speicheradresse einer anderen Variable. Mit & erhält man die Adresse, mit * greift man auf den Wert zu.

Konzept Beispiel Bedeutung
Adressoperator &a "Gib mir die Adresse von a"
Zeiger-Typ *[10]int Zeiger auf ein Array von 10 int
Dereferenzoperator *ptr "Gib mir den Wert, auf den ptr zeigt"
Wichtig: Ein Zeiger auf ein Array zeigt auf das Original, nicht auf eine Kopie. Änderungen wirken sich direkt aus.

findMin-Funktion: Braucht Zeiger?

Die findMin-Funktion liest nur im Array, ändert nichts. Sie braucht keinen Zeiger:

func findMin(a [10]int, pos int) int { min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } return min }
Überlegung: Wir lesen nur, verändern nicht. Deshalb bleibt diese Funktion unverändert.
Regel: Nur Funktionen, die das Array verändern, brauchen einen Zeiger-Parameter.

swap-Funktion mit Zeiger

Die swap-Funktion verändert das Array. Hier verwenden wir einen Zeiger:

Alte Version (call-by-value)

func swap(a [10]int, i int, j int) [10]int { a[i], a[j] = a[j], a[i] return a }

Neue Version (call-by-reference)

func swap(a *[10]int, i int, j int) { a[i], a[j] = a[j], a[i] }
Was ändert sich:
  • Parameter: *[10]int statt [10]int
  • Keine Rückgabe mehr!
  • Go dereferenciert automatisch: a[i] funktioniert auch auf Zeigern
Go-Feature: In Go kann man auf Array-Elementen über einen Zeiger ohne explizites Dereferenzieren zugreifen.

Aufruf in main(): Call-by-reference

Der Aufruf ändert sich, weil wir nun einen Zeiger übergeben:

Alte Version

min := findMin(a, pos) a = swap(a, pos, min)

Neue Version

min := findMin(a, pos) swap(&a, pos, min)
Was passiert:
  • &a gibt die Adresse des Arrays an swap
  • swap veändert das Original direkt
  • Keine Zuweisung nötig!
Aspekt call-by-value (alt) call-by-reference (neu)
Parameter-Typ in swap [10]int *[10]int
Übergabe swap(a, pos, min) swap(&a, pos, min)
Rückgabewert [10]int keine
Zuweisung nach Aufruf a = result nicht nötig

Vergleich: Bubble Sort vs. Selection Sort mit Zeigern

Beide Algorithmen nutzen das gleiche Zeiger-Konzept, aber mit unterschiedlicher Logik:

Aspekt Bubble Sort mit Zeigern Selection Sort mit Zeigern
Suchlogik Benachbarte Elemente vergleichen Minimum im Rest suchen
Tausch-Häufigkeit Viele kleine Tausche möglich Maximal ein Tausch pro Runde
Zeiger-Vorteil Vermeidet ständiges Kopieren beim Tausch Vermeidet Array-Rückgabe beim einzigen Tausch
Wichtig: Die Zeiger-Optimierung hilft bei beiden Algorithmen, aber Selection Sort profitiert mehr davon, weil nur ein Tausch pro Runde anfällt.

Vollständiger Code: Selection Sort mit Zeigern

package main import "fmt" func findMin(a [10]int, pos int) int { min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } return min } func swap(a *[10]int, i int, j int) { a[i], a[j] = a[j], a[i] } func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) for pos := 0; pos < len(a)-1; pos++ { min := findMin(a, pos) swap(&a, pos, min) fmt.Printf("Nach Runde %d: %v\n", pos+1, a) } fmt.Println("Sortiert:", a) }
Vergleich zur alten Lösung: Der Code sieht ähnlich aus, aber swap arbeitet jetzt mit einer Referenz zum Original, nicht mit einer Kopie.

Meta-Seite: Was haben wir gelernt?

Thema Erkenntnis
Call-by-value vs. Call-by-reference Funktionen mit Zeiger-Parametern verändern das Original, nicht eine Kopie.
Wann Zeiger verwenden? Nur wenn die Funktion Daten verändern soll. Beim Lesen nicht nötig.
Effizienz Zeiger sparen das Kopieren großer Objekte wie Arrays.
Go-Syntax a[i] funktioniert auch auf Zeigern – keine explizite Dereferenzierung nötig.
Universelle Anwendbarkeit Das gleiche Konzept funktioniert für verschiedene Algorithmen.

Wichtigste Erkenntnisse zusammengefasst

Zeiger für Effizienz
Unveränderliche Daten: Keine Zeiger nötig
Änderbare Daten: Zeiger sinnvoll
Verschiedene Algorithmen, gleiche Technik
Nächster sinnvoller Schritt: Rekursion. Bisher haben wir iterative Algorithmen mit Funktionen refaktoriert. Rekursion ermöglicht elegante Lösungen für Probleme, die sich selbst enthalten.
