Funktionen in Go: Rückgaben und Wertübergabe

Eine Funktion in Go kann mehrere Werte zurückgeben, zum Beispiel ein Ergebnis und einen Fehler. Jedes Argument bekommt sie als Kopie. Die Seite zeigt beides an den Programmen des Kurstexts.

Kurstext v3.0.6, Abschnitt 7.1 und 7.2, Seiten 163–170.

Worum es geht

Aus Kapitel 3 kennst du die Funktion mit Parametern und einem Rückgabewert. In Abschnitt 7.1 und 7.2 des Kurstexts kommen drei Stücke dazu:

  • Mehrere Rückgaben: Eine Funktion liefert zwei oder mehr Werte zurück, zum Beispiel Quotient und Rest einer Division.
  • Fehler als Rückgabe: Viele Funktionen der Standardbibliothek liefern ein Ergebnis und dazu einen Wert vom Typ error.
  • Wertübergabe: Eine Funktion bekommt von jedem Argument eine Kopie. Bei einem Array ist das eine Kopie aller Elemente.

  • Abschnitt 5.3.2, Tupel-Zuweisung: Die Lektion Zuweisungen in Go zeigt a, b = b, a. Mit einer Tupel-Zuweisung nimmt ein Programm mehrere Rückgaben entgegen.

Schritt 1: Mehrere Rückgaben

Erst vorhersagen, dann ausprobieren
  1. Was gibt fmt.Println(17 / 3, 17 % 3) aus?
    Auflösung5 2. Die 3 passt fünfmal in die 17, und es bleibt der Rest 2.

Eine Funktionsdeklaration besteht in Go aus vier Teilen:

  • dem Schlüsselwort func,
  • einem Funktionsnamen,
  • einer Liste mit Parametern in runden Klammern,
  • einer Liste mit Rückgaben in runden Klammern. Diese Liste darf fehlen.

Eine Funktion, die mehrere Werte zurückliefert, heißt mehrwertige Funktion. Die Funktion divMitRest liefert den Ganzzahlquotienten und den Divisionsrest:

func divMitRest(x int, y int) (int, int) {
    return x / y, x % y
}

Die Rückgabeliste (int, int) legt fest: Die Funktion liefert zwei Werte vom Typ int. Die return-Anweisung hat deshalb zwei Ausdrücke, getrennt durch ein Komma.

Benannte Rückgaben

Die Rückgaben dürfen Namen tragen wie die Parameter. Für jede benannte Rückgabe legt Go im Rumpf eine Variable an und gibt ihr den Null-Wert ihres Typs. Der Rumpf weist diesen Variablen die Ergebnisse zu.

Eine return-Anweisung ohne Ausdrücke heißt blankes return. Sie gibt die Werte der benannten Rückgaben zurück. Die Demo führt diese Fassung aus:

    Ausgabe

    Kürzer geschrieben

    Haben aufeinanderfolgende Parameter oder Rückgaben den gleichen Typ, steht der Typ nur einmal, wie bei einer Variablendeklaration:

    func divMitRest(x, y int) (q, r int) {
    // ...
}
    Hinweis 7.1 des Kurstexts: Namen für die Rückgaben sagen, was welcher Wert bedeutet. Das hilft, wenn mehrere Rückgaben den gleichen Typ haben. Ein blankes return ist kurz. In einer langen Funktion sieht man ihm aber nicht an, welche Werte zurückgehen. Es soll deshalb selten stehen. Auch mit benannten Rückgaben darf man return q, r schreiben.

    Schritt 2: Signatur

    Erst vorhersagen, dann ausprobieren
    1. Die Funktionen add(a, b int) int und sub(x int, y int) (int) rechnen verschieden und nennen ihre Parameter verschieden. Was haben sie gemeinsam?
      AuflösungBeide nehmen zwei int und liefern einen int. Sie haben die gleiche Signatur.

    Die Folge der Parameter-Typen und die Folge der Rückgabe-Typen bilden zusammen die Signatur einer Funktion. In Go heißt die Signatur auch Typ der Funktion.

    Für die Signatur zählen nur die Typen und ihre Reihenfolge. Es zählen nicht:

    • der Name der Funktion,
    • die Namen der Parameter und der Rückgaben,
    • die Schreibweise, zum Beispiel a, b int oder x int, y int.

    Wähle eine Funktion. Die Seite zeigt ihre Signatur und nennt die Funktionen mit der gleichen Signatur.

    Zwei Schreibweisen

    • Eine Zeile: Besteht der Rumpf aus einer einzigen Anweisung, darf die ganze Deklaration in einer Zeile stehen. Das ist üblich.
    • Klammern um die Rückgabe: Hat eine Funktion nur eine Rückgabe ohne Namen, dürfen die Klammern der Rückgabeliste fehlen. Die Klammern in sub(x int, y int) (int) sind überflüssig.

    Kurstext v3.0.6, Abschnitt 7.1, Seiten 164–165. Die sieben Funktionen stammen aus dem Kurstext. Die Schreibweise des Typs, zum Beispiel func(int, int) int, steht dort nicht. So gibt fmt.Printf mit %T den Typ einer Funktion aus.

    Schritt 3: Rückgabe-Tupel

    Erst vorhersagen, dann ausprobieren
    1. divMitRest(100, 17) liefert 5 und 15. Was liefert divMitRest(divMitRest(100, 17))?
      Auflösung0 und 5. Der äußere Aufruf bekommt 5 und 15 als Argumente. Die 15 passt nullmal in die 5, und es bleibt der Rest 5.

    Der Aufruf einer mehrwertigen Funktion liefert ein Tupel von Werten. divMitRest(17, 3) liefert das Paar aus 5 und 2. Mit diesem Paar kann das Programm vier Arten von Anweisungen bilden:

    • Weiterreichen: Das Paar geht als zwei Argumente an eine andere Funktion. Anzahl und Typen müssen passen.
    • Zuweisen: Eine Tupel-Zuweisung nimmt alle Rückgaben entgegen. Links stehen so viele Variablen, wie die Funktion Werte liefert.
    • Einen Wert verwerfen: An der Stelle eines Werts, den das Programm nicht braucht, steht der leere Bezeichner _.
    • Alles verwerfen: Der Aufruf steht allein als Anweisung.

    Alle acht Zeilen der Demo verwenden diese Funktion:

    func divMitRest(x, y int) (q, r int) { q = x / y; r = x % y; return }
func add(a, b int) int { return a + b }

    Wähle eine Zeile. Die Seite zeigt die Ausgabe oder die Meldung des Compilers.

    Ausgabe

    Kurstext v3.0.6, Abschnitt 7.1.1, Seite 166. Die Zeilen 1 bis 4 stammen aus dem Kurstext. Dort steht in Zeile 3 und 4 eine Zuweisung mit =, weil die Variablen schon deklariert sind. Die Zeilen 5 bis 8 und die Meldungen des Compilers sind eine Ergänzung, geprüft mit Go 1.26.

    Schritt 4: Fehler melden

    Erst vorhersagen, dann ausprobieren
    1. Ein Programm liest mit fmt.Scan(&a, &b, &c) drei ganze Zahlen. Der Benutzer gibt 7 und dann ups ein. Welche Werte haben a, b und c danach?
      Auflösung7, 0 und 0. Die erste Eingabe ist gelesen. Bei der zweiten bricht fmt.Scan ab, b und c behalten ihren Null-Wert.

    Viele Funktionen der Standardbibliothek haben zwei Rückgaben und folgen einem Muster:

    • Erste Rückgabe: der Nutzwert, zum Beispiel ein berechnetes Ergebnis.
    • Zweite Rückgabe: ein Wert vom Typ error. Er sagt, ob ein Fehler aufgetreten ist.

    error ist ein vorgegebener Typ. Der Wert nil bedeutet: Es liegt kein Fehler vor. Jeder andere Wert trägt eine Meldung, die fmt.Println ausgeben kann. Ein error ist dabei kein string.

    Das Beispiel des Kurstexts: fmt.Scan

    var a, b, c, n int
var err error
n, err = fmt.Scan(&a, &b, &c)
if err != nil {
    fmt.Println("Fehler:", err)
}
fmt.Println("Anzahl gültiger Eingaben:", n)
fmt.Println("Eingaben:", a, b, c)

    fmt.Scan liefert zwei Werte. Der erste ist ein int und zählt die gelesenen Eingaben. Der zweite ist ein error. Die Tupel-Zuweisung legt die zwei Werte in n und err ab. Was &a bedeutet, zeigt die Lektion Zeiger in Go.

    Ausgabe

    Eine eigene Funktion mit Fehler: safeAdd

    Die Lektion Überlauf bei Ganzzahlen zeigt: Passt eine Summe nicht in den Typ, rechnet Go ohne Meldung mit dem falschen Wert weiter. Die Funktion safeAdd prüft vor der Addition, ob die Summe in int32 passt. Sie folgt dem Muster: erst der Nutzwert, dann der Fehler.

    // liefert die Summe von a und b
// und meldet einen Fehler, wenn sie nicht in int32 passt
func safeAdd(a, b int32) (int32, error) {
    if b > 0 && a > math.MaxInt32-b {
        return 0, errors.New("Summe ist zu groß für int32")
    }
    if b < 0 && a < math.MinInt32-b {
        return 0, errors.New("Summe ist zu klein für int32")
    }
    return a + b, nil
}

    Die Funktion hat drei return-Anweisungen:

    • Zu groß: Die Summe läge über math.MaxInt32, also über 2147483647. Die Funktion liefert 0 und einen Fehler.
    • Zu klein: Die Summe läge unter math.MinInt32, also unter −2147483648. Die Funktion liefert 0 und einen Fehler.
    • Passt: Die Funktion liefert die Summe und nil.

    Die Bedingung fragt nicht a + b > math.MaxInt32. Diese Summe wäre selbst schon übergelaufen. Die Funktion stellt die Ungleichung um und rechnet math.MaxInt32 - b. Diese Differenz passt immer in int32, wenn b positiv ist.

    So ruft ein Programm die Funktion auf:

    summe, err := safeAdd(a, b)
if err != nil {
    fmt.Println("Fehler:", err)
} else {
    fmt.Println("Summe:", summe)
}

    Wähle zwei Werte für a und b:

    Ausgabe

    safeAdd steht nicht im Kurstext. Die Funktion ist ein Beispiel des Mentors. Sie braucht die Pakete math und errors. errors.New erzeugt aus einem String einen Wert vom Typ error. Im Kurstext kommt errors.New nicht vor.

    Schritt 5: Kopie des Arguments

    Erst vorhersagen, dann ausprobieren
    1. Die Funktion negToZeroValue setzt in ihrem Parameter a alle negativen Elemente auf 0. main ruft negToZeroValue(nums) auf. Ändert sich das Array nums?
      AuflösungNein. a ist eine Kopie von nums. Die Funktion ändert nur die Kopie.

    In Go bekommt eine Funktion von jedem Argument eine Kopie des Werts. Diese Art der Übergabe heißt call-by-value. Go kennt nur diese eine Art.

    Bei einem int fällt das kaum auf. Bei einem Array hat es zwei Folgen:

    • Aufwand: Bei jedem Aufruf kopiert der Rechner das ganze Array. Bei einem Array vom Typ [1000][1000]int sind das 1.000.000 Elemente. Das kostet Rechenzeit und Speicherplatz.
    • Wirkung: Was die Funktion am Array ändert, ändert sie an ihrer Kopie. Das Array des Aufrufers bleibt, wie es war. Die Funktion hat keinen Zugriff darauf.

    Die Demo führt Listing 7.1 aus. Die Funktion gibt ihre geänderte Kopie zurück, und main legt sie in posNums ab.

      Ausgabe

      Was daran stört

      Die Funktion erfüllt die Aufgabe, aber auf einem Umweg: Das Array wird zweimal kopiert, einmal beim Aufruf und einmal bei der Rückgabe. Praktischer wäre eine Funktion, die das Array des Aufrufers selbst ändert.

      Sprachen wie Pascal haben dafür eine zweite Art von Parametern, die Referenzparameter. Die Übergabe heißt dort call-by-reference. Go hat sie nicht. In Go übergibt man der Funktion einen Zeiger auf das Array.
