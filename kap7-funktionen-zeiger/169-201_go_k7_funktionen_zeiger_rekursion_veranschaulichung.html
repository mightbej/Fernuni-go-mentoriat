2. Eine Funktion systematisch lesen

Bevor mehrere Rückgaben, Zeiger oder Rekursion behandelt werden, muss eine Funktionsdeklaration sicher gelesen werden. Eine Funktion ist nicht nur ein Stück Code, sondern ein Vertrag: Welche Werte gehen hinein, welcher Wert oder welche Werte kommen heraus?

func rechteck(seiteA int, seiteB int) int { var flaeche int = seiteA * seiteB return flaeche }
TeilCodeFrage beim Lesen

ParameterseiteA int, seiteB intWelche Eingaben braucht die Funktion?
RückgabetypintWelchen Typ liefert die Funktion zurück?
Rumpf{ ... }Welche Anweisungen werden beim Aufruf ausgeführt?

Parameter vs. Argument

Merksatz: Parameter gehören zur Deklaration, Argumente gehören zum Aufruf.

3. Mehrere Rückgabewerte

Go kann mehrere Werte aus einer Funktion zurückgeben. Das ist kein Sondertrick, sondern ein zentrales Sprachmittel. Es wird besonders wichtig beim typischen Muster: Nutzwert plus Fehlerwert.

func divMitRest(x int, y int) (int, int) { return x / y, x % y }

Die Funktion beantwortet zwei Fragen gleichzeitig:

  1. Wie oft passt y ganzzahlig in x?
  2. Welcher Rest bleibt übrig?
divMitRest(17, 3)
→
17 / 3 = 5
+
17 % 3 = 2
→
5, 2
fmt.Println(divMitRest(17, 3)) // Ausgabe: 5 2
Wichtig: Die Rückgabeliste (int, int) sagt nur, dass zwei Integer-Werte zurückgegeben werden. Sie sagt noch nicht, welcher Wert welche Bedeutung hat.

4. Benannte Rückgaben

Wenn mehrere Rückgabewerte denselben Typ haben, kann die Bedeutung unklar werden. Benannte Rückgaben helfen, diese Bedeutung sichtbar zu machen.

func divMitRest(x int, y int) (q int, r int) { q = x / y r = x % y return }

Hier erzeugt die Rückgabeliste intern zwei lokale Variablen: q und r. Sie existieren im Funktionsrumpf und werden am Ende zurückgegeben.

Parameter
x = 17
y = 3
Benannte Rückgaben
q = 5
r = 2

Blankes return

Das einfache return funktioniert hier, weil Go weiß, dass q und r die Rückgabevariablen sind.

Didaktische Warnung: Blankes return ist kurz, aber nicht immer lesbar. Bei kurzen Funktionen ist es akzeptabel. Bei längeren Funktionen muss man nach oben zur Rückgabeliste schauen, um zu erkennen, was zurückgegeben wird.

5. Signatur: Der Typ einer Funktion

Die Signatur beschreibt die Typstruktur einer Funktion. Für die Signatur zählen die Typen der Parameter und die Typen der Rückgaben in ihrer Reihenfolge. Namen sind nicht entscheidend.

func add(a, b int) int { return a + b } func sub(x int, y int) (int) { return x - y } func div(a, b int) float64 { return float64(a) / float64(b) }
FunktionParameter-TypenRückgabe-TypenSignatur
addint, intintint, int → int
subint, intintint, int → int
divint, intfloat64int, int → float64
Folge: add und sub haben dieselbe Signatur, obwohl sie unterschiedliche Namen, Parameternamen und Operationen besitzen.
Lesetraining: Frage bei jeder Funktion zuerst: Welche Typen gehen hinein? Welche Typen kommen heraus?

6. Rückgabe-Tupel verarbeiten

Wenn eine Funktion mehrere Werte zurückgibt, müssen diese Werte passend verarbeitet werden. Man kann sie Variablen zuweisen, direkt weiterreichen oder bewusst verwerfen.

Fall 1: Beide Rückgaben übernehmen

gquot, rest := divMitRest(17, 3) fmt.Println(gquot, rest) // 5 2

Fall 2: Einen Wert bewusst verwerfen

gquot, _ = divMitRest(50, 7)

Der leere Bezeichner _ bedeutet: Dieser Wert wird absichtlich nicht verwendet. Das ist besser als eine Variable anzulegen, die danach nie gebraucht wird.

Fall 3: Rückgaben weiterreichen

gquot, rest = divMitRest(divMitRest(100, 17)) // 0 5
Wichtig: Mehrere Rückgaben müssen in Anzahl und Typ zu der Stelle passen, an der sie verwendet werden.
SchreibweiseDidaktische Bedeutung
x, y := f()beide Rückgaben werden ausgewertet
x, _ := f()ein Rückgabewert wird bewusst ignoriert
g(f())Rückgaben von f werden direkt Argumente von g

7. Das error-Muster in Go

Go verwendet häufig das Muster: erster Rückgabewert = Nutzwert, zweiter Rückgabewert = Fehler. Der Fehlerwert hat den Typ error. Wenn kein Fehler vorliegt, ist dieser Wert nil.

var a, b, c, n int var err error n, err = fmt.Scan(&a, &b, &c) if err != nil { fmt.Println("Fehler:", err) } fmt.Println("Anzahl gültiger Eingaben:", n) fmt.Println("Eingaben:", a, b, c)

Dieses Beispiel ist für Studenten schwierig, weil hier mehrere Konzepte gleichzeitig auftreten: mehrere Rückgaben, Zuweisung an zwei Variablen, Fehlerprüfung und bereits Zeiger bei &a, &b, &c.

TeilBedeutung
nAnzahl erfolgreich gelesener Eingaben
errFehlerwert; nil bedeutet kein Fehler
if err != nilPrüfung, ob ein Fehler aufgetreten ist
&aAdresse von a; wird später bei Zeigern erklärt
Didaktische Entlastung: Beim ersten Lesen reicht: fmt.Scan liefert zwei Werte zurück. Einer sagt, wie viel geklappt hat, der andere sagt, ob ein Fehler auftrat.

8. Call-by-value: Übergabe als Kopie

In Go werden Argumente an Funktionen per Wert übergeben. Das heißt: Der Wert des Arguments wird kopiert und diese Kopie wird dem Parameter zugewiesen.

func setzeAufNull(x int) { x = 0 } func main() { zahl := 7 setzeAufNull(zahl) fmt.Println(zahl) // 7 }
main
zahl = 7
setzeAufNull
x = 7
x = 0

Die Funktion verändert nur ihre lokale Kopie x. Die Variable zahl in main bleibt unverändert.

Merksatz: Ein Parameter ist eine neue lokale Variable, die beim Funktionsaufruf mit dem Argumentwert initialisiert wird.

9. Call-by-value bei Arrays: Die Kopie wird sichtbar teuer

Bei einem einzelnen int ist die Kopie kaum sichtbar. Bei Arrays wird das Prinzip wichtig, weil das ganze Array kopiert wird.

func negToZeroValue(a [10]int) [10]int { for i := range a { if a[i] < 0 { a[i] = 0 } } return a } func main() { nums := [10]int{8, -5, 6, -3, -7, 1, -4, 3, -9, 2} posNums := negToZeroValue(nums) fmt.Println(nums) // [8 -5 6 -3 -7 1 -4 3 -9 2] fmt.Println(posNums) // [8 0 6 0 0 1 0 3 0 2] }
Original in main
nums = [8 -5 6 -3 -7 1 -4 3 -9 2]
Kopie in Funktion
a = [8 -5 6 -3 -7 1 -4 3 -9 2]
a = [8 0 6 0 0 1 0 3 0 2]
Rückgabe
posNums = [8 0 6 0 0 1 0 3 0 2]

Die Funktion kann das Original nicht verändern, weil sie keinen Zugriff darauf hat. Sie kennt nur ihre lokale Kopie.

Typisches Missverständnis: Viele erwarten, dass nums verändert wird. Das passiert nicht, weil a nicht dasselbe Array ist, sondern eine Kopie.

11. Grundbild eines Zeigers

Eine Variable hat einen Wert. Zusätzlich liegt sie irgendwo im Speicher. Ein Zeiger enthält nicht den Wert selbst, sondern eine Adresse, unter der eine Variable gefunden werden kann.

var x int = 42 var p *int p = &x
Variable x
Name: x
Wert: 42
Adresse: z. B. 0xc00000a0a8
Zeigervariable p
Typ: *int
Wert: Adresse von x
p zeigt auf x

Die Formulierung „p zeigt auf x“ bedeutet: In p steht die Adresse von x. Über diese Adresse kann man wieder zu x gelangen.

Merksatz: Ein Zeiger ist selbst ein Wert. Sein Wert ist eine Adresse.

12. Die Operatoren & und *

Für Zeiger braucht man zwei Bewegungen: vom Namen zur Adresse und von der Adresse zurück zur Variablen.

var x int = 42 var p *int = &x fmt.Println(p) // Adresse von x fmt.Println(*p) // Wert der Variable, auf die p zeigt *p = 33 fmt.Println(x) // 33
AusdruckLesartErgebnis
&xAdresse von xWert vom Typ *int
pZeigerwertAdresse von x
*pVariable, auf die p zeigtzugreifbar wie x
*p = 33indirekte Zuweisungx bekommt den Wert 33
Der Stern hat drei Rollen:
  • *int: Bildung eines Zeigertyps
  • *p: Dereferenzierung eines Zeigers
  • a * b: Multiplikation
Einfaches Bild: & fragt: Wo liegt die Variable? * fragt: Was liegt an dieser Adresse?

13. Zeiger auf Arrays

Jetzt kehren wir zum Array-Beispiel zurück. Statt das ganze Array zu kopieren, übergeben wir die Adresse des Arrays.

func negToZeroPointer(pa *[10]int) { for i := range *pa { if (*pa)[i] < 0 { (*pa)[i] = 0 } } } func main() { nums := [10]int{8, -5, 6, -3, -7, 1, -4, 3, -9, 2} negToZeroPointer(&nums) fmt.Println(nums) // [8 0 6 0 0 1 0 3 0 2] }

Kurzschreibweise: Go erlaubt bei Array-Zeigern oft pa[i] statt (*pa)[i]. Für den Anfang ist die explizite Schreibweise aber didaktisch klarer.

14. Zeiger als Funktionsparameter

Ein Zeigerparameter erlaubt es einer Funktion, eine vorhandene Variable außerhalb ihres eigenen Rumpfes zu verändern. Das nennt man häufig einen Seiteneffekt.

func incr(p *int) int { *p++ return *p } func main() { x := 1 incr(&x) fmt.Println(x) // 2 fmt.Println(incr(&x)) // 3 fmt.Println(x) // 3 }

Schrittfolge

  1. x ist eine Variable in main.
  2. &x liefert die Adresse von x.
  3. Diese Adresse wird dem Parameter p übergeben.
  4. *p++ erhöht die Variable, auf die p zeigt.
  5. Da p auf x zeigt, wird x erhöht.
Wichtige Unterscheidung: Auch der Zeigerwert selbst wird per value übergeben. Aber dieser kopierte Zeigerwert zeigt auf dieselbe Originalvariable.

15. nil, new und Lebenszeit von Variablen

Der Nullwert eines Zeigertyps ist nil. Ein nil-Zeiger zeigt auf keine Variable. Deshalb darf man ihn nicht dereferenzieren.

var p *int fmt.Println(p) // nil // fmt.Println(*p) // Fehler zur Laufzeit: nil pointer dereference
Regel: Vor *p muss klar sein, dass p tatsächlich auf eine gültige Variable zeigt.

new erzeugt eine anonyme Variable

p := new(int) *p = 42 fmt.Println(*p) // 42

new(int) erzeugt eine neue int-Variable ohne Namen und liefert einen Zeiger auf diese Variable zurück.

Lebenszeit ist nicht dasselbe wie Sichtbarkeit

func erzeugeZahl() *int { x := 42 return &x } func main() { p := erzeugeZahl() fmt.Println(*p) // 42 }

Der Bezeichner x ist außerhalb der Funktion nicht sichtbar. Die Variable selbst kann aber weiterleben, wenn ein Zeiger auf sie zurückgegeben wird. Go verwaltet das automatisch.

Didaktisch wichtig: Sichtbarkeit betrifft Namen im Programmtext. Lebenszeit betrifft, wie lange die Variable im Speicher gültig bleibt.

16. Rekursion: Grundidee

Rekursion bedeutet: Eine Funktion ruft sich selbst auf. Das ist sinnvoll, wenn sich ein Problem als kleinere Version desselben Problems formulieren lässt.

func fakultaet(n int) int { if n <= 1 { return 1 } return n * fakultaet(n-1) }

Die Fakultät ist dafür ein gutes Beispiel:

4! = 4 * 3 * 2 * 1 4! = 4 * 3! 3! = 3 * 2! 2! = 2 * 1! 1! = 1
TeilCodeFunktion
Abbruchfallif n <= 1 { return 1 }beendet die Rekursion
rekursiver Fallreturn n * fakultaet(n-1)ruft dieselbe Funktion mit kleinerem Problem auf
Fortschrittn-1führt schrittweise zum Abbruchfall
Merksatz: Rekursion braucht immer zwei Dinge: einen Abbruchfall und einen rekursiven Schritt, der dem Abbruchfall näherkommt.

17. Rekursion als Aufrufstapel

Beim rekursiven Aufruf wird nicht dieselbe Ausführung einfach überschrieben. Jeder Aufruf erhält seinen eigenen Ausführungsrahmen mit eigenen Parametern und lokalen Variablen. Diese Rahmen liegen gedanklich auf einem Stapel.

fakultaet(4) = 4 * fakultaet(3) = 4 * 3 * fakultaet(2) = 4 * 3 * 2 * fakultaet(1) = 4 * 3 * 2 * 1 = 24
fakultaet(4): wartet auf Ergebnis von fakultaet(3)
fakultaet(3): wartet auf Ergebnis von fakultaet(2)
fakultaet(2): wartet auf Ergebnis von fakultaet(1)
fakultaet(1): liefert 1 zurück

Rückweg

Aufrufbekommt zurückliefert weiter
fakultaet(1)-1
fakultaet(2)12 * 1 = 2
fakultaet(3)23 * 2 = 6
fakultaet(4)64 * 6 = 24
Didaktischer Kern: Rekursion hat zwei Bewegungen: erst hinunter bis zum Abbruchfall, dann zurück mit den Ergebnissen.

18. Terminierung: Wann endet Rekursion?

Eine rekursive Funktion ist gefährlich, wenn nicht klar ist, dass sie den Abbruchfall erreicht. Dann ruft sie sich immer weiter auf, bis der Aufrufstapel erschöpft ist.

Korrekt: n wird kleiner

func countdown(n int) { if n <= 0 { return } fmt.Println(n) countdown(n-1) }

Fehlerhaft: kein Fortschritt

func countdownFehler(n int) { if n <= 0 { return } fmt.Println(n) countdownFehler(n) // n bleibt gleich }
Problem: Der zweite Code erreicht den Abbruchfall nicht, wenn n positiv ist. Die Funktion ruft sich endlos mit demselben Wert auf.
PrüffrageWarum wichtig?
Gibt es einen Abbruchfall?Ohne Abbruch kann Rekursion nicht enden.
Wird das Problem kleiner?Der rekursive Schritt muss dem Abbruchfall näherkommen.
Ist der Abbruchfall erreichbar?Ein vorhandener Abbruchfall reicht nicht, wenn er nie erreicht wird.

19. Fibonacci: Warum Rekursion ineffizient werden kann

Rekursion kann elegant aussehen, aber sehr ineffizient sein. Das klassische Beispiel ist die naive Fibonacci-Funktion.

func fib(n int) int { if n <= 1 { return n } return fib(n-1) + fib(n-2) }

Für fib(5) entsteht kein einfacher linearer Stapel, sondern ein verzweigter Aufrufbaum:

fib(5) ├─ fib(4) │ ├─ fib(3) │ │ ├─ fib(2) │ │ │ ├─ fib(1) │ │ │ └─ fib(0) │ │ └─ fib(1) │ └─ fib(2) │ ├─ fib(1) │ └─ fib(0) └─ fib(3) ├─ fib(2) │ ├─ fib(1) │ └─ fib(0) └─ fib(1)

Man sieht: fib(3), fib(2) und fib(1) werden mehrfach berechnet.

Negatives Verhalten: Die naive Fibonacci-Rekursion wächst kaskadenartig. Der Aufwand steigt sehr schnell, weil dieselben Teilprobleme immer wieder neu berechnet werden.
RekursionsformStrukturBewertung
lineare Rekursionein rekursiver Aufruf pro Schritteinfacher zu verstehen
kaskadenartige Rekursionmehrere rekursive Aufrufe pro Schrittkann sehr ineffizient werden
Endrekursionrekursiver Aufruf ist letzte Aktionkonzeptionell wichtig, in Go nicht automatisch Optimierungsgarantie
indirekte RekursionFunktionen rufen sich über Umwege gegenseitig aufschwerer zu erkennen
Lehrpunkt: Rekursion ist kein Selbstzweck. Sie ist gut, wenn die Problemstruktur rekursiv ist und der Aufwand kontrollierbar bleibt.
