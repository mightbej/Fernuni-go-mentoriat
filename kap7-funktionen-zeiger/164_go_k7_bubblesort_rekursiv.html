Bubble Sort kann auch rekursiv sein

Die iterative Version haben wir bereits gesehen. Aber: Bubble Sort kann auch rekursiv implementiert werden!

Kernidee:
  • Ein Durchlauf durch das Array: Die größten Elemente "blasen" nach oben
  • Dann: Rekursiver Aufruf mit um 1 kleinerer Größe
  • Basis-Fall: Wenn nur noch 1 Element übrig ist, sind wir fertig
Voraussetzung für Rekursion:
  • Basis-Fall: Wann stoppt die Rekursion?
  • Rekursiver Fall: Wie wird das Problem kleiner?
  • Fortschritt: Mit jedem Aufruf wird das Array um 1 Element kleiner
Vorteil von Rekursion: Der Code wird oft eleganter und kürzer, weil die Struktur des Algorithmus direkter ausgedrückt wird.

Wie funktioniert rekursives Bubble Sort?

Der Gedanke ist einfach: Mache einen Durchlauf, dann rufe dich selbst auf einem kleineren Array auf.

bubbleSort(a, n) mit n=5:

1. Durchlauf: Größtes Element nach Position 4
2. Rufe bubbleSort(a, 4) auf

  bubbleSort(a, 4):
  1. Durchlauf: Nächst-größtes nach Position 3
  2. Rufe bubbleSort(a, 3) auf

    bubbleSort(a, 3):
    1. Durchlauf: Nächst-größtes nach Position 2
    2. Rufe bubbleSort(a, 2) auf

      bubbleSort(a, 2):
      1. Durchlauf: Kleinstes und größtes tauschen
      2. Rufe bubbleSort(a, 1) auf

        bubbleSort(a, 1):
        Basis-Fall! Nur 1 Element → STOP
Der Stack wächst:
  • Jeder Aufruf "merkt sich", wo er aufgehört hat
  • Der Call-Stack wird tiefer und tiefer (5 → 4 → 3 → 2 → 1)
  • Dann "kehrt" der Stack wieder auf (1 ← 2 ← 3 ← 4 ← 5)
  • Das Array ist sortiert!

Der Basis-Fall: Wenn stoppt Rekursion?

Ohne Basis-Fall würde Rekursion ewig laufen (Stack Overflow!). Der Basis-Fall ist entscheidend:

func bubbleSort(a *[10]int, n int) { // BASIS-FALL: Stoppt die Rekursion if n <= 1 { return // Fertig! Nur 0 oder 1 Element } // Rekursiver Fall kommt später... }
Warum n <= 1?
  • Ein Array mit 0 oder 1 Element ist bereits sortiert
  • Da ist nichts zu tauschen
  • Wir können die Rekursion beenden
Wichtig: Der Basis-Fall muss immer erreichbar sein! Mit jedem Aufruf wird n kleiner → irgendwann erreichen wir n = 1.

Der rekursive Fall: Ein Durchlauf + Aufruf

Nach dem Basis-Fall kommt der Rekursive Fall: Durchlauf + rekursiver Aufruf mit n-1

func bubbleSort(a *[10]int, n int) { if n <= 1 { return } // REKURSIVER FALL: // 1. Ein Durchlauf: Vergleiche benachbarte Elemente for i := 0; i < n-1; i++ { if a[i] > a[i+1] { a[i], a[i+1] = a[i+1], a[i] // Tausch } } // 2. Rekursiver Aufruf mit kleinerem Array bubbleSort(a, n-1) }
Was passiert:
  • Schritt 1: Der größte Durchlauf sortiert: Das größte Element "blasiert" nach Position n-1
  • Schritt 2: Rufe dich selbst auf mit n-1
  • Die Schleife: i < n-1 stellt sicher, dass das bereits sortierte Element ignoriert wird
Die Eleganz: Der Code drückt die Struktur des Algorithmus direkt aus:
  • "Mache einen Durchlauf"
  • "Dann sortiere den Rest rekursiv"

Mit Funktionen: isGreater und swap

Wie bei der iterativen Version können wir Vergleich und Tausch in Funktionen auslagern:

func isGreater(a *[10]int, i int) bool { return a[i] > a[i+1] } func swap(a *[10]int, i int) { a[i], a[i+1] = a[i+1], a[i] } func bubbleSort(a *[10]int, n int) { if n <= 1 { return } for i := 0; i < n-1; i++ { if isGreater(a, i) { swap(a, i) } } bubbleSort(a, n-1) }
Vorteile dieser Zerlegung:
  • Der Code ist lesbarer
  • Die Logik ist isoliert und testbar
  • Mit Zeigern ist alles bereits O(1) Memory-Overhead!

Mit Zeigern: Effiziente Parameterübergabe

Mit Zeiger-Parametern (*[10]int) vermeiden wir teure Array-Kopien:

Aspekt call-by-value call-by-reference (Zeiger)
Parameter bei Aufruf ganzes Array kopiert (~800 Byte) nur Adresse (~8 Byte)
Was die Funktion ändert lokale Kopie, Original unverändert Original direkt verändert
Speicher-Overhead pro Aufruf O(n) O(1)
Return-Statement nötig? ja, ganzes Array zurück nein, Original ist bereits verändert
Bei Rekursion ist das kritisch!
  • Bei jedem rekursiven Aufruf (n Aufrufe insgesamt) würde call-by-value O(n²) Speicher-Overhead erzeugen
  • Mit Zeigern: Overhead bleibt O(n) gesamt (nur der Call-Stack)

Vergleich: Iterativ vs. Rekursiv

Beide Versionen implementieren denselben Bubble-Sort-Algorithmus. Die Unterschiede sind strukturell:

Aspekt Iterativ Rekursiv
Struktur Äußere Schleife (Pass), innere Schleife (Vergleiche) Rekursive Aufrufe; Basis-Fall und rekursiver Fall
Speicher (Call-Stack) O(1) – Stack-Tiefe konstant O(n) – Stack-Tiefe = n (rekursive Aufrufe)
Lesbarkeit Explizit, alle Schleifen sichtbar Eleganter, Struktur direkt ausgedrückt
Optimierung Mit len(a)-1-pass werden sortierte Teile übersprungen Mit n-1 wird das gleiche erreicht
Algorithmen-Komplexität O(n²) Vergleiche/Tausche O(n²) Vergleiche/Tausche
Wann welche Version?
  • Iterativ: Wenn du Speicher sparen willst und Schleifen bevorzugst
  • Rekursiv: Wenn du die Struktur betonen willst oder mit anderen rekursiven Algorithmen arbeitest
  • Praktisch: Bei großen Arrays ist iterativ meist besser (Stack-Overhead)

Der vollständige rekursive Code

Hier ist die komplette Implementierung mit Funktionen und Zeigern:

package main import "fmt" func isGreater(a *[10]int, i int) bool { return a[i] > a[i+1] } func swap(a *[10]int, i int) { a[i], a[i+1] = a[i+1], a[i] } func bubbleSort(a *[10]int, n int) { // Basis-Fall: Array mit 0 oder 1 Element ist sortiert if n <= 1 { return } // Ein Durchlauf: Größtes Element "blasiert" nach oben for i := 0; i < n-1; i++ { if isGreater(a, i) { swap(a, i) } } // Rekursiver Aufruf mit um 1 kleinerem Array bubbleSort(a, n-1) } func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) bubbleSort(&a, len(a)) fmt.Println("Sortiert:", a) }
Aufruf in main:
  • bubbleSort(&a, len(a)) – Adresse des Arrays + Größe
  • Die Funktion ändert das Original direkt
  • Kein Return-Wert nötig
Stack-Trace beim Durchlauf:
  • bubbleSort(&a, 10) → 1 Durchlauf → bubbleSort(&a, 9)
  • bubbleSort(&a, 9) → 1 Durchlauf → bubbleSort(&a, 8)
  • ... (weiter bis n=1)
  • bubbleSort(&a, 1) → Basis-Fall, return

Zusammenfassung: Rekursives Bubble Sort

Du hast jetzt die dritte Variante von Bubble Sort gesehen – und dabei mehrere Programmiertechniken kombiniert:

Gelernte Techniken:
  • ✅ Funktionen: Code-Zerlegung mit isGreater() und swap()
  • ✅ Zeiger: Effiziente Parameter-Übergabe mit Adresse statt Kopie
  • ✅ Rekursion: Basis-Fall + rekursiver Fall
  • ✅ Komplexität: O(n²) Algorithmus-Vergleiche, aber O(1) Memory-Overhead pro Aufruf
