Exkurs: Wie die Laufzeit mit der Datenmenge wächst

Ein Array wird zehnmal so groß. Braucht das Programm dann zehnmal so lange, hundertmal so lange oder fast gleich lange? Die Seite zeigt fünf Antworten als Kurven und zählt bei vier Algorithmen des Kurses die Vergleiche.

Kurstext v3.0.6, Abschnitt 8.4, Seiten 221–226

Worum es geht

Wie lange ein Programm läuft, hängt vom Rechner ab. Wie viele Schritte es macht, hängt nur vom Algorithmus und von der Datenmenge ab. Diese Seite zählt deshalb Schritte. Als Schritt gilt ein Vergleich zweier Werte, zum Beispiel a[i] > a[i+1]. Die Datenmenge ist die Zahl der Elemente im Array und heißt n.

Im Kurstext kommt die Frage an zwei Stellen vor:

  • Abschnitt 8.4.1, Seite 222, binäre Suche: Ein Array mit n Elementen kann nur log₂ n mal halbiert werden. Die Laufzeit wird dort logarithmisch genannt.
  • Abschnitt 8.4.2, Seite 225, Bubblesort: Die Zahl der Vergleiche beträgt n · (n − 1) / 2. Die Laufzeit wird dort quadratisch genannt.

Fünf Kurven

Nach rechts wächst das Array, nach oben wächst die Zahl der Schritte. Jede Kurve ist ausgerechnet, der Ausschnitt reicht bis n = 30 und bis 100 Schritte.

Die Schreibweise O(…) nennt nur, wie die Zahl der Schritte wächst. O(n²) heißt: Wird das Array zehnmal so groß, braucht der Algorithmus etwa hundertmal so viele Schritte. Im Kurstext stehen dafür die Wörter „logarithmisch“ und „quadratisch“.

Vergleiche zählen

Die Seite füllt ein Array mit n gemischten Zahlen und lässt vier Algorithmen wirklich laufen. Jeder Algorithmus zählt seine Vergleiche. Die gezählten Werte erscheinen als Punkte auf der gestrichelten Linie bei n.

Gesucht wird ein Wert, der im Array fehlt. Das ist für beide Suchen der ungünstigste Fall.

Zum Ausprobieren:
  • Achse klein stellen: Bei 100 Vergleichen auf der senkrechten Achse sind nur die flachen Kurven zu sehen. O(n²) hat den Ausschnitt schon bei n = 15 verlassen.
  • Achse groß stellen: Bei 500.000 Vergleichen ist nur O(n²) zu sehen. Die anderen vier Kurven liegen auf der Grundlinie.
  • n verdoppeln: Von n = 100 auf n = 200 bekommt die lineare Suche 100 Vergleiche dazu, die binäre Suche einen, Bubble Sort 14.950.

Woher die Formeln kommen

  • Bubble Sort: Der erste Durchgang vergleicht n − 1 Nachbarn, der zweite n − 2, der letzte einen. Die Summe (n − 1) + (n − 2) + … + 1 ergibt n · (n − 1) / 2. Die Herleitung steht im Kurstext in Abschnitt 8.4.2 auf Seite 225.
  • Selection Sort: Der erste Durchgang sucht das kleinste Element unter n Elementen und braucht dafür n − 1 Vergleiche, der zweite n − 2. Die Summe ist dieselbe wie bei Bubble Sort.
  • Lineare Suche: Fehlt der Wert, sieht die Suche jedes der n Elemente einmal an.
  • Binäre Suche: Jeder Blick in die Mitte halbiert den Rest. Aus 1000 Elementen werden 500, 250, 125, 62, 31, 15, 7, 3, 1. Nach zehn Blicken ist nichts mehr übrig. Das Array muss dafür sortiert sein.

Was die Schreibweise O(…) weglässt

Bubble Sort braucht n · (n − 1) / 2 Vergleiche und heißt trotzdem O(n²). Die Schreibweise lässt zwei Dinge weg:

  • Den festen Faktor: Die Hälfte in n² / 2 ändert nichts daran, dass ein zehnmal so großes Array hundertmal so viele Vergleiche kostet.
  • Den kleineren Summanden: n · (n − 1) / 2 ist n² / 2 − n / 2. Bei n = 1000 sind das 500.000 − 500. Die 500 fallen nicht ins Gewicht.

Drei Feinheiten

  • Gleiche Kurve, verschiedene Arbeit: Bubble Sort und Selection Sort brauchen gleich viele Vergleiche. Bei den Vertauschungen liegen sie weit auseinander. Selection Sort vertauscht höchstens n − 1 mal. Bei Bubble Sort kann die Zahl der Vertauschungen so groß werden wie die Zahl der Vergleiche, so steht es im Kurstext auf Seite 225.
  • Bubble Sort mit Abbruch: Kommt in einem Durchgang keine Vertauschung vor, ist das Array sortiert. Bricht das Programm dann ab, braucht es für ein schon sortiertes Array nur n − 1 Vergleiche. Im Kurstext ist diese Erweiterung auf Seite 226 als Übungsaufgabe gestellt.
  • Kleine Arrays: Die Kurven sagen etwas über große n. Bei n = 4 braucht Bubble Sort 6 Vergleiche, und 4 · log₂ 4 ist 8. Erst ab n = 7 liegt O(n²) über O(n log n).

Die Kurve am Programm erkennen

  • Keine Schleife über das Array: Das Programm braucht gleich viele Schritte für jedes n, also O(1). Beispiel: a[i] = 5.
  • Eine Schleife über das Array: Das Programm braucht O(n) Schritte. Beispiel: die lineare Suche oder die Summe aller Elemente.
  • Zwei geschachtelte Schleifen über das Array: Das Programm braucht O(n²) Schritte. Beispiel: Bubble Sort und Selection Sort.
  • Der Rest wird in jedem Schritt halbiert: Das Programm braucht O(log n) Schritte. Beispiel: die binäre Suche.

In Zeit umgerechnet: Angenommen, ein Rechner schafft eine Milliarde Vergleiche in der Sekunde. Eine Million Elemente sortiert Bubble Sort dann in gut acht Minuten. Ein Verfahren mit O(n log n) braucht dafür zwei Hundertstelsekunden.
