Programmierübung: Sortieren mit Bubble Sort

Zehn Zahlen sollen aufsteigend sortiert werden. Die Übung führt von zehn einzelnen Variablen über ein Array und einen einzelnen Durchgang zu einem Programm mit zwei Schleifen, das jedes Array sortiert.

Kurstext v3.0.6, Kapitel 6, Seiten 151–162. Das Verfahren selbst wird im Kurstext erst in Abschnitt 8.4.2 behandelt.

Worum es geht

Die Aufgabe: Ein Programm bekommt zehn ganze Zahlen und bringt sie in aufsteigende Reihenfolge. Die kleinste Zahl steht am Ende vorn, die größte hinten.

Unsortiert: [42 7 19 88 3 25 71 14 60 9]
Sortiert:   [3 7 9 14 19 25 42 60 71 88]

Die Idee von Bubble Sort

Das Verfahren kennt nur einen einzigen Handgriff: zwei Nachbarn vergleichen und sie tauschen, wenn der linke größer ist als der rechte. Diesen Handgriff wiederholt es so lange, bis alles stimmt.

Der Name kommt vom Bild der Luftblase, englisch bubble: Ein großer Wert steigt Tausch für Tausch nach hinten auf wie eine Blase im Wasser.

Womit das Programm auskommt

  • Array und Index, Kapitel 6: Dazu gibt es die Seite Arrays in Go.
  • for-Anweisung mit for-Klausel, Abschnitt 5.5.3.2: Dazu gibt es die Seite for-Anweisung mit for-Klausel in Go.
  • if-Anweisung, Abschnitt 5.5.1: Dazu gibt es die Seite if-Anweisung in Go.
  • Tupel-Zuweisung, Abschnitt 5.3.2: Mit ihr tauscht man zwei Werte in einer Zeile. Dazu gibt es die Seite Zuweisungen in Go, Schritt 4.

Funktionen braucht das Programm noch nicht. Sie kommen in Kapitel 7 dazu.

Die sechs Schritte

  • Schritt 1, zehn Variablen: Warum es ohne Array nicht geht.
  • Schritt 2, ein Durchgang: Einmal von links nach rechts durch das Array, Vergleich für Vergleich.
  • Schritt 3, drei Durchgänge: Was sich von Durchgang zu Durchgang ändert.
  • Schritt 4, zwei Schleifen: Aus den ausgeschriebenen Durchgängen wird eine äußere Schleife.
  • Schritt 5, das ganze Programm: Zum Kopieren und Ausführen.
  • Schritt 6, Bezug zum Kurstext: Welcher Abschnitt wo vorkommt.

Schritt 1: Zehn Variablen

Der erste Versuch kommt ohne Array aus. Jede Zahl bekommt eine eigene Variable:

package main

import "fmt"

func main() {
    a0, a1, a2, a3, a4 := 42, 7, 19, 88, 3
    a5, a6, a7, a8, a9 := 25, 71, 14, 60, 9
    fmt.Println("Unsortiert:", a0, a1, a2, a3, a4, a5, a6, a7, a8, a9)

    if a0 > a1 {
        a0, a1 = a1, a0
    }
    fmt.Println("Nach einem Tausch:", a0, a1, a2, a3, a4, a5, a6, a7, a8, a9)
}
Unsortiert: 42 7 19 88 3 25 71 14 60 9
Nach einem Tausch: 7 42 19 88 3 25 71 14 60 9

Der Handgriff

Das Programm zeigt den einen Handgriff des Verfahrens. Die Bedingung a0 > a1 fragt, ob die zwei Nachbarn falsch herum stehen. Die Tupel-Zuweisung a0, a1 = a1, a0 tauscht sie dann. Aus 42 und 7 wird 7 und 42.

Wo der Ansatz endet

  • Jeder Vergleich steht einzeln da: Für das nächste Paar braucht es eine neue if-Anweisung mit a1 und a2, dann eine mit a2 und a3. Zum Sortieren von zehn Zahlen sind 45 solche if-Anweisungen nötig.
  • Keine Schleife möglich: Eine Schleife kann nicht von a0 zu a1 weiterzählen. Die Namen sind fest in den Quelltext geschrieben.
  • Jede andere Anzahl ist ein neues Programm: Für elf Zahlen müsste man alles neu schreiben.

Mit einem Array wird aus dem Namen a1 der Index-Ausdruck a[1], und in den eckigen Klammern darf eine Variable stehen.

Kurstext v3.0.6, Kapitel 6, Seite 151: Dort wird das Array mit den sechs Variablen z1 bis z6 der Lottoziehung begründet. Das Programm mit a0 bis a9 ist ein eigenes Beispiel.

Schritt 2: Ein Durchgang

Erst vorhersagen, dann ausprobieren
  1. Die Schleife geht einmal von links nach rechts und tauscht jedes falsch stehende Paar. Wo steht danach die 88, der größte Wert?
    AuflösungGanz hinten, beim Index 9. Sobald die 88 links in einem Paar steht, ist sie größer als ihr Nachbar und wird getauscht. Das wiederholt sich bis zum Ende.
  2. Ist das Array nach einem Durchgang sortiert?
    AuflösungNein. Nur der größte Wert steht an seinem Platz. Die anderen Werte sind höchstens einen Platz nach vorn gerückt.

Aus den zehn Variablen wird ein Array. Der Handgriff aus Schritt 1 steht jetzt in einer Schleife, mit a[i] und a[i+1] für die zwei Nachbarn:

a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9}

for i := 0; i < len(a)-1; i++ {
    if a[i] > a[i+1] {
        a[i], a[i+1] = a[i+1], a[i]
    }
}
fmt.Println(a)

Warum die Schleife bei len(a)-1 endet

Der Rumpf greift auf a[i+1] zu. Das letzte Element hat keinen rechten Nachbarn. Der größte Index, mit dem der Rumpf laufen darf, ist deshalb 8: Dann ist a[i] das Element 8 und a[i+1] das Element 9. Mit der Bedingung i < len(a) würde das Programm bei i gleich 9 auf a[10] zugreifen und abbrechen.

Ausprobieren: der erste Durchgang

    Diese zwei Nachbarn hat das Programm verglichen und gelassen.Diese zwei Nachbarn hat es getauscht.Dieser Wert steht an seinem Platz.

    Das Programm ist ein eigenes Beispiel. Der Index-Ausdruck und len werden im Kurstext in Abschnitt 6.1 behandelt, Seiten 154–155.

    Schritt 3: Drei Durchgänge

    Ein Durchgang bringt einen Wert an seinen Platz. Also wiederholen wir den Durchgang. Zuerst schreiben wir drei Durchgänge einzeln aus und geben das Array nach jedem aus:

    a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9}
fmt.Println("Start:", a)

// Durchgang 1
for i := 0; i < len(a)-1; i++ {
    if a[i] > a[i+1] {
        a[i], a[i+1] = a[i+1], a[i]
    }
}
fmt.Println("Nach Durchgang 1:", a)

// Durchgang 2
for i := 0; i < len(a)-2; i++ {
    if a[i] > a[i+1] {
        a[i], a[i+1] = a[i+1], a[i]
    }
}
fmt.Println("Nach Durchgang 2:", a)

// Durchgang 3
for i := 0; i < len(a)-3; i++ {
    if a[i] > a[i+1] {
        a[i], a[i+1] = a[i+1], a[i]
    }
}
fmt.Println("Nach Durchgang 3:", a)
    Start: [42 7 19 88 3 25 71 14 60 9]
Nach Durchgang 1: [7 19 42 3 25 71 14 60 9 88]
Nach Durchgang 2: [7 19 3 25 42 14 60 9 71 88]
Nach Durchgang 3: [7 3 19 25 14 42 9 60 71 88]

    Was man an der Ausgabe sieht

    • Hinten wächst der sortierte Teil: Nach Durchgang 1 steht die 88 am Ende, nach Durchgang 2 stehen 71 und 88 dort, nach Durchgang 3 sind es 60, 71 und 88.
    • Vorn rücken kleine Werte langsam vor: Die 3 steht am Anfang beim Index 4. Sie rückt in jedem Durchgang nur einen Platz nach vorn.

    Was sich von Durchgang zu Durchgang ändert

    Die drei Schleifen sind fast gleich. Nur die Bedingung unterscheidet sich: len(a)-1, dann len(a)-2, dann len(a)-3. Jeder Durchgang darf einen Vergleich früher aufhören, denn die Werte am Ende stehen schon richtig.

    Dreimal fast der gleiche Code hintereinander: Das ist die Stelle, an der eine Schleife fehlt.

    Das Programm ist ein eigenes Beispiel.

    Schritt 4: Zwei Schleifen

    Erst vorhersagen, dann ausprobieren
    1. Wie viele Durchgänge braucht ein Array mit zehn Elementen höchstens?
      AuflösungNeun. Jeder Durchgang bringt einen Wert an seinen Platz. Stehen neun Werte richtig, steht der zehnte von selbst richtig.

    Eine äußere Schleife zählt die Durchgänge. Ihre Laufvariable durchgang beginnt bei 0 und steht in der Bedingung der inneren Schleife:

    for durchgang := 0; durchgang < len(a)-1; durchgang++ {
    for i := 0; i < len(a)-1-durchgang; i++ {
        if a[i] > a[i+1] {
            a[i], a[i+1] = a[i+1], a[i]
        }
    }
    fmt.Printf("Nach Durchgang %d: %v\n", durchgang+1, a)
}
    • Die äußere Schleife: Sie läuft len(a)-1 mal, bei zehn Elementen also neunmal.
    • Die innere Schleife: Sie ist der Durchgang aus Schritt 2. Aus len(a)-1, len(a)-2 und len(a)-3 in Schritt 3 ist len(a)-1-durchgang geworden.
    • Die Ausgabe: durchgang zählt ab 0. Für den Menschen zählt die Ausgabe ab 1, deshalb steht dort durchgang+1.

    Ausprobieren: das ganze Sortieren

      Diese zwei Nachbarn hat das Programm verglichen und gelassen.Diese zwei Nachbarn hat es getauscht.Diese Werte stehen an ihrem Platz.

      Ausgabe des Programms:

      Wie viel Arbeit das ist

      Der erste Durchgang vergleicht neun Paare, der zweite acht, der letzte eines. Zusammen sind das 9 + 8 + … + 1 = 45 Vergleiche. Für n Elemente sind es n · (n − 1) / 2. Bei doppelt so vielen Elementen braucht das Verfahren also etwa viermal so viele Vergleiche. Mehr dazu steht im Exkurs: Wie die Laufzeit mit der Datenmenge wächst.

      Das Programm ist ein eigenes Beispiel. Die Zahl der Vergleiche wird im Kurstext in Abschnitt 8.4.2 auf den Seiten 225–226 genannt.
