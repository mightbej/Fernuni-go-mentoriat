Programmierübung: Sortieren mit Selection Sort

Die gleichen zehn Zahlen wie bei Bubble Sort, ein anderes Verfahren: erst das kleinste Element suchen, dann mit einem einzigen Tausch an seinen Platz bringen. Die Übung führt von der Suche nach dem Minimum zu einem Programm mit zwei Schleifen.

Kurstext v3.0.6, Kapitel 6, Seiten 151–162. Selection Sort selbst kommt im Kurstext nicht vor.

Worum es geht

Die Aufgabe ist die gleiche wie in der Programmierübung zu Bubble Sort: Zehn ganze Zahlen sollen aufsteigend sortiert werden.

Start:    [42 7 19 88 3 25 71 14 60 9]
Sortiert: [3 7 9 14 19 25 42 60 71 88]

Bubble Sort tauscht Nachbarn, sobald sie falsch stehen. Das führt zu vielen kleinen Tauschen: Für diese zehn Zahlen sind es 23.

Selection Sort geht anders vor. Der Name sagt es: selection heißt Auswahl. Das Verfahren wählt erst aus und tauscht dann. Es sucht das kleinste Element und bringt es mit einem einzigen Tausch nach vorn. Für die zehn Zahlen braucht es 7 Tausche.

Womit das Programm auskommt

  • Array und Index, Kapitel 6: Dazu gibt es die Seite Arrays in Go.
  • for-Anweisung mit for-Klausel, Abschnitt 5.5.3.2: Dazu gibt es die Seite for-Anweisung mit for-Klausel in Go.
  • if-Anweisung, Abschnitt 5.5.1: Dazu gibt es die Seite if-Anweisung in Go.
  • Tupel-Zuweisung, Abschnitt 5.3.2: Dazu gibt es die Seite Zuweisungen in Go, Schritt 4.

Funktionen, Slices und Rekursion braucht das Programm nicht.

Die sieben Schritte

  • Schritt 1, die Idee: Links der sortierte Teil, rechts der Rest.
  • Schritt 2, das Minimum suchen: Eine Schleife findet den Index des kleinsten Werts.
  • Schritt 3, eine Runde: Suchen und danach einmal tauschen.
  • Schritt 4, zwei Schleifen: Die Runde wiederholt sich für jede Stelle des Arrays.
  • Schritt 5, das ganze Programm: Zum Kopieren und Ausführen.
  • Schritt 6, Vergleich mit Bubble Sort: Was die zwei Verfahren unterscheidet.
  • Schritt 7, Bezug zum Kurstext: Welcher Abschnitt wo vorkommt.

Schritt 1: Die Idee

Selection Sort baut das sortierte Array von links nach rechts auf. Links steht der Teil, der schon sortiert ist. Rechts steht der Rest, der noch nicht sortiert ist. Am Anfang ist der linke Teil leer.

Eine Runde

  1. Nimm die erste Stelle des Rests. Sie heißt im Programm pos.
  2. Suche im Rest, also von pos bis zum Ende, das kleinste Element.
  3. Tausche dieses Element mit dem Element an der Stelle pos.

Danach steht an der Stelle pos der richtige Wert. Der sortierte Teil ist um ein Element gewachsen, der Rest um eines geschrumpft.

Die ersten drei Runden

Start:    [42 7 19 88 3 25 71 14 60 9]

Runde 1:  Der kleinste Wert ist 3. Er wird mit der 42 an der Stelle 0 getauscht.
          [3 7 19 88 42 25 71 14 60 9]

Runde 2:  Der kleinste Wert im Rest ist 7. Er steht schon an der Stelle 1.
          [3 7 19 88 42 25 71 14 60 9]

Runde 3:  Der kleinste Wert im Rest ist 9. Er wird mit der 19 an der Stelle 2 getauscht.
          [3 7 9 88 42 25 71 14 60 19]

Zwei Aufgaben für das Programm

  • Suchen: Das Programm muss wissen, wo der kleinste Wert steht. Dafür merkt es sich seinen Index. Das ist Schritt 2.
  • Wiederholen: Die Runde läuft für pos gleich 0, dann 1, dann 2 und so weiter. Das ist Schritt 4.

Schritt 2: Das Minimum suchen

Erst vorhersagen, dann ausprobieren
  1. Die Schleife unten läuft über das ganze Array. Wie oft bekommt minIndex einen neuen Wert?
    AuflösungZweimal: bei der 7 mit dem Index 1 und bei der 3 mit dem Index 4. Danach ist kein Element mehr kleiner als 3.

Bevor wir sortieren, lösen wir die kleinere Aufgabe: den kleinsten Wert eines Arrays finden.

a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9}

minIndex := 0
for i := 1; i < len(a); i++ {
    if a[i] < a[minIndex] {
        minIndex = i
    }
}
fmt.Println("Index des kleinsten Werts:", minIndex)    // 4
fmt.Println("Kleinster Wert:", a[minIndex])            // 3

Der Kandidat

Die Variable minIndex ist der Kandidat: der Index des kleinsten Werts, den das Programm bisher gesehen hat. Am Anfang kennt es nur das erste Element, also ist der Kandidat der Index 0.

Die Schleife beginnt bei 1 und vergleicht jedes weitere Element mit dem Kandidaten. Ist a[i] kleiner als a[minIndex], wird i der neue Kandidat.

minIndex enthält den Index des kleinsten Werts und nicht den Wert selbst. Den Wert liefert a[minIndex]. Das Programm braucht den Index, weil es später an dieser Stelle tauschen will.

Ausprobieren: die Suche Vergleich für Vergleich

    Dieses Element wird gerade mit dem Kandidaten verglichen.Hier steht der Kandidat, das kleinste Element bisher.

    Das Programm ist ein eigenes Beispiel. Seit Go 1.21 gibt es eine eingebaute Funktion min. Die Variable heißt deshalb minIndex und nicht min.

    Schritt 3: Eine Runde

    Zur Suche kommt jetzt der Tausch. Und die Suche beginnt nicht mehr fest beim Index 0, sondern bei der Stelle pos:

    a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9}
fmt.Println("Start:", a)

pos := 0
minIndex := pos
for i := pos + 1; i < len(a); i++ {
    if a[i] < a[minIndex] {
        minIndex = i
    }
}
a[pos], a[minIndex] = a[minIndex], a[pos]
fmt.Println("Nach Runde 1:", a)
    Start: [42 7 19 88 3 25 71 14 60 9]
Nach Runde 1: [3 7 19 88 42 25 71 14 60 9]
    • minIndex := pos: Der erste Kandidat ist das Element an der Stelle pos.
    • i := pos + 1: Die Suche beginnt beim Element rechts davon. Die Elemente links von pos sind sortiert und werden nicht mehr angefasst.
    • Der Tausch nach der Schleife: Das kleinste Element des Rests und das Element an der Stelle pos wechseln ihre Plätze.

    Erst suchen, dann tauschen: Die Schleife ändert das Array nicht. Sie entscheidet nur. Getauscht wird ein einziges Mal, wenn die Entscheidung feststeht.

    Die zweite Runde

    Für die zweite Runde wiederholt sich alles mit pos gleich 1:

    pos = 1
minIndex = pos
for i := pos + 1; i < len(a); i++ {
    if a[i] < a[minIndex] {
        minIndex = i
    }
}
a[pos], a[minIndex] = a[minIndex], a[pos]
fmt.Println("Nach Runde 2:", a)    // [3 7 19 88 42 25 71 14 60 9]

    Die zwei Runden unterscheiden sich in einer einzigen Zahl: dem Wert von pos. Daraus wird in Schritt 4 die äußere Schleife.

    In Runde 2 steht der kleinste Wert des Rests, die 7, schon an der Stelle 1. Dann ist minIndex gleich pos, und das Programm tauscht das Element mit sich selbst. Das ist erlaubt und ändert nichts.

    Das Programm ist ein eigenes Beispiel.

    Schritt 4: Zwei Schleifen

    Erst vorhersagen, dann ausprobieren
    1. Die äußere Schleife läuft bis pos < len(a)-1. Warum braucht die letzte Stelle keine eigene Runde?
      AuflösungStehen die neun kleinsten Werte an ihrem Platz, bleibt für die letzte Stelle nur der größte Wert übrig. Er steht von selbst richtig.

    Eine äußere Schleife zählt pos von 0 an hoch. Ihr Rumpf ist die Runde aus Schritt 3:

    for pos := 0; pos < len(a)-1; pos++ {
    minIndex := pos
    for i := pos + 1; i < len(a); i++ {
        if a[i] < a[minIndex] {
            minIndex = i
        }
    }
    if minIndex != pos {
        a[pos], a[minIndex] = a[minIndex], a[pos]
    }
    fmt.Printf("Nach Runde %d: %v\n", pos+1, a)
}
    • Die äußere Schleife: Sie legt die Stelle fest, die in dieser Runde ihren Wert bekommt.
    • Die innere Schleife: Sie sucht im Rest ab pos + 1 den kleinsten Wert.
    • if minIndex != pos: Steht der kleinste Wert schon an der Stelle pos, spart sich das Programm den Tausch.

        Schritt 6: Vergleich mit Bubble Sort

        Beide Verfahren arbeiten mit den gleichen Mitteln: Array, Index, zwei verschachtelte Schleifen, ein Vergleich, ein Tausch. Sie setzen sie verschieden ein.

        FrageBubble SortSelection Sort
        Was vergleicht das Verfahren?Es vergleicht zwei Nachbarn: a[i] und a[i+1].Es vergleicht ein Element mit dem Kandidaten: a[i] und a[minIndex].
        Wann tauscht es?Es tauscht sofort, wenn zwei Nachbarn falsch stehen.Es tauscht einmal am Ende der Runde.
        Wo wächst der sortierte Teil?Er wächst hinten: Der größte Wert wandert nach rechts.Er wächst vorn: Der kleinste Wert kommt nach links.
        Wie viele Vergleiche braucht es für die zehn Zahlen?Es braucht 45 Vergleiche.Es braucht 45 Vergleiche.
        Wie viele Tausche braucht es für die zehn Zahlen?Es braucht 23 Tausche.Es braucht 7 Tausche.

        Gleich viele Vergleiche

        Beide Verfahren vergleichen in der ersten Runde neunmal, in der zweiten achtmal, in der letzten einmal. Das sind 9 + 8 + … + 1 = 45 Vergleiche, für n Elemente n · (n − 1) / 2. Bei doppelt so vielen Elementen sind es etwa viermal so viele. Für große Datenmengen sind beide Verfahren deshalb zu langsam. Mehr dazu steht im Exkurs: Wie die Laufzeit mit der Datenmenge wächst.

        Viel weniger Tausche

        Selection Sort tauscht höchstens einmal je Runde, bei zehn Elementen also höchstens neunmal. Bubble Sort kann in jeder Runde bei jedem Vergleich tauschen. Das zählt, wenn ein Tausch teuer ist, zum Beispiel bei großen Elementen.

        Kein Vorteil bei einem sortierten Array

        Selection Sort sucht in jeder Runde den ganzen Rest ab, auch wenn das Array schon sortiert ist. Es braucht immer alle 45 Vergleiche.

        Wie es weitergeht

        • Mit Funktionen: In Kapitel 7 wird das gleiche Programm in Funktionen zerlegt: Selection Sort mit Funktionen.
        • Schnellere Verfahren: Verfahren wie Quicksort und Mergesort kommen mit viel weniger Vergleichen aus. Sie brauchen Funktionen und meist Rekursion. Im Kurstext werden sie nicht behandelt.

        Die Zahl der Vergleiche von Bubblesort steht im Kurstext in Abschnitt 8.4.2, Seiten 225–226. Der Vergleich der zwei Verfahren und die Zahlen 23 und 7 stehen dort nicht.

        Selection Sort kommt im Kurstext nicht vor. Das einzige Sortierverfahren dort ist Bubblesort in Abschnitt 8.4.2. Die Übung ist eine Ergänzung des Mentors: Sie zeigt an einem zweiten Verfahren, dass man die gleiche Aufgabe mit den gleichen Mitteln auf verschiedene Weise lösen kann.
