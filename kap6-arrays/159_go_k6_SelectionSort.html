Einordnung: Bubble Sort und Selection Sort

Bubble Sort und Selection Sort verwenden dieselben Grundmittel: Array, Indizes, Schleifen, Vergleiche und Tauschen.

Bubble Sort Selection Sort
Vergleicht benachbarte Werte: a[i] und a[i+1] Sucht im Rest des Arrays den kleinsten Wert
Viele kleine Tausche innerhalb einer Runde Hoestens ein gezielter Tausch pro Runde
Der groesste Wert wandert nach rechts Der kleinste Wert wird nach links gestellt
Didaktischer Zweck: Selection Sort zeigt eine neue Denkfigur: Nicht sofort tauschen, sondern zuerst den besten Kandidaten suchen und danach gezielt platzieren.

Grundidee von Selection Sort

Das Array wird von links nach rechts aufgebaut. Links entsteht der sortierte Bereich, rechts bleibt der noch unsortierte Bereich.

Prinzip pro Runde:
  1. Waehle eine Position pos.
  2. Suche im Bereich von pos bis zum Ende das kleinste Element.
  3. Tausche dieses kleinste Element nach pos.
Start: [42 7 19 88 3 25 71 14 60 9] Runde 1: kleinster Wert ist 3 -> nach Position 0 Ergebnis: [3 7 19 88 42 25 71 14 60 9] Runde 2: kleinster Wert im Rest ist 7 -> bleibt auf Position 1 Ergebnis: [3 7 19 88 42 25 71 14 60 9]

Neue Begriffe

pos = Zielposition
min = Index des Minimums
unsortierter Rest
gezielter Tausch

Stufe 1: Minimum im Array suchen

Zuerst suchen wir nur den Index des kleinsten Werts im gesamten Array.

package main import "fmt" func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} min := 0 for i := 1; i < len(a); i++ { if a[i] < a[min] { min = i } } fmt.Println("Array:", a) fmt.Println("Index des kleinsten Werts:", min) fmt.Println("Kleinster Wert:", a[min]) }
Wichtig: min speichert nicht den kleinsten Wert selbst, sondern den Index, an dem der kleinste Wert steht.

Stufe 2: Kleinsten Wert nach vorne tauschen

Nach der Suche wird das gefundene Minimum an die erste Position getauscht.

package main import "fmt" func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) pos := 0 min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } a[pos], a[min] = a[min], a[pos] fmt.Println("Nach einem gezielten Tausch:", a) }
Merksatz: Erst suchen, dann tauschen. Selection Sort trennt Entscheidung und Aktion.

Stufe 3: Mehrere Runden sichtbar machen

Jetzt wiederholen wir dieselbe Logik fuer jede Zielposition. Nach jeder Runde wird der linke Bereich groesser.

package main import "fmt" func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) // Runde 1: kleinsten Wert nach Position 0 pos := 0 min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } a[pos], a[min] = a[min], a[pos] fmt.Println("Nach Runde 1:", a) // Runde 2: kleinsten Wert im Rest nach Position 1 pos = 1 min = pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } a[pos], a[min] = a[min], a[pos] fmt.Println("Nach Runde 2:", a) }
Beobachtung: Die Runden sind fast identisch. Nur pos aendert sich. Genau daraus entsteht die aeussere Schleife.

Vollstaendiger Code: Selection Sort

Die aeussere Schleife legt die Zielposition fest. Die innere Schleife sucht das Minimum im noch unsortierten Rest.

package main import "fmt" func main() { a := [10]int{42, 7, 19, 88, 3, 25, 71, 14, 60, 9} fmt.Println("Start:", a) for pos := 0; pos < len(a)-1; pos++ { min := pos for i := pos + 1; i < len(a); i++ { if a[i] < a[min] { min = i } } if min != pos { a[pos], a[min] = a[min], a[pos] } fmt.Printf("Nach Runde %d: %v\n", pos+1, a) } fmt.Println("Sortiert:", a) }

Vergleich: Bubble Sort vs. Selection Sort

Aspekt Bubble Sort Selection Sort
Grundidee Nachbarn vergleichen und tauschen Minimum suchen und nach vorne tauschen
Sortierter Bereich Waechst von rechts Waechst von links
Tauschverhalten Viele kleine Tausche moeglich Maximal ein Tausch pro Runde
Didaktischer Schwerpunkt Nachbarschaft, Indexgrenzen, Passes Minimumssuche, Kandidat, gezielte Platzierung
Didaktische Reihenfolge: Erst Bubble Sort, dann Selection Sort. So wird sichtbar, dass Sortieren nicht nur eine Technik ist, sondern eine Familie unterschiedlicher Strategien.

Metainformation: Was man ueber Selection Sort wissen sollte

Eigenschaft Einordnung
Laufzeit O(n²), weil fuer viele Positionen der restliche Bereich durchsucht wird.
Best Case Auch bei bereits sortiertem Array bleibt die Laufzeit O(n²), weil trotzdem gesucht wird.
Worst Case O(n²), zum Beispiel bei umgekehrter Sortierung.
Speicherbedarf O(1), weil direkt im Array sortiert wird und kein weiteres Array gebraucht wird.
Stabilitaet In der einfachen Form nicht stabil: gleiche Werte koennen ihre relative Reihenfolge verlieren.
Staerke Wenige Tausche: maximal ein Tausch pro Runde.
Schwaeche Viele Vergleiche, auch wenn das Array schon fast sortiert ist.
Praxisrelevanz Fuer grosse Datenmengen ungeeignet. Als Lernalgorithmus aber sehr nuetzlich.
Nicht beschönigen: Selection Sort ist einfach zu verstehen, aber algorithmisch schwach. Die Laufzeit wird bei groesseren Arrays schnell schlecht.
