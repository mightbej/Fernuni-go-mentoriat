break-Anweisung in Go

Die Anweisung break verlässt eine Schleife sofort, mitten im Schleifenrumpf. Die Seite führt das Programm zur Fakultät aus dem Kurstext Anweisung für Anweisung aus und zeigt, wie die gleiche Schleife ohne break auskommt.

Kurstext v3.0.6, Abschnitt 5.5.3.3, Seiten 146–149.

Worum es geht

Eine Schleife endet, wenn ihre Schleifenbedingung false ergibt. Geprüft wird die Bedingung aber nur vor einem Schleifendurchlauf. Manchmal stellt ein Programm mitten im Schleifenrumpf fest, dass Weitermachen keinen Sinn hat.

Dafür gibt es die break-Anweisung. Sie besteht nur aus dem Schlüsselwort break:

for k := 1; k <= 5; k++ {
    if k == 3 {
        break
    }
    fmt.Print(k, " ")
}

Das Programm gibt 1 2 aus. Beim dritten Schleifendurchlauf verlässt break die Schleife, bevor die 3 ausgegeben wird.

Fakultät und Überlauf

Das Programm des Kurstexts berechnet zu einer natürlichen Zahl n ihre Fakultät n!.

  • Die Fakultät: das Produkt aller ganzen Zahlen von 1 bis n. Beispiel: 5! = 1 · 2 · 3 · 4 · 5 = 120.
  • Der Sonderfall: 0! ist als 1 festgelegt.

Eine Schleife rechnet das Produkt Faktor für Faktor aus. Die Variable fak beginnt mit 1 und wird in jedem Schleifendurchlauf mit der Laufvariable i multipliziert:

fak := 1
for i := 1; i <= eingabe; i++ {
    fak *= i
}

Das Problem: die Fakultät wächst sehr schnell

Der Typ int hat auf den üblichen Rechnern 64 Bit. Sein größter Wert steht in der Konstante math.MaxInt und ist 9223372036854775807. Schon 21! ist größer.

Rechnet das Programm trotzdem weiter, kommt es zum arithmetischen Überlauf: Go meldet keinen Fehler und liefert einen falschen Wert.

Die Prüfung vor der Multiplikation

Ob fak * i noch in den Typ passt, lässt sich nicht am Ergebnis ablesen, denn das Ergebnis ist dann schon falsch. Das Programm prüft deshalb vorher, mit einer Division:

if math.MaxInt/fak >= i {
    fak *= i
}

Der Gedanke dahinter: math.MaxInt/fak sagt, wie oft fak in den größten Wert hineinpasst. Ist diese Zahl mindestens so groß wie i, dann ist fak * i höchstens math.MaxInt.

Ausprobieren: die Prüfung für einen Schleifendurchlauf

Schleifendurchlauf mit i gleich:
fak vor der Multiplikation math.MaxInt/fak math.MaxInt/fak >= i fak * i

Die Division math.MaxInt/fak ist eine Division ganzer Zahlen. Die Nachkommastellen fallen weg.

break im Lauf

Ergibt die Prüfung aus Schritt 1 false, meldet das Programm den Überlauf. Danach soll die Schleife enden, sonst käme in jedem weiteren Schleifendurchlauf die gleiche Meldung. Das erledigt break.

Die break-Anweisung im Schleifenrumpf einer for-Anweisung bewirkt zweierlei:

  • Der Schleifenrumpf wird sofort verlassen. Was im Schleifenrumpf noch folgt, läuft nicht mehr.
  • Die for-Anweisung ist sofort zu Ende. Auch die Post-Anweisung läuft nicht mehr, und die Schleifenbedingung wird nicht mehr geprüft.

    Wozu die Variable überlauf dient

    Hinter der Schleife weiß das Programm zunächst nicht, auf welchem Weg es dorthin gekommen ist:

    • Regulär: Die Schleifenbedingung i <= eingabe ergab false. Dann steht in fak die Fakultät.
    • Vorzeitig: break hat die Schleife verlassen. Dann steht in fak ein Zwischenergebnis.

    Die Flag-Variable überlauf hält den Unterschied fest. Sie beginnt mit false, und Zeile 25 setzt sie vor dem break auf true. Zeile 29 fragt sie ab.

    Zwei Stellen im Programm

    • Eingabe 0: Die Schleifenbedingung 1 <= 0 ergibt schon bei der ersten Prüfung false. Der Schleifenrumpf läuft nie. Weil fak mit 1 beginnt, stimmt das Ergebnis trotzdem: 0! = 1.
    • Negative Eingabe: Zeile 15 fängt sie ab. Die Fakultät ist nur für natürliche Zahlen erklärt.

    Ohne break

    Im Kurstext steht break in Listing 5.7, um die Anweisung an einem Beispiel zu zeigen. Die bessere Lösung kommt ohne break aus: Die Flag-Variable überlauf wandert in die Schleifenbedingung.

    for i := 1; i <= eingabe && !überlauf; i++ {
    // Schleifenrumpf wie zuvor, aber ohne break
}

    Die neue Schleifenbedingung hat zwei Teile, verknüpft mit &&, dem Operator für „und“:

    • i <= eingabe: die alte Bedingung. Es sind noch Faktoren übrig.
    • !überlauf: Das Ausrufezeichen kehrt den Wahrheitswert um. Der Ausdruck ist true, solange noch kein Überlauf festgestellt wurde.

    Die Schleife läuft nur weiter, wenn beide Teile true ergeben.

    Vergleich: was nach dem Überlauf geschieht

    Die Eingabe ist 25. Im Schleifendurchlauf mit i gleich 21 ergibt die Prüfung false.

    Wann break passt
    
    
    Eine Schleife mit break zu verlassen gilt oft als schlechter Programmierstil. Der Grund:
    
    
      
      
    • Ohne break entscheidet allein die Schleifenbedingung, wann die Schleife endet. Wer den Kopf der Schleife liest, weiß Bescheid.
      • 
      
    • Mit break stimmt das nicht mehr. Irgendwo im Schleifenrumpf kann ein break stehen, das unter einer ganz anderen Bedingung zuschlägt. Der Leser muss den ganzen Schleifenrumpf durchsuchen.
      • 
    
    
    
    Die Regel im Kurstext lautet deshalb: Eine Schleife soll möglichst ohne break auskommen.
    

    
    Wann break trotzdem in Ordnung ist
    
    
      
      
    • Hinter dem Grund für den Abbruch folgen noch Anweisungen im Schleifenrumpf, die dann nicht mehr laufen sollen. Ohne break bräuchte man mehrere Flag-Variablen und if-Anweisungen, und der Code würde unübersichtlicher als mit break.
      • 
      
    • In Listing 5.7 ist das anders: Hinter dem Überlauf ist der Schleifenrumpf ohnehin zu Ende. Deshalb ist dort das Programm aus Schritt 3 das bessere.
      • 
    
    
    
    Wer eine Schleife aus gutem Grund mit break baut, schreibt das in einen Kommentar an den Anfang der Schleife.
    

    
    Ausprobieren: was break verlässt
    
    
    break ist nur in einer Schleife und in einer switch-Anweisung erlaubt. Es verlässt immer nur die innerste Schleife oder switch-Anweisung, in der es steht.
