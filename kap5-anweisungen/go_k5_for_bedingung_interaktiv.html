for-Anweisung mit Bedingung in Go

Eine Schleife wiederholt einen Block, solange eine Bedingung erfüllt ist. Die Seite führt drei Programme Anweisung für Anweisung aus, darunter das Programm zur wiederholten Eingabe aus dem Kurstext.

Kurstext v3.0.6, Abschnitt 5.5.3.1, Seiten 138–142.

Worum es geht

Ein Programm soll oft dasselbe mehrmals tun: Zahlen einlesen, bis der Benutzer aufhört, oder rechnen, bis ein Ergebnis feststeht. Dafür gibt es die Wiederholungsanweisung, kurz Schleife, englisch loop statement.

In Go beginnt jede Schleife mit dem Schlüsselwort for. Die einfachste Form besteht aus einer Bedingung und einem Block:

for n > 0 {
    fmt.Println(n)
    n--
}

Sie heißt for-Anweisung mit Bedingung, englisch for statement with condition.

Die drei Arten der for-Anweisung

  • Mit Bedingung: Die Schleife läuft, solange die Bedingung erfüllt ist. Diese Art wird in Abschnitt 5.5.3.1 behandelt und ist das Thema dieser Seite.
  • Mit for-Klausel: Die Schleife zählt mit einer Laufvariable, zum Beispiel for i := 1; i <= 10; i++. Diese Art wird in Abschnitt 5.5.3.2 behandelt, Seiten 142–146. Dazu gibt es die Seite for-Anweisung mit for-Klausel.
  • Mit range: Die Schleife geht alle Elemente eines Arrays durch. Diese Art wird erst in Abschnitt 6.2 bei den Arrays behandelt.

Bedingung und Rumpf

Jede Schleife hat zwei Teile:

  • Schleifenbedingung: ein boolescher Ausdruck hinter for, zum Beispiel n > 0.
  • Schleifenrumpf: der Block zwischen { und }. Er wird wiederholt, solange die Schleifenbedingung erfüllt ist.

Dazu kommen drei Begriffe:

  • Schleifendurchlauf: Der Schleifenrumpf wird einmal ganz ausgeführt.
  • Abbruchbedingung: das Gegenteil der Schleifenbedingung. Zur Schleifenbedingung n > 0 gehört die Abbruchbedingung n <= 0. Sobald sie erfüllt ist, endet die Schleife.
  • Endlosschleife: Die Abbruchbedingung wird nie erfüllt. Die Schleife läuft immer weiter.

Wann die Bedingung geprüft wird

Go wertet die Schleifenbedingung vor jedem Schleifendurchlauf aus, auch vor dem ersten.

  • Ergebnis true: Der Schleifenrumpf wird ausgeführt. Danach wertet Go die Bedingung erneut aus.
  • Ergebnis false: Die Schleife ist zu Ende. Das Programm macht hinter } weiter.

Ergibt die Bedingung schon vor dem ersten Schleifendurchlauf false, wird der Schleifenrumpf kein einziges Mal ausgeführt.

      Mindestens ein Durchlauf
      
    
      Die for-Anweisung mit Bedingung prüft, bevor sie den Schleifenrumpf ausführt. Manche Sprachen haben dazu eine zweite Schleife, die erst nach dem Schleifenrumpf prüft. Ihr Schleifenrumpf läuft deshalb mindestens einmal.
      
    
        
      
      • do-while-Schleife in Java und C++: Erst kommt der Schleifenrumpf, dann while mit der Schleifenbedingung. Die Schleife endet, wenn die Bedingung nicht mehr zutrifft.
        • 
      
      • repeat-until-Schleife in Pascal: Erst kommt der Schleifenrumpf, dann until mit der Bedingung. Die Schleife endet, wenn die Bedingung zutrifft. Die Bedingung ist also umgekehrt formuliert.
        • 
    
      
    
      Die wiederholte Eingabe als do-while-Schleife in Java:
      

      do {
    System.out.println("Bitte eine positive Zahl eingeben (0 zum Beenden):");
    eingabe = scanner.nextDouble();
} while (eingabe != 0);
      
    
      Dieselbe Schleife als repeat-until-Schleife in Pascal:
      

      repeat
    writeln('Bitte eine positive Zahl eingeben (0 zum Beenden):');
    readln(eingabe);
until eingabe = 0;
      
    
      Go hat keine dieser zwei Schleifen. Sie fehlen mit Absicht: Code in Go soll einheitlich aussehen, und jede do-while-Schleife lässt sich mit einer while-Schleife nachbauen.
      

    
      Der Nachbau mit einer Flag-Variable
      
    
      Eine zusätzliche Variable vom Typ bool erzwingt den ersten Schleifendurchlauf. Eine boolesche Variable, die so einen Zustand festhält, heißt auf Englisch flag.
      
    
        
      
      • Vor der Schleife: ersterLauf hat den Wert true.
        • 
      
      • In der Schleifenbedingung: ersterLauf || eingabe != 0. Der Operator || bedeutet „oder“. Solange ersterLauf den Wert true hat, ist die Bedingung erfüllt.
        • 
      
      • Im Schleifenrumpf: ersterLauf bekommt den Wert false. Ab der zweiten Prüfung entscheidet nur noch eingabe != 0.
        •

        Der schlechtere Weg: den Rumpf kopieren
        
    
        Man kann die Anweisungen des Schleifenrumpfs auch einmal vor die Schleife schreiben:
        

        fmt.Println("Bitte eine positive Zahl eingeben (0 zum Beenden):")
fmt.Scan(&eingabe)

for eingabe != 0 {
    fmt.Println("Bitte eine positive Zahl eingeben (0 zum Beenden):")
    fmt.Scan(&eingabe)
}
        
    
        Das Programm läuft richtig. Trotzdem gilt es als schlechter Stil, Code zu kopieren: Wer später die Aufforderung ändert, muss an beide Stellen denken.

        Aus der Praxis
        
    
        Die Faustregeln in diesem Schritt stammen vom Mentor. Sie stehen nicht in Abschnitt 5.5.3.1 des Kurstexts. Go übersetzt jedes Beispiel, auch die drei mit dem Kommentar „falsch“.
        

    
        1. Der Rumpf ändert, was die Bedingung prüft
        

        var x int = 10
for x > 0 {
    fmt.Println(x)   // falsch: x bleibt 10, die Schleife endet nie
}
        
    
        Die Bedingung x > 0 kann nur dann einmal false ergeben, wenn der Schleifenrumpf den Wert von x ändert. Hier fehlt x--.
        
    
        Die Prüffrage beim Schreiben einer Schleife: Welche Anweisung im Schleifenrumpf sorgt dafür, dass die Bedingung irgendwann false ergibt? Gibt es keine, ist es eine Endlosschleife.
        

    
        2. Die Bedingung fängt auch den Wert ab, der das Ziel überspringt
        

        n := 5
for n != 0 {   // falsch: n wird 3, 1, -1, -3 … und nie 0
    n -= 2
}
        

        n := 5
for n > 0 {    // endet: n wird 3, 1, -1
    n -= 2
}
        
    
        Die erste Fassung wartet auf genau einen Wert, die 0. Mit Schritten von 2 springt n von 1 auf −1 und trifft die 0 nicht.
        
    
        Die zweite Fassung endet bei jedem Wert, der nicht mehr größer als 0 ist. Wer herunterzählt, vergleicht deshalb mit > und nicht mit !=.
        

    
        3. Eine errechnete Kommazahl nicht mit != prüfen
        

        x := 0.0
for x != 1.0 {   // falsch: x trifft 1.0 nie genau
    x += 0.1
}
        
    
        Zehnmal 0.1 addiert ergibt in Go nicht 1.0. Nach zehn Schleifendurchläufen hat x den Wert 0.9999999999999999, nach elf den Wert 1.0999999999999999. Die Schleife endet nie.
        
    
        Der Grund ist der Rundungsfehler bei Gleitkommazahlen aus Abschnitt 4.4.3, Seiten 87–90: 0.1 lässt sich im Zweiersystem nicht genau darstellen. Dazu gibt es die Seite Gleitkommazahlen.
        
    
        Mit for x < 1.0 endet die Schleife. Sie läuft dann aber elfmal und nicht zehnmal, weil 0.9999999999999999 noch kleiner als 1.0 ist. Wer genau zehn Schleifendurchläufe will, zählt mit einer ganzen Zahl:
        

        i := 1
for i <= 10 {
    x := float64(i) / 10   // 0.1, 0.2 … 1
    fmt.Println(x)
    i++
}
        
    
        In Listing 5.4 steht mit eingabe != 0 auch ein Vergleich einer Kommazahl mit !=. Dort ist er in Ordnung: Die 0 wird eingegeben und nicht errechnet.
        

    
        Wer zählt, nimmt die for-Klausel
        
    
        Das letzte Beispiel zählt mit i von 1 bis 10. Für solche Schleifen hat Go die for-Anweisung mit for-Klausel aus Abschnitt 5.5.3.2, Seiten 142–146. Sie schreibt Startwert, Bedingung und i++ in eine Zeile. Die for-Anweisung mit Bedingung ist für Schleifen gedacht, bei denen die Zahl der Schleifendurchläufe vorher nicht feststeht.
        

    
        Ausblick auf break
        
    
        In fremdem Go-Code steht für „mindestens ein Durchlauf“ oft eine Schleife ohne Bedingung, die mitten im Schleifenrumpf mit break verlassen wird:
        

        for {
    fmt.Println("Bitte eine positive Zahl eingeben (0 zum Beenden):")
    fmt.Scan(&eingabe)
    if eingabe == 0 {
        break
    }
}
        
    
        Die Schleife ohne Bedingung steht im Kurstext im Expertenwissen 5.16, die Anweisung break in Abschnitt 5.5.3.3, Seiten 146–149. Dort wird auch begründet, warum eine Schleife möglichst ohne break auskommen soll: An der Schleifenbedingung allein ist dann nicht mehr abzulesen, wann die Schleife endet. Im Kurstext wird deshalb die Flag-Variable aus Schritt 4 verwendet. Zu break gibt es die Seite break-Anweisung.
