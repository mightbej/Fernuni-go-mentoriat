for-Anweisung mit for-Klausel in Go

Eine Schleife, die zählt, braucht einen Startwert, eine Bedingung und einen Zählschritt. Die for-Klausel schreibt alle drei in eine Zeile. Die Seite führt das Programm zu den Quadratzahlen aus dem Kurstext Anweisung für Anweisung aus.

Kurstext v3.0.6, Abschnitt 5.5.3.2, Seiten 142–146.

Worum es geht

Viele Schleifen zählen: Sie beginnen bei einem Startwert, erhöhen eine Variable in jedem Schleifendurchlauf und hören bei einem Zielwert auf. Mit der for-Anweisung mit Bedingung sieht das so aus:

i := 1
for i <= 10 {
    fmt.Println(i * i)
    i++
}

Die drei Teile, die das Zählen ausmachen, stehen hier an drei verschiedenen Stellen. Weil Programme solche Schleifen sehr oft brauchen, hat Go dafür eine eigene Schreibweise, die for-Anweisung mit for-Klausel, englisch for statement with for clause:

for i := 1; i <= 10; i++ {
    fmt.Println(i * i)
}

Beide Programme laufen genau gleich ab und geben die Quadratzahlen von 1 bis 100 aus.

  • Abschnitt 5.4, Seite 129, die einfachen Anweisungen: Zwei Teile der for-Klausel müssen einfache Anweisungen sein. Dazu gibt es die Seite Zuweisungen, Schritt 5.

Die for-Klausel

Die for-Klausel steht zwischen for und der öffnenden Klammer {. Sie hat drei Teile, getrennt durch zwei Semikolons:

  • Init-Anweisung: hier i := 1. „Init“ steht für das englische initial, also anfänglich.
  • Schleifenbedingung: hier i <= 10.
  • Post-Anweisung: hier i++. „Post“ ist lateinisch und heißt hier: hinterher.

Was Go bei der for-Klausel verlangt

    
    
      
  • Init-Anweisung und Post-Anweisung sind einfache Anweisungen. Die ausführliche Deklaration mit var ist keine. Zu for var i int = 1; i <= 10; i++ { meldet der Compiler syntax error: var declaration not allowed in for initializer.
    • 
      
  • In der Post-Anweisung ist keine kurze Variablendeklaration erlaubt. Zu for i := 1; i <= 3; j := 0 { meldet der Compiler syntax error: cannot declare in post statement of for loop.
    • 
      
  • Um die for-Klausel stehen keine runden Klammern. In Java und C++ sind sie Pflicht. Zu for (i := 1; i <= 3; i++) { meldet der Go-Compiler syntax error: unexpected :=, expected ).
    • 
    


    
Was %2[1]v bedeutet

    
Im Listing des Kurstexts steht die Ausgabe als fmt.Printf("%2[1]v * %2[1]v ist %3v\n", i, i*i). Die Formatangabe %2[1]v hat drei Teile:

    
    
      
  • %v: An dieser Stelle setzt Printf einen Wert ein.
    • 
      
  • 2: Der Wert bekommt mindestens zwei Zeichen Platz. Eine einstellige Zahl rückt nach rechts, davor steht ein Leerzeichen. So stehen die Zahlen untereinander.
    • 
      
  • [1]: Gemeint ist das erste Argument hinter dem Text, also i. Deshalb kann i zweimal ausgegeben werden, obwohl es nur einmal in der Liste steht.
    • 
    

    
%3v gibt danach das nächste Argument aus, also i*i, mit mindestens drei Zeichen Platz.

  

  

    
    
  

  


  

  

    
Der Ablauf

    
Die drei Teile der for-Klausel stehen in einer Zeile, laufen aber zu drei verschiedenen Zeiten:

    
    
      
  • Init-Anweisung: einmal, ganz am Anfang.
    • 
      
  • Schleifenbedingung: vor jedem Schleifendurchlauf, auch vor dem ersten.
    • 
      
  • Post-Anweisung: nach jedem Schleifendurchlauf, also nach dem Schleifenrumpf.
    •

    Das Ende genau betrachtet
    
    
    Nach dem letzten Schleifendurchlauf läuft die Post-Anweisung noch einmal. In der Fassung des Kurstexts hat i im zehnten Schleifendurchlauf den Wert 10. Danach erhöht i++ den Wert auf 11. Erst die nächste Prüfung 11 <= 10 ergibt false und beendet die Schleife.
    
    
    Die Schleifenbedingung wird also elfmal geprüft, der Schleifenrumpf läuft zehnmal.
    
  
    
  
    
    
    
  
    
  
    

  
    
  
    
    
    Die Laufvariable
    
    
    Die Init-Anweisung darf jede einfache Anweisung sein. Fast immer ist sie eine kurze Variablendeklaration und führt eine Variable ein, die in der Schleife zählt. Diese Variable heißt Laufvariable, manchmal auch Kontrollvariable.
    

    
    Wo die Laufvariable gilt
    
    
    Der Gültigkeitsbereich einer Laufvariable, die in der Init-Anweisung deklariert ist, umfasst die ganze for-Anweisung: die for-Klausel und den Schleifenrumpf. Sie ist eine lokale Variable der Schleife. Hinter der Schleife gibt es sie nicht mehr.
    
    
    
      
      
      
    
    
    
      
    
      
      
      Ausgabe
    
      
    
      
    
      Gelb markiert ist die Zeile, auf die es in der gewählten Fassung ankommt. Die drei Programme sind Ausschnitte ohne package, import und func main.
      

    
      Wie die Laufvariable heißt
      
    
      Laufvariablen heißen üblicherweise i, j oder k. Dafür gibt es zwei Gründe:
      
    
        
      
      • Erkennbar: Wer i liest, erkennt die Laufvariable auf den ersten Blick.
        • 
      
      • Der Grundsatz dahinter: Je kleiner der Gültigkeitsbereich einer Variable ist, desto kürzer darf ihr Bezeichner sein. Eine Laufvariable gilt nur in ihrer Schleife. Dort bleibt ihre Bedeutung auch mit einem Namen aus einem Buchstaben klar.
        • 
    
      

    
      Zwei Laufvariablen
      
    
      Eine kurze Variablendeklaration kann mehrere Variablen deklarieren, und eine Tupel-Zuweisung kann mehreren Variablen Werte geben. Beide sind je eine einfache Anweisung. Deshalb kann eine for-Klausel zwei Laufvariablen führen:
      

      for i, j := 0, 100; i < j; i, j = i+1, j-5 {
    fmt.Println("i, j:", i, j)
}
      
    
        
      
      • Init-Anweisung: i beginnt mit 0, j mit 100.
        • 
      
      • Post-Anweisung: i wächst um 1, j schrumpft um 5.
        • 
      
      • Ausgabe: 17 Zeilen. Die erste ist i, j: 0 100, die letzte i, j: 16 20. Danach hat i den Wert 17 und j den Wert 15, und 17 < 15 ergibt false.
        • 
    
      
    
      Solche Schleifen kommen bei höherdimensionalen Arrays vor, die in Abschnitt 6.3 behandelt werden.
      
  
      
  
      
    
    
  
      
  
      

  
      
  
      
    
      Eine Schleife, vier Schreibweisen
      
    
      Alle drei Teile der for-Klausel dürfen fehlen. Daran sieht man: Go hat im Grunde nur eine Schleife. Die for-Anweisung mit Bedingung und die Schleife ohne Bedingung sind verkürzte Schreibweisen der for-Anweisung mit for-Klausel.
      
    
      Jeder Knopf zeigt eine Schreibweise. Alle vier Programme geben 1, 2 und 3 aus.
      
    
      
      
      
      
      
    
      
    
      
    
      

    
      Wozu eine Schleife ohne Bedingung gut ist
      
    
      Eine Schleife, deren Bedingung immer true ist, wirkt zunächst sinnlos. Gebraucht wird sie in Programmen, die auf Dauer laufen und immer wieder Daten einlesen oder ausgeben. Eine solche Schleife heißt auf Englisch event loop.
      
    
      Weil die Bedingung nie false ergibt, muss die Schleife auf anderem Weg enden: mit break oder mit dem Ende des ganzen Programms durch os.Exit(0). Zu break gibt es die Seite break-Anweisung.
      
    
      Die dritte Art der for-Anweisung, die mit range, wird in Abschnitt 6.2 bei den Arrays behandelt.
      
  
      
  
      
    
    
  
      
  
      

  
      
  
      
    
      Aus der Praxis
      
    
      Die Faustregeln in diesem Schritt stammen vom Mentor. Sie stehen nicht in Abschnitt 5.5.3.2 des Kurstexts. Go übersetzt jede Fassung, auch die vier mit dem Kommentar „falsch“. { … } steht für einen beliebigen Schleifenrumpf.
      

    
      1. Startwert und Vergleich gehören zusammen
      

      for i := 0; i < 10; i++ { … }    // zehn Schleifendurchläufe: i von 0 bis 9
for i := 1; i <= 10; i++ { … }   // zehn Schleifendurchläufe: i von 1 bis 10
      

      for i := 1; i < 10; i++ { … }    // falsch: nur neun Schleifendurchläufe
for i := 0; i <= 10; i++ { … }   // falsch: elf Schleifendurchläufe
      
    
      Wer zehnmal zählen will, hat zwei übliche Formen: ab 0 mit < oder ab 1 mit <=. Wer die Formen mischt, zählt einmal zu wenig oder einmal zu viel. Der Fehler heißt auf Englisch off-by-one error.
      
    
      In Go ist die Form ab 0 die häufigere. Der Grund kommt in Kapitel 6: Das erste Element eines Arrays hat den Index 0.
      

    
      2. Die Laufvariable ändert nur die Post-Anweisung
      

      for i := 1; i <= 10; i++ {
    fmt.Print(i, " ")
    i++              // falsch: i wird zweimal je Schleifendurchlauf erhöht
}                    // Ausgabe: 1 3 5 7 9
      
    
      Die for-Klausel verspricht dem Leser: Diese Schleife zählt von 1 bis 10 in Schritten von 1. Ändert der Schleifenrumpf die Laufvariable, stimmt das nicht mehr, und niemand sieht es der ersten Zeile an.
      
    
      Wer in Schritten von 2 zählen will, schreibt es in die Post-Anweisung: for i := 1; i <= 10; i += 2.
      

    
      3. Wer herunterzählt, dreht alle drei Teile um
      

      for i := 10; i >= 1; i-- { … }   // zehn Schleifendurchläufe: i von 10 bis 1
      

      for i := 10; i <= 1; i-- { … }   // falsch: kein einziger Schleifendurchlauf
      
    
      Beim Herunterzählen ändern sich der Startwert, der Vergleich und die Post-Anweisung. In der zweiten Fassung ist der Vergleich stehen geblieben: 10 <= 1 ergibt schon bei der ersten Prüfung false, und die Schleife läuft nie.
      
    
      Die Prüffrage ist die gleiche wie bei der for-Anweisung mit Bedingung: Ergibt die Schleifenbedingung am Anfang true, und sorgt die Post-Anweisung dafür, dass sie irgendwann false ergibt?
      

    
      Faustregeln zur for-Anweisung mit Bedingung stehen auf der Seite for-Anweisung mit Bedingung, Schritt 5.
