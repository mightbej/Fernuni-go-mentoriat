Frage 1 von 10
Was ist der Hauptunterschied zwischen einer Konstanten und einer Variablen in Go?

Erklärung:

Der Wert einer Konstanten ist nach der Deklaration unveränderlich, während Variablen beliebig oft geändert werden können. Konstanten können verschiedene Datentypen haben und der Typ muss nicht explizit angegeben werden.

Frage 2 von 10
Welche der folgenden Deklarationen ist/sind korrekt?
// A) const maxWert int // B) const maxWert = 500 // C) const maxWert int = 500 // D) const maxWert = 500 maxWert = 600

Erklärung:

A ist falsch, weil einer Konstanten bei der Deklaration immer ein Wert zugewiesen werden muss. D ist falsch, weil der Wert einer Konstanten nicht geändert werden kann. B und C sind beide korrekt – der Typ kann weggelassen werden (B) oder explizit angegeben werden (C).

Frage 3 von 10
Welches Schlüsselwort wird für die Deklaration einer Konstanten verwendet?

Erklärung:

In Go wird das Schlüsselwort const für die Deklaration von Konstanten verwendet. var wird für Variablen verwendet, final und let existieren in Go nicht.

Frage 4 von 10
Welche Gründe sprechen für die Verwendung von Konstanten? (Mehrfachauswahl)

Erklärung:

A, B und C sind alles gültige Gründe für die Verwendung von Konstanten, wie im Studienbrief beschrieben. D ist nicht korrekt – Konstanten bieten keine signifikanten Performance-Vorteile zur Laufzeit, aber sie vermeiden wiederholte Berechnungen zur Compile-Zeit.

Frage 5 von 10
Was ist die Ausgabe dieses Codes?
const monateImJahr = 12 fmt.Printf("Der Typ ist %T.\n", monateImJahr)

Erklärung:

Wenn eine Konstante ohne explizite Typangabe deklariert wird und kein spezieller Kontext einen anderen Typ erfordert, wird der Standardtyp verwendet. Bei Integer-Konstanten ist dies int.

Frage 6 von 10
Welche Notation erlaubt es, mehrere Konstanten kompakt zu deklarieren?

Erklärung:

Go verwendet die Klammern-Notation mit const ( ... ) für die kompakte Deklaration mehrerer Konstanten. Jede Konstante steht dabei in einer eigenen Zeile (Semikolon ist optional am Zeilenende).

Frage 7 von 10
Was bedeutet "untyped constant" in Go?

Erklärung:

Eine "untyped constant" ist eine Konstante (oder ein Literal), deren konkreter Typ noch nicht festgelegt ist. Der Typ wird erst bei der Verwendung durch den Kontext bestimmt. Dies ermöglicht flexible Verwendung und hohe Präzision bei Berechnungen zur Compile-Zeit.

Frage 8 von 10
Mit welcher Präzision führt der Go-Compiler Berechnungen auf untyped Konstanten durch?

Erklärung:

Der Go-Compiler führt Berechnungen auf untyped Konstanten mit einer Präzision von mindestens 256 Bit durch. Dadurch können Konstanten wie math.Pi mit 65 Dezimalziffern definiert werden, obwohl float64 nur ca. 16 Dezimalziffern unterstützt.

Frage 9 von 10
Warum ist es sinnvoll, eine Konstante wie const monateImJahr = 12 zu verwenden, obwohl sich dieser Wert nie ändern wird?

Erklärung:

Durch die Konstante können alle Stellen im Code eindeutig identifiziert werden, an denen der Wert 12 tatsächlich die Monate im Jahr bedeutet. Dies unterscheidet sie von anderen Stellen, wo zufällig auch 12 steht (z.B. Stunden auf einer Uhr), aber eine andere Bedeutung hat.

Frage 10 von 10
Was passiert in diesem Code?
var a uint8 = 20 var b int64 = 20 fmt.Println(a + 88) fmt.Println(b + 88)

Erklärung:

Das Integer-Literal 88 ist vom speziellen Typ "untyped integer" und passt sich je nach Verwendungskontext an. Im ersten Ausdruck wird es zu uint8, im zweiten zu int64, damit beide Operanden vom gleichen Typ sind.
