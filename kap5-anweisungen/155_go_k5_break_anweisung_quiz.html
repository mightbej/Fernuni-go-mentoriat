🛑 Quiz: break-Anweisung

Teste dein Wissen über break in Go!

1. Was bewirkt die break-Anweisung?

  • Sie beendet das gesamte Programm
  • Sie verlässt die umschließende Schleife sofort und beendet die for-Anweisung
  • Sie überspringt nur den aktuellen Durchlauf
  • Sie setzt die Laufvariable zurück

2. Was passiert mit der Post-Anweisung, wenn break aufgerufen wird?

for i := 0; i < 10; i++ { if i == 5 { break } }
  • i++ wird noch einmal ausgeführt, dann endet die Schleife
  • i++ wird NICHT mehr ausgeführt - die Schleife endet sofort
  • i++ wird zweimal ausgeführt
  • i++ wird in eine Warteschlange verschoben

3. Wo ist die break-Anweisung erlaubt?

  • Überall im Programm
  • Nur in if-Anweisungen
  • Nur innerhalb von for-Anweisungen und switch-Anweisungen
  • Nur in Funktionen

4. Was ist das Problem mit break in Schleifen?

  • break ist sehr langsam in der Ausführung
  • break unterwandert die Schleifenbedingung und macht den Code schwerer nachvollziehbar
  • break kann zu Speicherlecks führen
  • break ist in Go veraltet

5. Wozu dient eine Flag-Variable bei Verwendung von break?

  • Um die Schleife zu beschleunigen
  • Um nach der Schleife zu wissen, warum sie beendet wurde (regulär oder durch break)
  • Um break rückgängig zu machen
  • Um die Laufvariable zu speichern

6. Was ist die bessere Alternative zu break?

// Variante A: mit break for i := 0; i < 10; i++ { if problem { break } } // Variante B: ohne break problem := false for i := 0; i < 10 && !problem; i++ { // ... }
  • Variante A ist besser, weil kürzer
  • Variante B ist besser, weil die Schleifenbedingung allein kontrolliert, wann die Schleife endet
  • Beide sind gleich gut
  • Variante A ist schneller in der Ausführung

7. Wie prüft man, ob fak * i zu einem Überlauf führt?

  • if fak * i > math.MaxInt
  • if math.MaxInt/fak >= i (dann ist kein Überlauf)
  • if i > math.MaxInt
  • Man kann Überläufe nicht vorab prüfen

8. Welchen Wert hat i nach dieser Schleife?

for i := 0; i < 10; i++ { if i == 5 { break } } fmt.Println(i) // Was passiert hier?
  • i hat den Wert 5
  • i hat den Wert 10
  • Compiler-Fehler: i ist außerhalb der Schleife nicht gültig
  • i hat den Wert 0

9. Wann ist break legitim?

  • Niemals - break sollte komplett vermieden werden
  • Wenn die Alternative mit Flag-Variablen zu unübersichtlichem Code führen würde und break die pragmatischste Lösung ist
  • Immer - break ist der beste Weg, Schleifen zu beenden
  • Nur in switch-Anweisungen

10. Was ist das typische Pattern für break mit Flag?

  • Flag nach break setzen
  • Flag vor break auf true setzen, dann break aufrufen, nach Schleife Flag prüfen
  • Flag während break setzen
  • Flag ist bei break nicht nötig

11. Was gibt dieses Programm aus?

for i := 1; i <= 5; i++ { if i == 3 { break } fmt.Print(i, " ") }
  • 1 2 3 4 5
  • 1 2
  • 1 2 3
  • 3 4 5

12. Warum ist break hier nicht nötig?

for i := 1; i <= 10; i++ { fmt.Println(i) // Am Ende des Rumpfes }
  • Weil die Schleife unendlich läuft
  • Weil nach dem letzten Statement im Rumpf ohnehin das Ende des Durchlaufs erreicht ist - break würde nichts ändern
  • Weil break in dieser Schleife verboten ist
  • Weil i++ automatisch break aufruft

13. Ist dieser Code korrekt?

func main() { x := 10 if x > 5 { break } }
  • Ja, break beendet die if-Anweisung
  • Nein, break ist nur in Schleifen und switch erlaubt, nicht in if-Anweisungen
  • Ja, break beendet die Funktion
  • Nein, aber nur weil x falsch initialisiert ist

14. Was sollte man tun, wenn man break in einer Schleife verwendet?

  • Nichts Besonderes
  • Einen expliziten Kommentar am Schleifenanfang hinzufügen, der darauf hinweist
  • break zweimal aufrufen zur Sicherheit
  • Eine Warnung in die Konsole ausgeben
