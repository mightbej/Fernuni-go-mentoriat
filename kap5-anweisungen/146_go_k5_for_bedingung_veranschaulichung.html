🔄 for-Anweisung mit Bedingung in Go

Die einfachste Schleifenart: Wiederholung mit Bedingung (while-Schleife)

FernUni Hagen - Kurs 01613 - Kurstext v3.0.6, Abschnitt 5.5.3.1, Seiten 138–142

📚 Grundkonzept: Schleifen

Eine Schleife (loop statement) ist eine Wiederholungsanweisung, die einen Block von Anweisungen wiederholt ausführt.

🎯 Schleifenbedingung

Bestimmt, ob der Schleifenrumpf (erneut) ausgeführt wird. Wird vor jedem Durchlauf geprüft.

📦 Schleifenrumpf

Block mit Anweisungen, die wiederholt ausgeführt werden, solange die Bedingung erfüllt ist.

🔁 Schleifendurchlauf

Einmalige Ausführung aller Anweisungen im Schleifenrumpf.

🛑 Abbruchbedingung

Negation der Schleifenbedingung. Wenn erfüllt, bricht die Schleife ab.

⚠️ Endlosschleife

Wenn die Abbruchbedingung nie erfüllt wird, läuft die Schleife endlos weiter!

for true { // Läuft für immer (Endlosschleife!) }

🔑 for-Anweisung in Go

Besonderheit in Go:

In Go werden alle Schleifenarten mit dem Schlüsselwort for eingeleitet. Es gibt keine unterschiedlichen Schlüsselwörter wie while, do oder repeat wie in anderen Sprachen.

Go bietet drei Arten von Schleifen (alle mit for):

1. for mit Bedingung

Nur Bedingung + Rumpf
(wie while-Schleife)

for bedingung { // Rumpf }

2. for mit Klausel

Init + Bedingung + Post
(klassische for-Schleife)

for i := 0; i < 10; i++ { // Rumpf }

3. for mit range

Durchlaufen von Arrays
(foreach-Schleife)

for i, v := range arr { // Rumpf }

📖 In diesem Kapitel: Wir behandeln die for-Anweisung mit Bedingung – die einfachste Schleifenart in Go!

📝 Syntax: for-Anweisung mit Bedingung

Allgemeine Form

for schleifenbedingung { // Anweisungen im Schleifenrumpf // Werden wiederholt, solange schleifenbedingung == true }

🔍 Wichtige Eigenschaften:

  • ✅ Keine Klammern um die Bedingung (wie bei if und switch)
  • ✅ Geschweifte Klammern { } sind Pflicht
  • ✅ Bedingung wird vor jedem Durchlauf geprüft
  • ✅ Wenn Bedingung vor 1. Durchlauf false: Rumpf wird übersprungen

Ablaufdiagramm

Start
↓
Ist Bedingung erfüllt?
✓ JA (true)
↓
Schleifenrumpf ausführen
↓
⤴ Zurück zur Bedingung
✗ NEIN (false)
↓
Schleife beenden

💡 Beispiel 1: Wiederholte Eingabe

Das Programm fordert wiederholt zur Eingabe einer Zahl auf und berechnet deren Quadratwurzel. Die Schleife läuft, bis 0 eingegeben wird.

Quelle: Das Programm ist Listing 5.4 for_bedingung_eingabe.go aus dem Kurstext „Imperative Programmierung“ (Kurs 01613) der FernUniversität in Hagen, Abschnitt 5.5.3.

package main import ( "fmt" "math" ) func main() { var eingabe float64 = 1.0 for eingabe != 0 { fmt.Println("Bitte eine positive Zahl eingeben (0 zum Beenden):") fmt.Scan(&eingabe) if eingabe > 0 { fmt.Printf("Die Wurzel von %v ist %v.\n", eingabe, math.Sqrt(eingabe)) } } }

Initialisierung

eingabe = 1.0

✓ Bedingung erfüllt → Schleife wird betreten

1. Durchlauf

Eingabe: 16

Ausgabe: Wurzel von 16 ist 4

↻ Bedingung prüfen

2. Durchlauf

Eingabe: 25

Ausgabe: Wurzel von 25 ist 5

↻ Bedingung prüfen

Abbruch

Eingabe: 0

✗ Bedingung nicht erfüllt → Schleife endet

🔍 Wichtige Details:

  • Initialisierung mit 1.0: Stellt sicher, dass die Bedingung eingabe != 0 beim ersten Erreichen der Schleife erfüllt ist
  • Anzahl Durchläufe unbekannt: Wir wissen vorher nicht, wie oft der Benutzer Zahlen eingeben will
  • Prüfung VOR Durchlauf: Die Bedingung wird vor jedem Durchlauf geprüft
  • math.Sqrt(): Berechnet die Quadratwurzel (aus dem math-Paket)

💡 Beispiel 2: ggT-Berechnung (Euklidischer Algorithmus)

Berechnung des größten gemeinsamen Teilers (ggT) zweier natürlicher Zahlen. Die Anzahl der Schleifendurchläufe ergibt sich aus den Berechnungen.

Quelle: Das Programm ist Listing 5.5 for_ggt.go aus dem Kurstext „Imperative Programmierung“ (Kurs 01613) der FernUniversität in Hagen, Abschnitt 5.5.3.

package main import "fmt" // ggT von n und m mittels Euklidischen Algorithmus berechnen func ggT(n, m int) int { for n != m { if n > m { n -= m } else { m -= n } } return n } func main() { var n, m int fmt.Println("Bitte zwei natürliche Zahlen größer 0 eingeben:") fmt.Scan(&n) fmt.Scan(&m) if n > 0 && m > 0 { fmt.Printf("%v ist der ggT von %v und %v.\n", ggT(n, m), n, m) } else { fmt.Printf("Die Eingabe %v und %v ist unzulässig.\n", n, m) } }

Beispiel-Ablauf: ggT(42, 78)

Start

n = 42, m = 78

✓ n ≠ m

1. Durchlauf

m > n → m = 78 - 42 = 36

n = 42, m = 36

2. Durchlauf

n > m → n = 42 - 36 = 6

n = 6, m = 36

3. Durchlauf

m > n → m = 36 - 6 = 30

n = 6, m = 30

4. Durchlauf

m > n → m = 30 - 6 = 24

n = 6, m = 24

5. Durchlauf

m > n → m = 24 - 6 = 18

n = 6, m = 18

6. Durchlauf

m > n → m = 18 - 6 = 12

n = 6, m = 12

7. Durchlauf

m > n → m = 12 - 6 = 6

n = 6, m = 6

Ende

✗ n == m

Ergebnis: 6

💡 Bemerkung zu Variablennamen:

Die Parameter-Variablen n und m in der Funktion ggT haben den gleichen Namen wie die Variablen in main, sind aber völlig unabhängig! Der Gültigkeitsbereich ist auf den jeweiligen Funktionsrumpf beschränkt.

🎯 Wann for-Anweisung mit Bedingung verwenden?

✅ Einsatz wenn:

  • Anzahl der Durchläufe vor Eintritt unbekannt
  • Wiederholung hängt von Benutzereingabe ab
  • Wiederholung hängt von Berechnungen ab
  • Einlesen unbekannter Datenmenge (z.B. bis 0 oder EOF)

Typische Anwendungsfälle

📥 Dateneingabe

for eingabe != 0 { fmt.Scan(&eingabe) // Verarbeiten... }

🔍 Suche

for !gefunden { // Suchen... if bedingung { gefunden = true } }

🧮 Algorithmen

for n != m { // Berechnung... // n und m ändern sich }

🌍 Sprachvergleiche

while-Schleife

In vielen Sprachen (Java, C++, Python, JavaScript, etc.):

Diese Schleifenart wird mit while eingeleitet und heißt while-Schleife.

for i < 10 { fmt.Println(i) i++ }

✅ Keine Klammern um Bedingung (idiomatisch)

while (i < 10) { System.out.println(i); i++; }

Schlüsselwort: while, Klammern um Bedingung

while i < 10: print(i) i += 1

Schlüsselwort: while, Doppelpunkt statt Klammern

while (i < 10) { cout << i << endl; i++; }

Schlüsselwort: while, Klammern um Bedingung

do-while-Schleife / repeat-until-Schleife

⚠️ Gibt es NICHT in Go!

In Java, C++ gibt es die do-while-Schleife, in Pascal die repeat-until-Schleife. Diese führen den Schleifenrumpf mindestens einmal aus (Prüfung am Ende).

Java/C++ - do-while:

do { // Wird mindestens 1x ausgeführt fmt.Println("Eingabe:"); fmt.Scan(&eingabe); } while (eingabe != 0);

Pascal - repeat-until:

repeat { Wird mindestens 1x ausgeführt } writeln('Eingabe:'); readln(eingabe); until eingabe = 0;

In Go: do-while kann mit einer Flag-Variable nachgebildet werden (siehe unten).

🚩 Flag-Variable: Mindestens 1x durchlaufen

Um sicherzustellen, dass der Schleifenrumpf mindestens einmal durchlaufen wird (wie bei do-while), verwendet man eine boolesche Flag-Variable.

var eingabe float64 = 1.0 // Muss != 0 sein! for eingabe != 0 { fmt.Println("Bitte eine Zahl eingeben (0 zum Beenden):") fmt.Scan(&eingabe) // Verarbeitung... }

⚠️ Problem: eingabe muss mit 1.0 initialisiert werden, damit Schleife überhaupt betreten wird

var eingabe float64 = 0.0 // Kann jetzt 0.0 sein! var ersterLauf bool = true // Flag-Variable for ersterLauf || eingabe != 0 { fmt.Println("Bitte eine Zahl eingeben (0 zum Beenden):") fmt.Scan(&eingabe) // Verarbeitung... ersterLauf = false // Ab jetzt keine Wirkung mehr }

✅ Beim ersten Durchlauf ist ersterLauf == true → Bedingung erfüllt (unabhängig von eingabe)

✅ Nach erstem Durchlauf: ersterLauf = false → nur noch eingabe != 0 zählt

💡 Flag-Variable (engl. "flag"):

Eine boolesche Variable, die einen Zustand markiert (hier: "erster Durchlauf"). Wird oft für Kontrollfluss verwendet.

❌ Schlechte Alternative: Code-Duplikation

Man könnte den Code vor die Schleife kopieren, aber das gilt als schlechter Stil:

// Code VOR der Schleife (schlecht!) fmt.Println("Bitte eine Zahl eingeben (0 zum Beenden):") fmt.Scan(&eingabe) // Verarbeitung... for eingabe != 0 { // GLEICHER Code nochmal (Duplikation!) fmt.Println("Bitte eine Zahl eingeben (0 zum Beenden):") fmt.Scan(&eingabe) // Verarbeitung... }

⛔ Copy-Paste von Code vermeiden!

✅ Best Practices

✅ DO

  • Keine Klammern um Bedingung
  • Bedingung klar formulieren
  • Abbruchbedingung garantieren
  • Bei unbekannter Anzahl Durchläufe
  • Variable richtig initialisieren

❌ DON'T

  • Klammern um Bedingung (unidiomatisch)
  • Endlosschleifen (außer absichtlich)
  • Zu komplexe Bedingungen
  • Code-Duplikation für do-while
  • Schleifenvariable falsch initialisieren

Häufige Fehler

1. Falsche Initialisierung

var eingabe float64 = 0.0 // Problem: Bedingung sofort false! for eingabe != 0 { // Wird NIE ausgeführt! }

2. Bedingung wird nie false

var x int = 10 for x > 0 { fmt.Println(x) // x wird nicht verändert → Endlosschleife! }

3. Klammern um Bedingung (funktioniert, aber unidiomatisch)

for (x > 0) { // Funktioniert, aber nicht idiomatisch! x-- }

🔄 Schleife

Wiederholung eines Blocks, solange Bedingung erfüllt

🔑 for in Go

Alle Schleifen mit for (kein while/do/repeat)

⏱ Prüfung VOR

Bedingung vor jedem Durchlauf geprüft

❓ Anzahl unbekannt

Ideal wenn Durchlauf-Anzahl vorher nicht bekannt

Für mindestens 1 Durchlauf (do-while-Ersatz)

🛑 Abbruch

Abbruchbedingung muss erfüllbar sein!

🎯 Kernpunkte

  • for bedingung { } ist die einfachste Schleifenart in Go
  • Entspricht der while-Schleife in anderen Sprachen
  • Keine Klammern um Bedingung (idiomatisch)
  • Bedingung wird vor jedem Durchlauf geprüft
  • Wenn Bedingung initial false: Rumpf wird übersprungen
  • Ideal für unbekannte Anzahl von Durchläufen
  • do-while-Verhalten mit Flag-Variable erreichbar
