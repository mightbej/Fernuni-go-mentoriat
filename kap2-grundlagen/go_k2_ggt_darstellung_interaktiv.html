Größter gemeinsamer Teiler: vom Struktogramm zum Go-Programm

Ein kleines Programm in vier Darstellungen: als Text, als Struktogramm, als Flussdiagramm und als Go-Programm.

Kurstext v3.0.6, Abschnitt 2.5, Seiten 13–14, und Abschnitt 5.5.3.1, Listing 5.5 auf Seite 140.

Worum es geht

Ein Programm ist ein Text. An einem Text erkennt man schlecht, welche Anweisungen zusammengehören und in welcher Reihenfolge sie laufen. Ein Bild zeigt das besser. In Abschnitt 2.5 des Kurstexts werden dafür zwei Bilder vorgestellt:

  • Das Struktogramm zeigt ein Programm als Kästen, die ineinander stecken. Es passt zur strukturierten Programmierung mit Blöcken.
  • Das Flussdiagramm zeigt ein Programm als Kästen, die mit Pfeilen verbunden sind. Es passt zur imperativen Programmierung mit Sprüngen.

Beide Bilder zeigen im Kurstext dasselbe Programm:

Eingabe n, m (positive ganze Zahlen); WHILE n ≠ m IF n > m THEN n ← n − m ELSE m ← m − n; Ausgabe n

Der Pfeil ← bedeutet: Die Variable links bekommt den Wert, der rechts ausgerechnet wird.

Dasselbe Programm steht in Abschnitt 5.5.3.1 noch einmal, dort als Go-Programm. Die Seite führt in vier Schritten vom Bild zum Go-Programm:

  • Schritt 1 lässt das Programm im Struktogramm laufen.
  • Schritt 2 lässt es mit denselben Zahlen im Flussdiagramm laufen.
  • Schritt 3 stellt jede Zeile ihrer Schreibweise in Go gegenüber.
  • Schritt 4 lässt das Go-Programm aus dem Kurstext laufen.

Im Kurstext stehen zu dem Programm zwei Fragen. Beantworte sie, nachdem du Schritt 1 mit einigen Zahlen ausprobiert hast.

  • Frage 1: Was leistet das Programm?
  • Frage 2: Warum kommt es bei positiven Zahlen immer zu einem Ende?

Antwort 1: Das Programm berechnet den größten gemeinsamen Teiler der zwei Zahlen, kurz ggT. Der ggT von 42 und 78 ist 6.

Antwort 2: In jedem Durchlauf wird die größere Zahl um die kleinere vermindert. Beide Zahlen bleiben dabei größer als 0, und ihre Summe wird jedes Mal kleiner. Eine Summe positiver ganzer Zahlen kann nicht beliebig oft kleiner werden. Also sind die zwei Zahlen irgendwann gleich.

Das Programm als Struktogramm

Ein Struktogramm liest man von oben nach unten. Jeder Kasten ist eine Anweisung.

  • Die Schleife: Der Kasten while n ≠ m umschließt links und oben alles, was wiederholt wird.
  • Die Verzweigung: Unter der Frage n > m? stehen zwei Kästen nebeneinander. Ausgeführt wird nur einer von beiden.

Gelb ist der Kasten, der gerade an der Reihe ist.

Das Programm als Flussdiagramm

Ein Flussdiagramm liest man entlang der Pfeile. Ein Rechteck ist eine Anweisung, eine Raute ist eine Frage mit den Ausgängen ja und nein.

  • Die Schleife: Sie hat keinen eigenen Kasten. Sie entsteht durch die zwei Pfeile, die von unten zurück nach oben führen.
  • Die Frage oben: Sie lautet hier n = m?. Im Struktogramm steht die Bedingung umgekehrt als n ≠ m. Beides bedeutet dasselbe: Solange die Zahlen verschieden sind, geht es in die Schleife.

Der Durchlauf steht an derselben Stelle wie in Schritt 1. Mit „von vorn“ beginnt er neu.

Ein Pfeil zurück nach oben ist ein Sprung. Wie Blöcke den Sprung ersetzen, zeigt die Seite Imperative Programmierung, Schritt 3.

Aus den vier Zeilen wird in Go dieser Kern:

for n != m { if n > m { n -= m } else { m -= n } }

Ein vollständiges Go-Programm braucht mehr als diesen Kern. Im Programm des Kurstexts kommt dazu:

  • Der Rahmen: Jedes Go-Programm beginnt mit package main und hat eine Funktion main.
  • Die Deklaration: var n, m int legt die zwei Variablen an und nennt ihren Typ. Dazu gibt es die Seite Variablendeklaration.
  • Eingabe und Ausgabe: fmt.Scan liest eine Zahl ein, fmt.Printf gibt das Ergebnis aus.
  • Die Prüfung der Eingabe: Das Programm aus Abschnitt 2.5 setzt positive Zahlen voraus. Das Go-Programm prüft das mit if n > 0 && m > 0.
  • Die Funktion: Die Schleife steht in einer eigenen Funktion ggT. Aus Ausgabe n wird dort return n.
